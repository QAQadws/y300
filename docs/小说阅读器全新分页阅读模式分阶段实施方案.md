# 小说阅读器全新分页阅读模式分阶段实施方案

> 状态：待实施方案
>
> 编写日期：2026-07-20
>
> 适用范围：小说阅读器的新 HTML-first 正文渲染链、阅读模式设置、阅读进度恢复和章节导航

## 1. 背景与结论

小说阅读器需要支持“分页阅读模式”：正文以固定视口为一页，用户通过左右滑动切换页面，并可以选择从左到右或从右到左的阅读方向。

本方案有一个必须先确认的前提：当前代码中已经存在的分页相关代码不能作为新功能的实现基础。旧分页建立在旧的 HTML 渲染路径和旧的 `NovelReaderDocumentView` 之上；当前小说正文已经切换到新的 HTML-first 解析、主题适配、图片管线和 `ForumHtmlWidgetPostRenderer` 渲染链。继续修补旧分页会产生两套正文模型、两套排版规则和两套图片语义，最终会出现“纵向阅读看起来正确、分页阅读却丢格式或页码不一致”的问题。

因此最终方向是：

1. 清理旧分页表面、旧布局服务、旧估算分页器以及其专属测试。
2. 以当前新 HTML-first 预处理结果作为唯一的视觉正文来源。
3. 新分页只负责把已经准备好的 HTML 流切分成页片，不重新发请求、不使用旧的 RichBlock 渲染器、不复制一套正文样式。
4. 每一页仍然使用现有 HTML 渲染器显示，因此主题、字号、行距、简繁转换、链接、正文图片和图片缓存规则保持一致。
5. 阅读位置使用“稳定正文锚点优先、页码仅作同一布局快速恢复”的策略，避免字号、窗口尺寸或主题改变后恢复到错误位置。

本方案不是“重新打开已有 `PageView`”的计划，而是一次分页管线重构。

## 2. 目标与非目标

### 2.1 目标

- 提供三种小说正文展示模式：
  - `vertical`：现有纵向滚动模式。
  - `pagedLtr`：分页，从左到右。
  - `pagedRtl`：分页，从右到左。
- 分页正文使用新的 HTML-first 解析和渲染结果。
- 分页页片和纵向正文使用同一套：
  - HTML 规范化规则。
  - 主题适配规则。
  - 字号、行距、段距、字体、对齐方式和首行缩进设置。
  - 正文图片请求、缓存 owner、尺寸信息和点击打开逻辑。
  - 链接解析和应用内帖子打开逻辑。
- 分页模式切换时保留用户当前阅读位置，而不是简单跳到第一页或错误页码。
- 同一章节、同一正文和同一布局条件下，退出后重新进入可以恢复到上次分页位置。
- 正文内容变化、窗口变化、字号变化、主题变化和图片尺寸补齐后，分页布局可以安全失效并重新生成。
- 旧分页残留数据不会让新分页恢复到不可解释的旧页码。
- 章节切换继续由 `NovelReaderController` 统一管理，不在分页 Widget 中复制章节顺序逻辑。
- 不改变小说正文水合、SQLite 正文唯一来源、书签数据和 `version=1` 请求链路。

### 2.2 非目标

- 本轮不把小说正文重新保存为页片 JSON、HTML 文件或图片文件。
- 本轮不增加 EPUB、PDF、离线压缩包或导出能力。
- 本轮不引入 WebView 作为分页器。
- 本轮不引入第二个 HTML 渲染插件来替代现有 `flutter_widget_from_html_core` 链路。
- 本轮不修改漫画阅读器的分页、评论尾部或图片阅读器行为。
- 本轮不改变小说的章节发现、章节水合、封面缓存和作品清理逻辑。
- 本轮不重新引入已经移除的小说未读语义、底部书签入口或底部交互式 slider。

## 3. 当前基线审计

### 3.1 当前仍可保留的能力

| 能力 | 当前位置 | 新分页的处理 |
| --- | --- | --- |
| 阅读模式枚举 | `lib/features/novel/domain/models/novel_reader_preferences.dart` | 保留 `vertical`、`pagedLtr`、`pagedRtl` 存储值和编解码协议 |
| 个性化设置 | `NovelReaderPreferences`、SharedPreferences repository | 保留；默认值仍为字号 `18.5`、行高 `1.6`、护眼主题、纵向模式 |
| 新 HTML 预处理 | `NovelHtmlChapterRenderPreparer` | 作为纵向和分页的共同输入 |
| HTML 主题和样式 | `ForumHtmlRenderPreparer`、`ForumHtmlStylePolicy`、主题适配器 | 保留，不在分页模块复制样式规则 |
| HTML 渲染 | `ForumHtmlWidgetPostRenderer` | 每个分页页片继续调用同一 renderer |
| 正文图片缓存 | `ForumHtmlCachedImageWidgetFactory` 和现有图片缓存服务 | 保持同一 owner、请求 header、缓存 key 和尺寸索引规则 |
| RichDocument | `NovelReaderDocument` 和 shared rich text 模型 | 继续服务搜索、书签摘要和语义操作；不再由旧分页 Widget 直接渲染 |
| 阅读进度提交 | `NovelReaderProgressCommitter` | 继续 debounce、串行提交和退出 flush |
| SQLite 正文 | `novel_episode_content` | 不变，分页只消费当前章节正文 |
| 章节导航 | `NovelReaderController.openEpisode`、上下章节入口 | 保留 controller 单一入口，分页层不自行读取目录 |

### 3.2 当前必须清理或替换的旧实现

当前代码中已经有一组分页骨架，但它不应作为新功能继续扩展：

- `lib/features/novel/presentation/widgets/novel_reader_paged_surface.dart`
  - 旧分页 surface 使用旧的 `NovelReaderDocumentView`。
  - 旧 surface 自己持有页面布局、页码恢复和 PageController 生命周期。
  - 新实现应删除该 Widget 和其 controller。
- `lib/features/novel/presentation/services/novel_reader_layout_service.dart`
  - 旧布局服务缓存旧分页结果。
  - 新实现用 HTML-first 分页服务替代。
- `lib/features/novel/presentation/models/novel_reader_layout_key.dart`
- `lib/features/novel/presentation/models/novel_reader_layout_request.dart`
  - 两者包含旧分页请求字段和旧布局身份。
  - 新实现应建立新的 `NovelReaderPaginationKey`，加入 HTML renderer revision、图片尺寸 revision 和稳定正文身份。
- `NovelReaderProgressPolicy` 中旧的 `NovelReaderPaginator`、`NovelReaderPageLayout`、`NovelReaderPageSlice` 和旧分页恢复耦合。
  - 阅读进度快照本身可以保留。
  - 旧分页结果模型应删除或拆出后替换为新页片模型。
- `lib/features/novel/presentation/widgets/novel_reader_document_view.dart`
  - 如果确认只被旧分页 surface 使用，应随旧分页一起删除。
  - `NovelReaderDocument`、搜索服务和解析服务不能因此删除，它们仍承担语义解析和搜索职责。
- `novelReaderLayoutServiceProvider`
  - 删除旧 provider，改为新分页 coordinator provider。
- `NovelReaderPage._isPagedMode()` 当前返回 `false`，且顶部/底部模式入口只是提示“后续接入”。
  - 这不是可接受的分页状态机，必须改为真实模式分支。
- 旧的分页测试和旧文档测试。
  - 不应通过修改断言继续保留旧语义，应删除并替换为新 HTML-first 分页测试。

### 3.3 现有数据兼容结论

当前 `novel_reading_progress` 已经有 `flow_mode`、`page_index`、`anchor_node_id` 和 `progress_percent` 字段，当前偏好也已经能存储 `pagedLtr` 和 `pagedRtl`。这些字段不能直接证明旧页码对新分页有效：旧页码来自旧分页布局，新的 HTML-first 分页页数和页边界可能完全不同。

兼容规则如下：

1. 已保存的 `flow_mode` 继续作为用户模式选择读取，避免把用户已选的方向强制改回默认值。
2. 旧 `page_index` 在没有新 `paginationKey` 时只作为低优先级候选，不得直接当作新分页的真值。
3. `anchor_node_id`、`text_offset` 和 `progress_percent` 优先用于重新定位。
4. 新分页第一次成功生成后，保存新的 `paginationKey` 和新页码。
5. 如果锚点已经不存在，或者旧数据明显超出新正文范围，则安全回到当前章节第一页，并允许用户继续阅读；不得恢复到最后一页或显示空白页。
6. 不需要把旧分页页片导入新页片，也不需要读取旧下载 JSON。

## 4. 产品行为定义

### 4.1 模式定义

| 模式 | 用户行为 | 逻辑位置 |
| --- | --- | --- |
| 滚动 | 上下连续滚动正文 | `scrollOffset + anchor` |
| 分页 LTR | 横向向左滑进入下一页，向右滑返回上一页 | 逻辑 `pageIndex` 从 `0` 开始，视觉方向为 LTR |
| 分页 RTL | 按 RTL 方向横向翻页 | 逻辑 `pageIndex` 仍从 `0` 表示正文第一页，只有视觉方向反转 |

RTL 只改变 PageView 的视觉手势方向，不改变业务页码。业务层永远不把 RTL 的物理 index 当成正文 index，避免进度、书签和搜索跳转倒序。

### 4.2 模式切换

- 设置面板新增“阅读模式”分段选择：
  - `滚动`
  - `分页 LTR`
  - `分页 RTL`
- 分页模式的入口统一放在现有显示设置中；不再维护一个独立的、只显示提示的“模式”入口。
- 若保留底部“模式”按钮，它只能打开同一个显示设置面板，不能拥有另一套状态。
- 默认仍为纵向滚动，不因为本次增加分页而改变已有用户的阅读习惯。
- 设置预览仍可即时更新；持久化仍使用现有 SharedPreferences repository，不把用户偏好写入章节正文表。

### 4.3 分页页面

- 每一页使用当前阅读视口的可用宽高，扣除安全区和阅读器 chrome 后生成。
- 页面正文不显示额外的“章节标题”开关，也不重复插入章节标题；现有正文解析后的第一句/首个正文节点继续按当前规则展示。
- 页片不包含虚假的“下一章页面”，因此：
  - page count 只统计真实正文页。
  - slider（如果未来有只读进度显示）不把章节过场算作页。
  - 最后一页的章节切换通过明确的边界动作或现有章节入口处理。
- 底部不重新引入已经移除的 slider、左右章节按钮和底部书签图标。
- 如果 `showProgressIndicator` 开启，可以显示非交互式的“当前页 / 总页数”或百分比；它不是拖动控件。
- 页片内部不应该出现隐式的无限滚动。无法分页的特殊块必须有明确的降级策略，不能静默裁切内容。

### 4.4 章节切换

- 当前章节切换仍由 `NovelReaderController` 读取目录并决定目标章节。
- 从目录、上一章、下一章或搜索结果进入新章节时，不把当前章节的页码复制给目标章节。
- 目标章节如果有自己的有效阅读位置，按既有小说阅读进度规则恢复；没有有效位置则从第一页开始。
- 分页层不计算章节排序，不直接操作 repository，不修改章节进度之外的状态。

## 5. 目标架构

### 5.1 数据流

```text
SQLite novel_episode_content
        |
        v
NovelReaderBootstrapService
        |
        v
NovelReaderDocumentBuildService
        |
        v
NovelHtmlChapterRenderPreparer
  (简繁转换、DOM规范化、主题适配、图片语义和缓存规格)
        |
        +----------------------------+
        |                            |
        v                            v
Vertical HTML surface       NovelReaderPaginationCoordinator
                                      |
                                      v
                         HTML flow units / page fragments
                                      |
                                      v
                         ForumHtmlWidgetPostRenderer
                                      |
                                      v
                              PageView page surface
```

### 5.2 依赖方向

```text
NovelReaderController
  -> NovelReaderPaginationCoordinator (抽象)
  -> NovelReaderProgressCommitter
  -> NovelReaderRepository

NovelReaderPaginationCoordinator
  -> NovelReaderHtmlPreparationPort
  -> NovelReaderPageBreaker
  -> NovelReaderPaginationCache

NovelReaderPagedSurface
  -> NovelReaderPaginationSession
  -> ForumHtmlWidgetPostRenderer

NovelReaderController 不依赖 PageController、BuildContext、RenderBox 或 HTML DOM。
```

规则：

- controller 管理业务状态和章节切换，不管理 Flutter 滚动对象。
- pagination service 管理页片生成和布局身份，不保存 SQLite。
- Widget 管理页面生命周期、手势和可见页回调，不解析论坛 API。
- HTML renderer 继续拥有主题、链接、图片和富文本显示细节。
- 不把 `ForumHtmlWidgetPostRenderer` 类型泄漏到 domain 层；通过 novel 自己的 port/DTO 传递必要的页片信息。

## 6. 领域模型与接口草案

以下接口用于固定边界和责任，具体命名可以根据现有代码风格微调，但不应把这些职责重新合并到一个巨型 controller。

### 6.1 阅读位置

现有 `NovelReaderProgressSnapshot` 继续作为跨模式的持久化快照，但需要增加布局身份和更稳定的页片锚点概念：

`paginationKey` 是缓存和快速恢复用的身份，不是用户数据的业务主键。它不应写入作品元数据，只写入阅读进度的可选字段或单独的进度快照结构。

### 6.2 HTML-first 视觉输入

新分页不直接消费旧 `NovelReaderPageSlice`。建议建立一个只属于小说 presentation/data adapter 的准备结果：

```dart
class NovelReaderPreparedChapter {
  const NovelReaderPreparedChapter({
    required this.episodeId,
    required this.contentHash,
    required this.preparedHtml,
    required this.units,
    required this.themeSignature,
    required this.imageDimensionRevision,
  });

  final String episodeId;
  final String contentHash;
  final String preparedHtml;
  final List<NovelReaderFlowUnit> units;
  final String themeSignature;
  final int imageDimensionRevision;
}

class NovelReaderFlowUnit {
  const NovelReaderFlowUnit({
    required this.unitId,
    required this.html,
    required this.startAnchor,
    required this.endAnchor,
    required this.breakability,
    required this.imageIndices,
  });

  final String unitId;
  final String html;
  final NovelReaderTextAnchor startAnchor;
  final NovelReaderTextAnchor endAnchor;
  final NovelReaderFlowUnitBreakability breakability;
  final List<int> imageIndices;
}

enum NovelReaderFlowUnitBreakability {
  text,
  inlineText,
  blockImage,
  atomicWidget,
}
```

说明：

- `preparedHtml` 必须来自新的 `NovelHtmlChapterRenderPreparer`，不能直接从原始 HTML 另起一套样式解析。
- `units` 来自同一个已规范化 DOM 快照。不要先由一个 parser 生成分页，再让另一个 parser 重新生成视觉正文。
- `unitId` 必须稳定，至少包含章节、DOM 锚点和必要的文本偏移；不能使用每次 rebuild 都变化的随机 ID。
- `imageIndices` 使用现有全章图片序列的逻辑索引，不能在每一页重新从 0 开始，否则图片缓存和打开图片的序列会错乱。

## 7. 新 HTML-first 分页管线

### 7.1 准备阶段

准备阶段必须和纵向模式共享：

1. 从 `NovelChapterContent.rawHtml` 读取当前正文；缺失正文时仍由现有 bootstrap 错误处理负责。
2. 按当前偏好执行简繁转换。
3. 使用 `NovelHtmlChapterRenderPreparer` 和现有 `ForumHtmlRenderPreparer`：
   - 规范化 DOM 结构。
   - 应用论坛主题适配。
   - 规范化正文图片来源。
   - 生成全局图片序列和缓存请求规格。
   - 保留链接、表情、折叠内容和附件信息。
4. 从同一个 prepared DOM 构建 flow units。
5. 生成 `NovelReaderPaginationKey`。

分页层不能再次把原始 HTML 交给另一个 parser 生成“分页专用样式”。如果需要新增 DOM 拆分能力，应扩展现有 prepared document 的公开能力，或在小说 adapter 中对同一个 prepared fragment 做一次拆分。

### 7.2 Flow unit 切分

建议优先按语义块提取：

- 段落和标题：可断行、可按字符/文本 run 拆分。
- 带链接、粗体、斜体、颜色和内联表情的段落：保留 HTML 标签结构，在 DOM 文本节点边界进行拆分。
- 引用块：优先作为可拆分的嵌套流，保留引用样式。
- 独立图片：作为原子块，使用 HTML 宽高、缓存尺寸索引或稳定 fallback 比例。
- 分隔线和空行：作为可合并的间距 unit，不能产生大量只有空白的页面。
- Discuz 折叠块：按现有默认展开策略处理；如果内容展开后跨页，分页只切内容流，不复制标题。
- 无法安全拆分的复杂 widget：标记为 `atomicWidget`，进入明确的溢出降级策略。

每个 unit 都必须保存起止锚点。锚点至少包括：

- episodeId。
- 稳定 DOM/node ID。
- 文本偏移（对可拆分文本）。
- 生成时的语义版本或 renderer revision。

### 7.3 分页算法

分页算法分为“候选分割”和“渲染测量”两部分，不能只用字符数量猜页数。

#### 候选分割

- 文本使用与正文 renderer 相同的 typography 参数生成候选行布局。
- 长段落按文本节点和 run 拆分，保留 HTML 标签配对，不把 HTML 标签字符串截断到非法状态。
- 首次实现允许以文本 run 为最小可拆分单位；后续再补充字符级切分。
- 图片按照真实尺寸或缓存尺寸参与高度预算；未知尺寸使用稳定 fallback，并标记需要尺寸确认。
- 页片必须满足安全内边距和 bottom bar/top bar 预留高度。

#### 渲染测量

为了避免候选算法和实际 `flutter_widget_from_html_core` 高度差异过大，分页服务需要提供 Flutter presentation 层的测量 adapter：

- 候选页片交给与真实页面相同的 `ForumHtmlWidgetPostRenderer`。
- 在固定宽度和固定主题下测量实际高度。
- 若超过可用高度，则在最后一个可拆分 unit 处回退并重新切分。
- 对同一候选 fragment 的测量结果做 session 内缓存，避免重复构建。
- 测量过程必须有最大候选次数和超时/失败出口，不能阻塞页面永久 loading。

该 adapter 不应该进入 domain。domain 只知道“页片是否通过测量”和“页片边界”，Flutter 细节留在 presentation。

#### 特殊内容降级

- 独立大图：优先按可用高度缩放，不能裁切原图；点击打开仍使用现有图片 reader。
- 图片尺寸未知：先以 fallback 尺寸布局，尺寸解析完成后使 layout key 失效并按锚点重排。
- 超过一页的不可拆分 widget：不能静默裁切。第一版可以在该页开启明确标记的内部滚动，并记录诊断；后续逐步为该 widget 增加拆分器。
- HTML 异常或空片：丢弃空 fragment，若全章没有有效 fragment，显示正文为空的业务状态，不创建无穷空页。

### 7.4 页面渲染

新 `NovelReaderPagedSurface` 可以重新命名为 `NovelReaderHtmlPagedSurface`，但不能复用旧 surface 的状态逻辑。它应当：

- 接收已经生成的 `NovelReaderPaginationPlan`。
- 以 plan 的 owner key 创建独立的 `PageController`。
- `PageView.itemCount` 只使用真实 `pages.length`。
- `pagedRtl` 只反转视觉方向，不反转传给 controller 的逻辑 page index。
- 每个页面使用 `ForumHtmlWidgetPostRenderer` 渲染 page fragment。
- 传递全章 `sourceId`、`threadId`、`imageCacheOwnerId` 和全局图片序列。
- 对页面 index 变化只发出“真实页面已稳定可见”事件。
- 页面预构建、图片预加载、测量和解码完成都不能写阅读进度。
- owner、generation 或 plan key 变化时丢弃旧回调。
- plan 变化时销毁旧 PageController，禁止 PageStorage 恢复旧章节或旧布局页码。

## 8. 阅读进度与恢复策略

### 8.1 真值定义

分页模式的当前页真值只能来自：

- `PageView.onPageChanged` 的当前 session 回调。
- 用户完成的显式页码跳转。
- 用户点击搜索结果或书签后完成的定位。
- 应用进入后台或阅读器退出时的最终 flush。

以下事件禁止更新 pageIndex：

- page builder 构建相邻页。
- `precacheImage` 或图片解码完成。
- 测量页片。
- 预加载下一个章节。
- 旧 session 的迟到回调。
- 只因偏好预览而暂时生成的候选布局。

### 8.2 恢复优先级

生成新计划后，按以下顺序恢复：

1. 相同 `paginationKey` 且 pageIndex 有效：直接恢复 pageIndex。
2. 找到稳定 `anchorNodeId + textOffset`：映射到包含该 anchor 的新页面。
3. 使用 progressPercent 映射到新页数，并在相邻页通过 anchor 校正。
4. 最后才使用旧 pageIndex 作为低优先级兼容候选。
5. 所有候选都无效时回到 page `0`。

恢复结果必须 clamp 到 `[0, pageCount - 1]`，不得因为旧页码大于新页数而跳到末页。

### 8.3 模式切换定位

模式切换不应丢失用户正在看的正文：

- 纵向 -> 分页：读取 viewport 中真正位于顶部的 anchor，映射到新分页页片。
- 分页 -> 纵向：使用当前页的 start anchor，计算垂直 renderer 中对应的 scroll offset。
- LTR <-> RTL：保留逻辑 pageIndex，不重新按物理方向计算页码。
- 字号、行距、内容宽度或窗口方向改变：保留 anchor，重新生成 plan 后定位。
- 主题只改变颜色而不改变文字度量时，可以只重绘；若主题适配影响 HTML 结构或字体度量，则使 plan key 失效。

### 8.4 SQLite 变化

建议为 `novel_reading_progress` 增加可空的 `pagination_key` 或等价 `layout_fingerprint` 字段，并保持兼容：

- `flow_mode`、`page_index`、`anchor_node_id`、`progress_percent` 继续保留。
- 新字段只用于判断 pageIndex 是否属于当前布局，不保存正文或页片 HTML。
- 旧版本行的字段为空时按“无可信 paginationKey”处理。
- 迁移只增加列和默认值，不迁移、不重写旧小说正文，不改变 `novel_episode_content`。
- repository 读取未知/损坏 fingerprint 时回退到 anchor/percent 恢复。
- 书签位置仍使用 `reader_bookmarks`，不与阅读进度混用。

如果实际验证发现 anchor 已经足以稳定恢复，也可以不增加字段，但必须在代码中明确“pageIndex 仅为同一布局优化”，并以测试证明旧布局不能错误恢复。默认推荐增加可空 fingerprint，因为它能直接区分旧分页和新分页。

## 9. 搜索、书签、链接和图片的接入规则

### 9.1 搜索

- 搜索服务继续在 `NovelReaderDocument` 的语义模型上运行，不对分页页片重新做全文搜索。
- 搜索结果携带 nodeId、textOffset 和当前章节。
- 分页模式点击搜索结果时先等待当前 plan ready，再通过 anchor 映射 pageIndex。
- 结果所在页只高亮目标文本；如果当前 renderer 第一版无法在 page fragment 中精确高亮，至少必须跳到包含结果的页并保持正文可读。
- 纵向模式保留现有 scroll anchor 行为。

### 9.2 书签

- 顶部章节书签入口保持不变。
- 位置书签使用 `NovelReaderTextAnchor`，不保存易失的 pageIndex 作为唯一定位。
- 分页模式展示位置书签时优先用 anchor 映射页码。
- 页面重排后，书签仍以 nodeId/textOffset 重新定位；找不到时显示“位置已变化”，不能跳到随机页。

### 9.3 链接

- 页片内链接继续通过现有 `NovelReaderLink` 和 `_openReaderLink` 处理。
- HTML fragment 拆分不得切断 `<a>` 标签；需要拆分时应在标签内部生成合法的开始/结束标签。
- 链接点击不得被 PageView 的左右点击区域吞掉。手势层只能处理空白区域或未被链接消费的手势。

### 9.4 正文图片和表情

- 普通正文图片、表情和缩略资源继续使用新 HTML renderer 的资源类型。
- 图片序列索引是全章稳定索引，不按页重置。
- 分页页片只影响显示，不改变图片下载、缓存、章节下载和作品清理语义。
- 单页图片的尺寸变化触发当前 plan 失效时，使用当前可见页 anchor 重新定位，不把用户送回第一页。
- 图片打开仍由 `NovelHtmlImageReaderBridge` 生成现有 `ThreadImageOpenRequest`。

## 10. UI 与交互方案

### 10.1 显示设置

建议把“阅读模式”放入现有 `NovelReaderDisplaySettingsSheet` 的“阅读”分组：

```text
阅读模式
  滚动
  分页 LTR
  分页 RTL

简繁
  原文
  简体
  繁体
```

- 使用现有 segment control 风格。
- 设置改变时先 preview，布局准备完成后再提交状态。
- 分页准备失败时不保存一个无法工作的模式；恢复为上一次有效模式，并显示可操作错误提示。
- 保存失败时恢复 preview，保持现有设置 repository 的错误处理方式。

### 10.2 分页 chrome

- 使用现有 `ReaderOverlayScaffold`，不创建第二套顶部/底部菜单。
- 顶部保留书签、搜索、打开原帖等已有入口。
- 不新增底部书签图标，不新增底部 slider 和左右章节按钮。
- 底部只显示目录、显示设置和必要的只读页码指示。
- 页面切换时按现有 reader overlay 规则隐藏菜单，避免底部 chrome 遮挡正文。

### 10.3 加载、失败和降级

分页计划异步生成时：

- 保留当前正文或显示轻量的非方向性布局加载遮罩，避免用户误触半成品页面。
- 不显示“评论加载中”或漫画 reader 的过场状态。
- 如果已有旧 plan 且只是小范围重排，可以短暂保留旧页作为视觉占位，但不能继续写旧页进度。

分页失败时：

- 页面显示“分页布局失败，已保留正文”，提供“回到滚动模式”和“重试分页”。
- 现有章节内容仍可通过纵向模式阅读。
- 不把分页失败写成章节内容丢失，不清理 SQLite 正文，不删除书签。
- 错误日志记录稳定错误类别、章节 ID 和 renderer revision，不记录正文全文、Cookie 或完整网络凭据。

- 纵向模式无回归。

### Phase 4：进度、重排和章节导航收口

> 状态：已完成（2026-07-20）。本阶段已接入分页位置持久化、布局指纹、锚点/百分比恢复、模式切换位置桥接和生命周期 flush。

#### 目标

让分页阅读成为可持久使用的模式，而不是只能临时浏览。

#### 实施内容

1. 新增 `paginationKey/layoutFingerprint` 持久化和 migration（若 Phase 0 评估确认需要）。
2. 以 anchor 优先、同 key 页码次之的规则恢复位置。
3. 模式切换时保持当前位置。
4. 字号、行距、窗口尺寸、方向和图片尺寸变化时按 anchor 重新定位。
5. 进度只由真实可见页、显式跳转和退出 flush 提交。
6. controller 增加分页位置事件，但不接收 PageController。
7. 章节切换继续调用现有 controller 入口；目标章节不继承源章节页码。
8. 处理应用后台、页面 dispose、快速切换章节和重建布局时的 generation。

#### 本阶段实际交付

- `novel_reading_progress` 在数据库 v34 增加可空 `pagination_key` 与 `anchor_text_offset`；旧版本行只获得空指纹和零偏移默认值，正文、页片缓存、书签和作品元数据均不变。
- `NovelReaderPaginationKey.layoutFingerprint` 使用稳定 SHA-256 指纹标识章节内容、视口、排版、主题、图片尺寸 revision 和 renderer revision；它只作为阅读进度布局身份，不是作品主键。
- `NovelReaderPaginationRestorePolicy` 按同一布局的有效页码、稳定锚点、阅读百分比、旧页码兼容候选的顺序恢复；旧页码越界时回到第一页，不会被 clamp 到末页。
- 页面真实可见的初始页、`PageView.onPageChanged` 页和显式 flush 都通过 `NovelReaderPaginationPosition` 进入 controller；`PageController`、HTML Widget 和 RenderObject 没有进入 controller 或 SQLite。
- 每个分页 session 按 plan key 隔离，旧 plan 的迟到位置事件会在 surface 层丢弃。页片保存页内全部 anchor range，因此布局变化后可以定位到包含原文本节点的页面，而不是只能回到节点首屏。
- 分页转滚动时使用分页快照的百分比计算当前滚动 offset；滚动转分页时使用 anchor，缺失 anchor 时使用百分比。LTR/RTL 只改变视觉方向，不改变逻辑页码。
- 分页阅读在后台、退出和章节切换时 flush 当前快照；分页准备尚未完成时保留已有位置快照，不会把未生成的第一页冒充为用户位置。

#### 测试重点

- 同一 key 重进恢复同一页。
- 同一正文改字号后恢复到同一 anchor 附近，而不是固定旧 pageIndex。
- 从纵向切到分页、从分页切回纵向位置不跳到章节开头。
- LTR 切 RTL 后仍在同一逻辑页。
- 退出刷新不会写入预加载页。
- 旧分页进度不把新分页恢复到末页。
- 快速切章节时旧计划、旧图片和旧 page callback 不污染新章节。

#### 验收标准

- 进度数据重启后可以可靠恢复。
- 任何布局变化都不会出现空白、越界或跨章节恢复。
- SQLite 只保存位置和身份，不保存重复正文。

### Phase 5：交互完整性、性能与可访问性

> 状态：已完成（2026-07-20）。本阶段已完成锚点交互、有限挂载、分页诊断和长章节响应性收口；真实设备验收与发布前清理仍属于 Phase 6。

#### 目标

补齐实际阅读中容易被分页放大的边界场景，并控制内存和布局成本。

#### 实施内容

1. 搜索结果和位置书签在分页页片中精确定位。
2. 图片点击、链接点击、表情和折叠块回归。
3. 只预热当前页和有限相邻页，不把全章 HTML widget 全部挂载。
4. 对长章节使用布局缓存和分段计算，必要时在 isolate 做纯数据候选计算。
5. 增加渲染诊断：page count、布局耗时、重排次数、未知图片尺寸数量和降级页数量。
6. 处理语义树：页码、上一页/下一页、当前章节和书签按钮有稳定 label。
7. 验证大字号、小屏、横屏、系统字体缩放和深色/护眼主题。

#### 本阶段实际交付

- 搜索结果和章节书签通过 `NovelReaderAnchorNavigationRequest` 以声明式请求传递到分页 surface。请求只携带 request ID 和语义锚点，不泄漏 `PageController`；跨章节跳转在目标章节成功打开后才提交，锚点无法映射时保留当前位置并反馈可理解的提示。
- `NovelReaderHtmlPreparationService` 和 flow unit extractor 接收同一个 `NovelReaderDocument` 语义来源。能匹配的 flow unit 复用 `node-N` 锚点，未匹配内容使用确定性 fallback，保证搜索/书签锚点与新 HTML-first 页片使用同一身份。
- 分页 surface 通过稳定 page key、`PageView` 的有限构建范围和 `allowImplicitScrolling: false` 控制挂载成本；页片继续使用共享 `ForumHtmlWidgetPostRenderer`，图片点击、链接和图片 fallback 不建立第二套渲染链。
- `NovelReaderPaginationCache` 作为页面生命周期拥有的容量受限 LRU，在章节和模式 surface 重建之间复用派生页片；缓存只存在进程内，不写入 SQLite、正文表或下载目录。
- `NovelReaderPaginationDiagnostics` 记录章节、布局指纹、页数、耗时、重排次数、未知图片尺寸、溢出页、缓存命中和 flow unit 数量。默认 debug sink 不记录正文、Cookie 或完整请求信息，release 模式不输出诊断日志。
- 分页语义树提供章节、当前页/总页数和上一页/下一页动作；逻辑页码在 LTR/RTL 中保持一致，语义动作和实际 PageView 翻页都会走同一位置回调。
- page breaker 的候选测量预算提升到 `4096`，每 `32` 次测量主动让出事件循环；预算仍是有限的，超过预算会进入已有的分页失败/纵向回退路径，不会无限等待。
- 新增页面级测试覆盖分页锚点、语义标签、有限邻页挂载和相同布局恢复；flow unit、preparation、page breaker 与 LRU cache 测试覆盖稳定锚点、全章图片索引、溢出降级、缓存边界和布局异常。

#### 测试重点

- 1000 个段落和较长正文不会阻塞 UI 主 isolate。
- PageView 只保留有限页面，内存不会随页数线性增长。
- 低内存回收图片缓存后，当前页可以恢复，不改变进度。
- TalkBack/VoiceOver 能知道当前页和翻页动作。
- 触摸链接不会误触页面翻页。

#### 验收标准

- 常见章节首次分页可接受，重进同一布局优先命中缓存。
- 快速滑动、快速打开搜索/书签和切换主题没有崩溃或错页。
- 不存在只在特定屏幕尺寸下稳定的隐式溢出。

### Phase 6：真机验收、灰度和清理收口

> 状态：代码收口已完成（2026-07-20）；自动化验证与 Android release 构建通过，Android/iOS 真机矩阵仍需人工执行后才可宣布正式发布。

#### 目标

在发布前确认真实 HTML、真实图片和不同设备尺寸下的可读性，并移除临时降级开关和诊断噪音。

#### 实施内容

1. Android 和 iOS 真机验证纵向、LTR、RTL、后台恢复和横竖屏。
2. 使用真实但脱敏的长章节、混合图片章节、含引用和折叠内容章节。
3. 验证水合后的 SQLite 正文可以离线生成分页；断网不影响已水合章节阅读。
4. 验证图片失败不会让文字页变成空白，仍遵循现有图片失败占位。
5. 验证应用升级、数据库 migration 和旧阅读进度兼容。
6. 删除旧分页残留 feature flag、旧测试 fixture 和无效诊断代码。
7. 更新 `docs/开发文档.md`，记录最终行为和 review 重点。

#### 本阶段实际交付

- 默认分页诊断 sink 改为 `NovelReaderNoopPaginationDiagnosticsSink`，普通开发运行和 release 构建不再打印每次分页的诊断噪音；`NovelReaderDebugPaginationDiagnosticsSink` 仍可通过显式依赖注入启用，用于本地排障，不进入默认产品链路。
- 全仓库检索确认没有旧 `NovelReaderPagedSurface`、旧 layout service、旧 paginator、旧 PageStorage 分页状态或旧分页 provider 的代码引用。当前分页只有 HTML-first surface 一条视觉链路；纵向 fallback 仍是分页失败时的正式可操作入口。
- 保留 Phase 4 的 SQLite `pagination_key`/anchor migration 与旧行兼容策略，不增加第二份正文或分页页片存储。水合正文仍从规范化 SQLite 内容表读取，断网分页继续复用同一 prepared HTML 和图片缓存管线。
- 分页图片继续交由共享 HTML renderer 处理。图片尺寸未知、加载慢或加载失败时，文字页不被清空；分页只使用已有尺寸/fallback 预算和图片失败占位，不复制图片文件。
- 增加最终验收记录边界：自动化测试、静态分析和 Android arm64 release build 可以在开发环境执行；Android/iOS 真机、系统回收和横竖屏矩阵必须在真实设备上人工复核，不能由 widget test 冒充。
- 默认阅读模式仍保持滚动，分页通过既有显示设置显式开启。Phase 6 不以一次通过的模拟器测试为依据改变用户默认偏好。

#### 验收标准

- 真实设备上分页不会因字体、状态栏、安全区或系统导航栏产生底部裁切。
- LTR/RTL 的首尾页、章节切换和进度恢复一致。
- 旧版本用户升级后不会丢失正文、书签和可恢复的阅读位置。
- 通过相关测试、`flutter analyze`、release 构建和手工真机验收后才允许默认开放。

## 12. 测试矩阵

### 12.1 Domain/Service

- `NovelReaderPaginationKey` 对所有影响布局的输入敏感，对无关字段稳定。
- 相同 prepared HTML 和相同 key 得到相同页数、unit ID 和 anchor。
- 长文本可以在合法 HTML 边界拆分。
- 任何生成的 fragment 都是可解析、标签闭合的 HTML。
- 过短/过长 viewport、空正文和异常 HTML 有确定结果。
- 旧 pageIndex 没有 paginationKey 时不会无条件恢复。
- anchor 优先于 percent，percent 优先于旧 pageIndex。
- 相同 key 并发请求只有一次实际计算。
- 新 generation 产生后，旧 generation 结果被丢弃。

### 12.2 HTML/render parity

- 纵向和分页使用同一 conversion、theme 和 image preparation 结果。
- 相同正文的文字样式、链接 URL、图片 URL、图片 owner 和图片 index 一致。
- 分页 fragment 的图片点击仍能生成完整 image reader request。
- 表情不会被错误计入普通正文图片序列。
- 主题切换后 prepared document 和 layout key 正确失效。

### 12.3 Widget

- 默认显示 `novel-reader-paragraph-list`，没有分页 surface。
- 选择 `pagedLtr` 显示新 HTML paged surface，旧 `novel-reader-paged-view` key 不再作为契约。
- 选择 `pagedRtl` 的第一个逻辑页内容仍是正文开头。
- 页面翻动只提交实际 pageIndex。
- 页面构建和图片预加载不提交进度。
- 章节切换期间阻止重复手势，成功后新章节从自己的恢复位置开始。
- 分页失败可以回到纵向模式。
- 显示设置、搜索、书签、打开原帖和图片打开没有回归。

### 12.4 Persistence/migration

- 默认偏好仍为：字号 `18.5`、行高 `1.6`、护眼主题、纵向模式。
- SharedPreferences 保存/读取三种 flow mode。
- SQLite 旧行能读取，缺失 pagination key 时安全降级。
- 新行保存 flow mode、page index、anchor、progress percent 和新 layout identity。
- 清理作品时阅读进度和书签继续由现有 purge 链路处理。
- 不会把 HTML、分页页片或图片字节写入 metadata。

### 12.5 真机

- Android 13/14/15、iOS 当前支持版本。
- 小屏、大屏、横屏、系统字体放大。
- LTR/RTL 手势方向和语义方向。
- 锁屏、切后台、恢复、应用被系统回收后重新进入。
- 断网读取已水合正文。
- 图片无尺寸、图片加载慢、图片加载失败、缓存回收。
- 长章节首次生成和命中布局缓存的耗时、内存。

## 13. 性能与可靠性约束

- 不在每次 `build` 中重新解析、转换和分页整个章节。
- 同一个 prepared chapter + pagination key 使用 single-flight。
- 不把全章每一页都永久保存在 Widget tree 中。
- PageView 只负责当前页和有限邻页，页片数据可缓存但要有上限。
- 主题或偏好预览时使用 debounce，旧布局计算必须可丢弃。
- 任何布局计算异常都必须有错误状态和纵向 fallback。
- 进度提交继续使用现有 committer，不能让每次滑动产生同步 SQLite 写入阻塞手势。
- 诊断中不记录正文全文、Cookie、完整请求头或私有本地路径。
- 图片缓存继续使用现有 protected/owner 语义，不因为分页复制图片文件。

## 14. 明确禁止的实现方式

以下方式会重新制造旧问题，实施时应在 code review 中直接拒绝：

1. 在 `NovelReaderController` 中直接创建或持有 `PageController`。
2. 让分页 surface 读取章节目录并自行计算下一章。
3. 保留旧 `NovelReaderPagedSurface`，再通过条件分支塞入新 renderer。
4. 用字符数粗略切页后永远不经过真实 renderer 高度验证。
5. 每一页重新从图片索引 0 构造图片 owner。
6. 用 PageStorage 自动恢复跨章节的物理页码。
7. 把 `pageIndex` 作为跨字号、跨窗口和跨 renderer revision 的唯一进度真值。
8. 把分页页片写入 SQLite 正文、作品 metadata 或下载目录。
9. 为分页单独引入一个与论坛正文不同的 HTML 主题和图片组件。
10. 用全章 `shrinkWrap` 列表或一次性构建所有页面换取“实现简单”。
11. 在页面 builder、图片预加载或测量回调中写阅读进度。
12. 分页失败时静默显示空白页或静默丢弃无法显示的正文。

## 17. 最终完成定义

只有同时满足以下条件，才认为“小说分页阅读模式”完成：

## 18. 后续实现顺序

实际开发时按以下顺序推进，不建议跳过 Phase 0 直接修改现有分页 surface：

1. 完成 Phase 0，删除旧分页并让纵向模式保持绿灯。
2. 完成 Phase 1，先证明新 HTML prepared document 可以稳定拆成合法 flow units。
3. 完成 Phase 2，单独验证分页计划和重排，不急着接入复杂手势。
4. 完成 Phase 3，再开放用户模式开关和 PageView。
5. 完成 Phase 4，处理进度和章节切换，否则用户会遇到“能翻但不能恢复”的半成品体验。
6. 完成 Phase 5/6 后再作为默认可长期使用的阅读模式发布。
