## 3. 接口设计与封装（已实现）

### 3.1 目标

统一请求入口，统一错误返回，统一 Cookie 管理，保证后续页面开发只依赖 Repository，不直接写 HTTP 细节。

### 3.2 代码结构

```text

    utils/

    network/

      cookie_store.dart            # Cookie 持久化（shared_preferences）
      discuz_response.dart         # Discuz 通用响应包装
```

### 3.3 统一请求规范

`ApiClient` 已统一处理：

1. 自动注入公共参数 `version=4`。
2. 自动从本地读取 Cookie 并随请求发送。
3. 自动解析响应中的 `set-cookie` 并持久化。
4. 统一返回 `ApiResult<T>`，避免 UI 层直接 try-catch 网络异常。
5. 对 Discuz 的 `Message` 结构做业务错误识别。

### 3.4 错误模型

统一错误类型：

- `ApiErrorType.network` 网络连接异常
- `ApiErrorType.timeout` 请求超时
- `ApiErrorType.unauthorized` 未授权/登录失效
- `ApiErrorType.server` 服务端异常
- `ApiErrorType.parse` 响应或业务解析异常
- `ApiErrorType.business` 业务失败（Discuz Message）
- `ApiErrorType.unknown` 未知错误

UI 层只需要判断 `ApiResult` 是 `ApiSuccess` 还是 `ApiFailure`。

### 3.5 已封装接口

基于 `docs/解析.md` 已完成以下 Repository：

1. `ForumRepository.getForumIndex()`
   - module: `forumindex`
2. `ProfileRepository.getProfile()`
   - module: `profile`
3. `FavoriteRepository.getFavoriteForums()`
   - module: `myfavforum`
4. `FavoriteRepository.getFavoriteThreads(page)`
   - module: `myfavthread`
5. `ThreadRepository.getThreadDetail(tid, page)`
   - module: `viewthread`
6. `AuthRepository.refreshSession()`
   - 复用 `profile` 接口判断登录态
7. `AuthRepository.login(username, password, questionId, answer)`
  - 通过 Discuz 网页登录流程（`member.php?mod=logging&action=login`）完成真实鉴权
  - 自动提取 `formhash` 和 `loginhash`
  - 自动接收并持久化登录 Cookie
  - 登录后立即调用 `profile` 二次校验会话是否生效
7. `AuthRepository.logout()`
   - 清理本地 Cookie 会话

> 说明：当前登录能力已不是“只调移动接口探活”，而是“先网页登录建会话，再通过移动接口校验登录态”。

### 3.6 登录态与鉴权实现细节（关键）

本次实现对齐 `docs/Discuz-X3.5移动端App实现方案.md` 的第 4 节，落地如下：

1. 新增站点地址配置 `AppConfig.siteBaseUrl`，用于网页端登录入口。
2. `ApiClient.loginWithWebCredentials` 按两步执行：
  - GET 登录页：提取 `formhash/loginhash`，并接收预登录 Cookie。
  - POST 登录表单：提交用户名密码和必要字段，接收登录 Cookie。
3. `AuthRepository.login` 负责业务层收口：
  - 网页登录成功后，立刻请求 `profile`。
  - 当 `member_uid` 为空或为 `0` 时，判定为会话未真正生效，返回 `ApiErrorType.unauthorized`。
4. 失败场景统一纳入 `ApiResult`：
  - 参数提取失败 -> `ApiErrorType.parse`
  - 登录失败提示（如密码错误）-> `ApiErrorType.business`
  - 网络异常、超时 -> 沿用统一 Dio 异常映射

### 3.7 调用示例（Riverpod）

```dart
final repository = ref.read(forumRepositoryProvider);
final result = await repository.getForumIndex();

result.when(
  success: (data) {
    // 使用 data.forums 渲染列表
  },
  failure: (error) {
    // 显示 error.message
  },
);
```

登录调用示例：

```dart
final authRepository = ref.read(authRepositoryProvider);
final loginResult = await authRepository.login(
  username: username,
  password: password,
);

loginResult.when(
  success: (session) {
    // session.isLoggedIn == true，进入已登录态
  },
  failure: (error) {
    // 展示 error.message，例如“密码错误”
  },
);
```

### 3.8 分页约定

- 收藏帖子和帖子详情分页均从 `page=1` 开始。
- 收藏列表模型 `FavoriteThreadsPage` 提供 `hasMore`。
- 帖子详情模型 `ThreadDetailData` 提供 `hasMore`。

### 3.9 扩展约定

后续新增接口时，按以下步骤：

1. 在对应 feature 下新增 `models`。
2. 在对应 Repository 中新增方法，调用 `ApiClient.getParsed`。
3. UI/State 层只依赖 Repository 与模型，不直接依赖 Dio。
4. 每新增一个接口，在 `docs/解析.md` 增补成功/失败 JSON 样例。

## 4. 测试说明（本次新增）

### 4.1 测试文件

- `test/features/auth/auth_repository_test.dart`

### 4.2 已覆盖测试用例

1. 登录成功：
  - 网页登录成功后返回 `ApiSuccess<SessionInfo>`。
  - 断言 `session.isLoggedIn == true`。
  - 断言后续 `profile` 请求带上了登录 Cookie。
2. 登录失败：
  - 模拟网页登录返回错误提示（如“密码错误”）。
  - 断言返回 `ApiErrorType.business` 并保留错误文案。
3. 登录后会话未生效：
  - 模拟网页登录成功但 `profile.member_uid = 0`。
  - 断言返回 `ApiErrorType.unauthorized`。
4. 退出登录：
  - 执行 `logout()` 后 Cookie 被清理。
