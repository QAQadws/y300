# 阶段 1：优化收藏解析流程

**预计时间：8–10 小时**

## 1. 当前问题

### 1.1 解析阻塞

`NetworkFavoriteSyncService._fillMissingDetails()` 逐条加载所有收藏帖子的详情，全部完成后才刷新 UI。

```
当前流程：
拉取列表 → 写入 DB → 逐条加载详情(全部) → 分类 → 摄入模块 → 刷新UI
                         ↑
                   用户在此等待，看不到漫画/小说
```

**问题**：
- 用户首次打开 App，有 N 条收藏时需等待 N × (网络请求时间) 才能看到漫画/小说模块
- 小说每章节都解析出来了（重度操作），封面图片也在详情加载阶段就处理
- 收藏列表的 `remote_order`（按收藏时间排序）没有被严格遵守

### 1.2 刷新生硬

- 必须等全部解析完才手动刷新漫画小说模块
- 解析过程中没有增量更新，用户感知上是"卡住"的

### 1.3 排序问题

- 新收藏的帖子应该出现在对应分类的最前端
- 首次解析时，`remote_order` 小的（最新收藏）应该排前面

## 2. 目标架构

```
                        ┌──────────────┐
                        │  拉取收藏列表  │  ← 分页拉取全部
                        └──────┬───────┘
                               │
                        ┌──────▼───────┐
                        │  Phase 1:     │  ← 快速概览 (仅写 DB，不摄入模块)
                        │  批量轻量分类  │     只做: title/tid/contentKind
                        └──────┬───────┘     不解析章节/封面
                               │
                        ┌──────▼───────┐
                        │  首次渲染     │  ← 收藏页立即可见
                        │  (收藏页 UI)  │
                        └──────┬───────┘
                               │
                        ┌──────▼───────┐
                        │  Phase 2:     │  ← 渐进摄入管道
                        │  逐个摄入      │     每完成 N 个 → 通知 UI 刷新
                        │  (漫画/小说)   │
                        └──────┬───────┘
                               │
                        ┌──────▼───────┐
                        │  Phase 3:     │  ← 深度解析（可选，延迟执行）
                        │  封面/章节补全 │     漫画封面、小说章节
                        └──────────────┘
```

## 3. 详细设计

### 3.1 新增管道模型文件

**新文件：`lib/features/favorites/domain/favorite_pipeline_models.dart`**

```dart
/// 收藏解析管道的三阶段处理级别
enum FavoriteProcessingLevel {
  /// 仅记录基本信息（title, tid, dateline），不分类、不摄入
  bare,

  /// 轻量分类：加载帖子详情后分类为 comic/novel/forum，但不解析章节
  light,

  /// 完全解析：分类 + 摄入模块 + 解析章节/封面
  full,
}

/// 收藏管道中每一条记录的处理状态
enum FavoriteItemProcessingState {
  /// 尚未处理
  pending,

  /// 正在加载帖子详情
  loadingDetail,

  /// 已分类但尚未摄入模块
  classified,

  /// 正在摄入漫画/小说模块
  ingesting,

  /// 摄入完成，等待深度解析（封面/章节）
  awaitsDeepParse,

  /// 完全完成
  completed,

  /// 处理失败
  failed,
}

class FavoritePipelineProgress {
  final int total;           // 需要处理的总数
  final int bareCount;       // 已 bare 的
  final int classifiedCount; // 已分类的
  final int ingestedCount;   // 已摄入模块的
  final int completedCount;  // 完全完成的
  final int failedCount;     // 失败的
  final String? currentTid;
  final String? message;

  // 供 UI 展示
  double get lightFraction =>
      total > 0 ? classifiedCount / total : 0.0;
  double get fullFraction =>
      total > 0 ? ingestedCount / total : 0.0;
}
```

```dart
Future<FavoriteSyncResult> _syncInternal() async {
  // 1. 拉取列表（不变）
  // 2. 保存列表到 DB（不变）
  // 3. 快速分类 — 轻量加载详情 + 分类，不摄入
  final classifyResult = await _lightClassify();
  // 4. 发出快速阶段完成信号，UI 此时已能显示分类后的收藏
  _emitProgress(FavoriteSyncProgress(
    phase: FavoriteSyncProgressPhase.classified,
    message: '已完成快速分类',
    current: classifyResult.classifiedCount,
    total: classifyResult.total,
  ));
  // 5. 渐进摄入 — 逐个摄入漫画/小说模块
  await _progressiveIngest(classifyResult.comicTids, classifyResult.novelTids);
  // 6. 完成
}
```

#### 阶段 B：渐进摄入管道

```dart
/// 新增枚举阶段
enum FavoriteSyncProgressPhase {
  idle,
  fetchingList,
  savingList,
  classifying,     // 新增：快速分类中
  classified,      // 新增：快速分类完成
  ingesting,       // 新增：渐进摄入中
  finishing,
  completed,
  failed,
}

/// 渐进式摄入：
/// - 逐个处理漫画/小说摄入
/// - 每完成 _ingestNotifyBatchSize 个，发出进度
/// - UI 监听进度并在 ingestedCount 增加时自动刷新模块
Future<void> _progressiveIngest(
  List<String> comicTids,
  List<String> novelTids,
) async {
  final allTids = <String>[...comicTids, ...novelTids];
  // 按 remote_order 升序（小的 = 最新收藏 = 排前面）
  var ingested = 0;
  for (final tid in allTids) {
    // 获取记录
    final record = await _localRepository.getActiveThreadByTid(tid);
    if (record == null) continue;

    // 加载详情
    final result = await _loadThreadDetail(tid);

    // 摄入模块（只做直接解析，不搜索）
    await _syncModuleWithLevel(
      detail: detail,
      kind: record.contentKind,
      tagName: record.sourceTagName,
      level: FavoriteProcessingLevel.light, // 只做直接解析
    );

    ingested++;

    // 每 N 个发出进度 → UI 刷新
    if (ingested % _ingestNotifyBatchSize == 0) {
      _emitProgress(FavoriteSyncProgress(
        phase: FavoriteSyncProgressPhase.ingesting,
        message: '已更新 $ingested/${allTids.length} 部作品',
        current: ingested,
        total: allTids.length,
      ));
    }
  }

  // 最后再发一次保证完整刷新
  _emitProgress(FavoriteSyncProgress(
    phase: FavoriteSyncProgressPhase.ingesting,
    message: '已更新 $ingested/${allTids.length} 部作品',
    current: ingested,
    total: allTids.length,
  ));
}
```

在 `RepositoryComicFavoriteIngestService` 中实现 `lightUpsertFromThreadDetail`：

```dart
Future<String> lightUpsertFromThreadDetail({
  required ThreadDetailData detail,
  String? sourceTagName,
}) async {
  final comicId = buildComicWorkId(detail.tid);
  final aggregation = _aggregationService.build(detail.posts);

  // 只解析基本结构，不深度提取每张图片
  final parsed = _parserService.parseInput(
    ComicPostParseInput(
      messageHtml: aggregation.parseMessage,
      attachmentImageUrls: const [], // 暂不处理附件图片
    ),
  ).copyWith(subjectMetadata: _subjectParser.parse(detail.subject));

  // 判断是否需要深度解析
  final isLongSerial = (sourceTagName ?? '').contains('長篇連載') ||
      (sourceTagName ?? '').contains('长篇连载');
  final hasCatalog = parsed.catalogUrl != null &&
      parsed.catalogUrl!.trim().isNotEmpty;
  final hasDirectLinks = parsed.episodeLinks.isNotEmpty;

  await _repository.addToShelfWithLevel(
    comicId: comicId,
    tid: detail.tid,
    fid: detail.fid,
    sourceTypeId: detail.typeid,
    sourceTagName: sourceTagName,
    title: detail.subject,
    parsedPost: parsed,
    processingLevel: isLongSerial && !hasCatalog && hasDirectLinks
        ? FavoriteProcessingLevel.light  // 需要后续深度解析
        : FavoriteProcessingLevel.full,  // 直接完成
  );

  return comicId;
}
```

## 4. 数据流图

```
                    FavoriteSyncService
                    ├─ sync()
                    │   ├─ 拉取列表页 → 写入 DB
                    │   ├─ 快速分类（加载详情 + contentKind 判定）
                    │   │   每完成一条发出进度
                    │   ├─ 发出 classified 事件
                    │   │       ↓
                    │   │   FavoriteShelfPage 刷新
                    │   │   (此时漫画/小说分类已可见)
                    │   │
                    │   ├─ 渐进摄入
                    │   │   for each comic/novel tid (按 remote_order ASC):
                    │   │     ├─ 加载详情
                    │   │     ├─ lightUpsert 到 comic/novel 模块
                    │   │     └─ 每 N 个发出 ingested 进度
                    │   │           ↓
                    │   │       ComicShelfPage / NovelShelfPage 增量刷新
                    │   │
                    │   └─ 发出 completed 事件
                    │           ↓
                    │       UniversalShelfPage 最终刷新
                    │
                    └─ 阶段 2 队列开始处理 awaits_deep_parse 的漫画
```

## 7. 验收标准

1. ✅ 首次同步后，收藏页立即显示分类后的列表（漫画/小说/默认）
2. ✅ 无需手动刷新，漫画/小说模块逐步出现内容
3. ✅ 收藏列表严格按收藏时间排序（最新在前）
4. ✅ 新收藏的漫画/小说出现在对应"默认"分类最前端
5. ✅ 同步过程中进度条持续更新，不会"卡住"
6. ✅ 轻量摄入不解析小说章节、不下载封面
