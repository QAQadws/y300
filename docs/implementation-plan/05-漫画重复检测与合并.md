# 阶段 5：漫画重复检测与合并

**预计时间：8–10 小时**

## 1. 问题分析

### 1.1 为什么会产生重复

在 Discuz 论坛中，一部漫画可能分散在多个帖子：
- 帖子 A：`[汉化组] 某某漫画 第1-5话` （tid=100）
- 帖子 B：`[汉化组] 某某漫画 第6话`   （tid=200）
- 帖子 C：`[汉化组] 某某漫画 第7-8话` （tid=300）

如果用户收藏了这三条帖子，当前系统会创建**三个独立的漫画作品**，分别在漫画模块中显示。

### 1.2 检测依据

- **不依赖标题**：因为同一漫画的帖子标题格式可能不同（有的带汉化组名，有的不带，有的用繁体）
- **依赖 tid 重叠**：如果漫画 A 的章节中包含漫画 B 的 source_tid，则 A 和 B 是同一漫画

### 1.3 三种触发场景

| 场景 | 时机 | 行为 |
|------|------|------|
| 1. 首次使用 App | 大量解析收藏时 | 踢出被包含的漫画，只保留完全解析的 |
| 2. 新收藏帖子 | 论坛收藏后解析 | 保留已存在的漫画，把新帖子的 tid 合并进去 |
| 3. 自定义标题 | 用户手动修正标题后 | 同场景 2，保留已存在的（有自定义标题的）漫画 |

## 2. 核心概念

### 2.1 漫画的 "tid 集合"

每个漫画作品由一组 tid 组成：
- `source_tid`：最初创建该漫画的帖子 tid
- 每个章节有一个 `source_tid`：该章节来自哪个帖子
- 合并后的漫画包含所有相关帖子的 tid

```
comic_work:
  comic_id: "yamibo:100"
  source_tid: "100"              ← 最初收藏的帖子
  episodes:
    - ep1: source_tid="100"       ← 来自帖子 100
    - ep2: source_tid="100"       ← 来自帖子 100
    - ep3: source_tid="200"       ← 合并自帖子 200
    - ep4: source_tid="300"       ← 合并自帖子 300
```

### 2.2 什么是"完全解析"

```
完全解析的漫画 = 满足以下任一条件：
  a) 有 catalogUrl（有目录页，可以完整发现所有章节）
  b) 通过搜索策略（search strategy）完成了解析
  c) 有 >= directEnoughThreshold 个直接链接（默认 3 个）
  d) 已通过 recursive 策略获得更多章节
```

不完全解析的漫画 = 只有直接链接且少于阈值，没有目录，也没有搜索过。

```dart
/// 重复检测结果
enum DeduplicationAction {
  /// 无重复，正常创建新作品
  none,

  /// 新的被已有的吸收（场景 1：全部 tid 已包含）
  absorbNew,

  /// 把新的合并进已有的（场景 2、3：部分 tid 重复）
  mergeIntoExisting,
}

class ComicDeduplicationResult {
  const ComicDeduplicationResult({
    required this.action,
    this.existingComicId,     // 已有的漫画 ID
    this.overlappingTids,     // 重复的 tid
    this.newOnlyTids,         // 只在新的中出现的 tid
    this.existingOnlyTids,    // 只在已有的中出现的 tid
  });

  final DeduplicationAction action;
  final String? existingComicId;
  final Set<String>? overlappingTids;
  final Set<String>? newOnlyTids;
  final Set<String>? existingOnlyTids;

  static const none = ComicDeduplicationResult(action: DeduplicationAction.none);

  bool get hasDuplicate => action != DeduplicationAction.none;
}

class MergeResult {
  const MergeResult({
    required this.keptComicId,
    required this.absorbedComicId,
    required this.addedEpisodeCount,
    required this.mergedTids,
  });

  final String keptComicId;
  final String absorbedComicId;
  final int addedEpisodeCount;
  final List<String> mergedTids;
}
```

### 4.2 重复检测服务

**新文件：`lib/features/comic/domain/services/comic_deduplication_service.dart`**

```dart
class ComicDeduplicationService {
  ComicDeduplicationService({
    required ComicRepository comicRepository,
  }) : _comicRepository = comicRepository;

  final ComicRepository _comicRepository;

  /// 检测给定的一组 tid 是否与已有的漫画重复
  ///
  /// [sourceTid] 新帖子的主 tid
  /// [episodeTids] 新帖子中发现的全部章节 tid（含 sourceTid）
  ///
  /// 遍历漫画书架中所有作品，比较 tid 集合。
  Future<ComicDeduplicationResult> detectDuplicate({
    required String sourceTid,
    required Set<String> episodeTids,
    required bool isExistingFullyParsed,
  }) async {
    // 收集所有书架中的漫画及其 tid 集合
    final allComics = await _comicRepository.getShelfItems();
    final candidateTids = {sourceTid, ...episodeTids};

    for (final comic in allComics) {
      // 跳过自身
      if (comic.comicId == buildComicWorkId(sourceTid)) continue;

      // 获取该漫画的所有 tid（source_tid + 每章的 source_tid）
      final existingTids = await _getAllTidsForComic(comic.comicId);
      final existingIsFullyParsed = await _isFullyParsed(comic.comicId);

      // 计算交集
      final overlapping = existingTids.intersection(candidateTids);
      if (overlapping.isEmpty) continue;

      final newOnly = candidateTids.difference(existingTids);
      final existingOnly = existingTids.difference(candidateTids);

      if (newOnly.isEmpty && existingIsFullyParsed) {
        // 场景 1：新的全部被已有的包含，且已有的已经充分解析
        return ComicDeduplicationResult(
          action: DeduplicationAction.absorbNew,
          existingComicId: comic.comicId,
          overlappingTids: overlapping,
          newOnlyTids: const <String>{},
          existingOnlyTids: existingOnly,
        );
      }

      if (newOnly.isNotEmpty) {
        // 场景 2/3：部分重叠，把新的合并到已有的
        return ComicDeduplicationResult(
          action: DeduplicationAction.mergeIntoExisting,
          existingComicId: comic.comicId,
          overlappingTids: overlapping,
          newOnlyTids: newOnly,
          existingOnlyTids: existingOnly,
        );
      }

      // 场景 1 但已有的还没充分解析 → 用新的替换已有的？
      // 保守策略：如果已有的还没充分解析且新的是充分解析的，
      // 用新的吸收已有的
      if (isExistingFullyParsed && !existingIsFullyParsed) {
        return ComicDeduplicationResult(
          action: DeduplicationAction.absorbNew,
          existingComicId: comic.comicId,
          overlappingTids: overlapping,
        );
      }
    }

    return ComicDeduplicationResult.none;
  }

  /// 获取一个漫画包含的全部 tid
  ///
  /// = source_tid + 所有章节的 source_tid
  Future<Set<String>> _getAllTidsForComic(String comicId) async {
    final detail = await _comicRepository.getComicDetail(comicId: comicId);
    if (detail == null) return <String>{};

    final tids = <String>{detail.sourceTid};
    final episodes = await _comicRepository.getComicEpisodes(
      comicId: comicId,
    );
    for (final ep in episodes) {
      tids.add(ep.sourceTid);
    }
    return tids;
  }

  /// 判断一个漫画是否已完全解析
  Future<bool> _isFullyParsed(String comicId) async {
    final detail = await _comicRepository.getComicDetail(comicId: comicId);
    if (detail == null) return false;

    // 有目录 → 完全解析
    if (detail.catalogUrl != null && detail.catalogUrl!.trim().isNotEmpty) {
      return true;
    }

    // 通过搜索策略解析过 → 完全解析
    if (detail.discoveryStrategy == EpisodeDiscoveryStrategy.search.name ||
        detail.discoveryStrategy == EpisodeDiscoveryStrategy.catalog.name) {
      return true;
    }

    // 章节数 >= 阈值 → 视为充分
    final episodes = await _comicRepository.getComicEpisodes(comicId: comicId);
    if (episodes.length >= 3) return true; // directEnoughThreshold

    return false;
  }

  /// 合并两个漫画
  ///
  /// [keepComicId] 保留的漫画（已有的）
  /// [absorbComicId] 被吸收的漫画（新的）
  /// [newOnlyTids] 只在新的中存在的 tid → 作为新章节加入保留的漫画
  Future<MergeResult> mergeComics({
    required String keepComicId,
    required String absorbComicId,
    required Set<String> newOnlyTids,
  }) async {
    // 1. 获取被吸收漫画的章节
    final absorbEpisodes = await _comicRepository.getComicEpisodes(
      comicId: absorbComicId,
    );

    // 2. 只保留 newOnlyTids 中的章节
    final episodesToAdd = absorbEpisodes
        .where((ep) => newOnlyTids.contains(ep.sourceTid))
        .toList();

    // 3. 把这些章节加入到保留的漫画
    for (final episode in episodesToAdd) {
      await _comicRepository.addEpisodeToComic(
        comicId: keepComicId,
        episode: episode,
      );
    }

    // 4. 从书架移除被吸收的漫画
    await _comicRepository.removeFromShelf(comicId: absorbComicId);

    // 5. 发射 ComicRemoved 事件（阶段 4）
    _eventBus.fire(ComicRemoved(
      comicId: absorbComicId,
      reason: 'duplicate_merged',
    ));

    return MergeResult(
      keptComicId: keepComicId,
      absorbedComicId: absorbComicId,
      addedEpisodeCount: episodesToAdd.length,
      mergedTids: newOnlyTids.toList(),
    );
  }
}
```

### 4.4 场景 1 详解：首次使用 App

```
用户有 3 条收藏：
  A(tid=100): "某某漫画 第1-5话" → 解析后有目录 → 完全解析
  B(tid=200): "某某漫画 第6话"   → 解析后只有 1 个直接链接
  C(tid=300): "yyy漫画 第1话"    → 独立漫画

处理顺序（按 remote_order ASC，即收藏时间最近在前）：

1. 解析 A(tid=100)
   - 去重检测：书架为空 → 无重复
   - 创建漫画 yamibo:100，包含 tid: {100} + episodes

2. 解析 B(tid=200)
   - 去重检测：yamibo:100 包含 tid=200 吗？
     - _getAllTidsForComic('yamibo:100') → {100, 100-1, 100-2, ...}
     - 如果 A 的章节中有一个章节的 source_tid=200 → 重叠！
   - 假设重叠：200 在 A 中，B 没有新 tid
     → action = absorbNew
     → 不创建 yamibo:200，返回 yamibo:100
     → 发射 ComicRemoved 事件

3. 解析 C(tid=300)
   - 去重检测：yamibo:100 不包含 300
   - 无重复 → 正常创建 yamibo:300
```

### 4.5 场景 2 详解：新收藏帖子

```
已有漫画 yamibo:100 (tid 集合: {100, 200})
用户在论坛收藏了 tid=500 的帖子 "某某漫画 第10话"

流程：
1. ForumFavoriteAdded 事件发射
2. FavoriteSyncService 增量同步
3. 解析 tid=500
   - 去重检测：yamibo:100 的 tid 集合 {100, 200} ∩ {500} = ∅
   - 但标题匹配！用 ComicSubjectParser 提取 normalizedTitle：
     "某某漫画" == "某某漫画" → 需要进一步检测
   - 查看 500 的 episodelinks 是否包含 100 或 200
     - episodelinks 里可能有 "上一话" 链接到 tid=200
     - 发现 200 在 yamibo:100 中
   → action = mergeIntoExisting
   → 保留 yamibo:100（可能有自定义标题等）
   → 将 500 的章节合并到 yamibo:100
   → 从书架移除 yamibo:500
```

### 4.6 场景 3 详解：自定义标题触发

```
用户自定义了漫画标题后，触发 ComicMetadataUpdated 事件。
在事件处理中：

1. 用新标题重新搜索
2. 搜索结果的 episodelinks 可能包含已有漫画的 tid
3. 执行去重检测 → mergeIntoExisting
4. 保留已有漫画（有自定义标题），吸收新的 tid
```

### 4.8 性能优化

在大量收藏的场景下（例如 100+ 个漫画），每次摄入都遍历所有已有漫画会很慢。

优化策略：
1. **基于 fid+typeid 索引**：同一版块同一分类的帖子才可能是同一漫画
2. **基于 normalizedTitle 索引**：同名的才需要进一步检测
3. **两级检测**：
   - Level 1（快速）：基于 normalizedTitle + fid 过滤候选集
   - Level 2（精确）：只有 Level 1 通过后才比较 tid 集合

```dart
Future<ComicDeduplicationResult> detectDuplicate({...}) async {
  // Level 1: 快速过滤
  final candidates = await _comicRepository.findCandidatesByTitleFid(
    normalizedTitle: _subjectParser.parse(detail.subject).normalizedTitle,
    fid: detail.fid,
  );

  if (candidates.isEmpty) {
    return ComicDeduplicationResult.none;
  }

  // Level 2: 精确 tid 比较
  for (final candidate in candidates) {
    final existingTids = await _getAllTidsForComicFast(candidate.comicId);
    final overlapping = existingTids.intersection(candidateTids);
    if (overlapping.isNotEmpty) {
      // ... 执行去重逻辑
    }
  }

  return ComicDeduplicationResult.none;
}
```
