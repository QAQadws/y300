# 阶段 2：漫画后台章节补全与搜索队列

**预计时间：10–14 小时**（原 6–8h + 本次新增 4–6h）

## 1. 问题分析

### 1.1 两类需要补全的漫画

阶段 1 的轻量摄入只提取了帖子正文中的直接 episodelinks。但一部漫画可能：

| 类型 | 特征 | 需要的补全策略 | 限速 |
|------|------|---------------|------|
| **有目录** | `catalogUrl` 非空 | 爬取目录页 HTML，解析全部章节链接 | 无（普通 HTTP） |
| **長篇連載 + 无目录** | `catalogUrl` 为空 且 tag 含"長篇連載" | 通过 Discuz 搜索 API 用标题搜索章节 | 10s/次 |

### 1.2 场景

```
用户首次打开 App，收藏同步完成后：
- 漫画 A：有目录（catalogUrl = "forum.php?mod=tag&type=thread&..."）
  → 应自动、静默地爬取目录页，获取完整章节列表
  → 不应阻塞阶段 1 的快速分类和渐进摄入

- 漫画 B：長篇連載，无目录，只有一个"第10话"跳转链接
  → 加入搜索队列，每 10.5s 用标题搜索一次
  → 搜索完成后合并发现的章节

- 漫画 C：普通漫画，有 >= 3 个直接 episodelinks
  → 直接链接足够，不需要后台补全
```

搜索 API 限制：`SearchRateLimiter` 规定每次搜索间隔 ≥ 10 秒。

### 1.3 当前缺陷

- 首次使用 App 的用户会看到部分漫画"没有完整章节"
- 有目录的漫画也只在用户手动打开详情页刷新时才补全
- 没有后台自动补全机制
- 没有向用户展示补全进度

### 1.4 需要实现的行为

1. 渐进摄入完成后，对有目录的漫画**立即、并发、静默**爬取目录页 → 合并章节
2. 对長篇連載 + 无目录的漫画加入搜索队列，每 10.5s 处理一个
3. 队列持久化（App 退出后恢复）
4. 显示队列状态：还有 N 部漫画未完全解析，预计 X 秒完成
5. 动态调整预计时间（合并机制会减少队列长度）
6. 目录爬取不阻塞、搜索队列也不阻塞——两者都在后台运行

/// 队列整体状态，供 UI 展示
class DeepParseQueueStatus {
  const DeepParseQueueStatus({
    required this.totalPending,
    this.catalogPending = 0,
    this.searchPending = 0,
    this.currentlyProcessing,
    this.estimatedSecondsRemaining,
  });

  /// 所有待处理任务数（catalog + search）
  final int totalPending;

  /// 待处理的目录爬取任务数
  final int catalogPending;

  /// 待处理的搜索任务数
  final int searchPending;

  final String? currentlyProcessing;
  final int? estimatedSecondsRemaining;

  bool get isActive => totalPending > 0 || currentlyProcessing != null;

  String formatEstimatedTime() {
    if (estimatedSecondsRemaining == null) return '计算中...';
    if (estimatedSecondsRemaining! <= 0) return '即将完成';
    final minutes = estimatedSecondsRemaining! ~/ 60;
    final seconds = estimatedSecondsRemaining! % 60;
    if (minutes > 0) return '约 $minutes 分 $seconds 秒';
    return '约 $seconds 秒';
  }

  /// 人类可读的阶段描述
  String get phaseLabel {
    if (catalogPending > 0) return '正在获取目录章节 ($catalogPending 部)';
    if (searchPending > 0) return '正在搜索补全章节 ($searchPending 部)';
    return '即将完成';
  }
}

### 3.4a 阶段 2a：有目录漫画后台静默爬取

**设计原则**：目录爬取是普通的 HTTP GET 请求（爬 HTML 页面），不受搜索 API 的 10s 限速。因此可以在渐进摄入完成后**立即并发启动**，快速补全所有有目录的漫画。

#### 3.4a.1 入队时机

在阶段 1 的 `_progressiveIngest()` 完成时（或与渐进摄入并行），扫描所有 `processingLevel = 'full'` 且 `catalogUrl` 非空的漫画，将它们加入目录爬取队列。

#### 3.4a.2 目录爬取流程

```
_progressiveIngest() 完成
  │
  ▼
_enqueueCatalogTasks()
  │ 扫描所有 processingLevel=full + catalogUrl 非空的漫画
  │ 以 strategy=catalog 入队
  ▼
_processCatalogBatch()
  │ 从队列取出所有 strategy=catalog 的任务
  │ 对每个任务：
  │   ├─ CatalogHtmlFetcher.fetchHtml(catalogUrl)
  │   ├─ CatalogThreadHtmlParser.parse(html) → entries[]
  │   ├─ ComicRepository.mergeEpisodesFromLinks(episodeLinks=entries)
  │   └─ queue.remove(comicId)
  │
  │ 所有 catalog 任务完成后：
  ▼
emit 进度 → UI 横幅更新
  │
  ▼
_scheduleSearchLoop()  ← 启动搜索队列的 10.5s 定时循环
```

#### 3.4a.3 目录爬取与分类获取不阻塞

关键设计点：
- 目录爬取在 `_progressiveIngest()` 完成**之后**启动（不阻塞阶段 1 的快速分类和渐进摄入）
- 目录爬取使用 **`Future.wait` 或受控并发**（例如最多 2 个并发），比逐个处理快得多
- 每完成一个目录爬取就发出进度，UI 横幅实时更新
- コ目录爬取失败不阻塞搜索队列启动

```dart
/// 并发爬取目录，最多 [maxConcurrent] 个并发。
Future<void> _processCatalogBatch({int maxConcurrent = 2}) async {
  // 一次性取出所有 catalog 任务
  final tasks = await _repository.dequeueAllByStrategy(DeepParseStrategy.catalog);
  if (tasks.isEmpty) return;

  final total = tasks.length;
  var completed = 0;

  // 用 chunked 并发控制
  for (var i = 0; i < tasks.length; i += maxConcurrent) {
    final chunk = tasks.skip(i).take(maxConcurrent);
    await Future.wait(chunk.map((task) async {
      try {
        if (task.catalogUrl == null) {
          await _repository.remove(task.comicId);
          return;
        }

        final html = await _catalogHtmlFetcher.fetchHtml(task.catalogUrl!);
        if (html == null || html.isEmpty) {
          await _repository.remove(task.comicId);
          return;
        }

        final parsed = _catalogThreadHtmlParser.parse(html: html, pageUrl: task.catalogUrl!);
        if (parsed.entries.isNotEmpty) {
          await _comicRepository.mergeEpisodesFromLinks(
            comicId: task.comicId,
            episodeLinks: parsed.entries.map((e) => ComicEpisodeLink(
              url: e.url,
              rawText: e.subject,
              episodeTitle: e.subject,
            )).toList(),
            fallbackSourceTid: task.sourceTid,
          );
        }

        await _repository.remove(task.comicId);
        completed++;
        await _updateStatus();
      } catch (_) {
        // 目录爬取失败不重试，直接移除
        await _repository.remove(task.comicId);
        completed++;
        await _updateStatus();
      }
    }));
  }
}
```

### 3.5 调度器

**新文件：`lib/features/comic/domain/services/comic_deep_parse_scheduler.dart`**

调度器统一管理两种补全策略：

```
start()
  │
  ├─ 1. _processCatalogBatch()   ← 先并发爬取所有有目录的漫画（不限速）
  │     完成后 emit 进度
  │
  └─ 2. _scheduleSearchLoop()    ← 再启动搜索定时器（10.5s/次）
        逐个处理長篇連載 + 无目录的漫画
```

```dart
class ComicDeepParseScheduler {
  ComicDeepParseScheduler({
    required ComicDeepParseQueueRepository repository,
    required SearchRateLimiter rateLimiter,
    required ComicEpisodeDiscoveryService discoveryService,
    required CatalogHtmlFetcher catalogHtmlFetcher,
    required CatalogThreadHtmlParser catalogThreadHtmlParser,
    required ComicRepository comicRepository,
    int catalogMaxConcurrent = 2,
  });

  final ComicDeepParseQueueRepository _repository;
  final SearchRateLimiter _rateLimiter;
  final ComicEpisodeDiscoveryService _discoveryService;
  final CatalogHtmlFetcher _catalogHtmlFetcher;
  final CatalogThreadHtmlParser _catalogThreadHtmlParser;
  final ComicRepository _comicRepository;
  final int _catalogMaxConcurrent;

  static const Duration searchInterval = Duration(milliseconds: 10500);

  final ValueNotifier<DeepParseQueueStatus> status =
      ValueNotifier(const DeepParseQueueStatus(totalPending: 0));

  Timer? _timer;
  bool _running = false;

  /// 启动调度：
  /// 1. 先并发爬取所有有目录的漫画（不限速）
  /// 2. 再启动搜索定时器处理搜索队列
  Future<void> start() async {
    if (_running) return;
    _running = true;

    // 阶段 2a：目录爬取（不限速，并发执行）
    await _processCatalogBatch();

    // 阶段 2b：搜索队列（10.5s 间隔）
    _scheduleSearchLoop();
  }

  void pause() {
    _running = false;
    _timer?.cancel();
    _timer = null;
  }

  void resume() {
    if (_running) return;
    _running = true;
    _scheduleSearchLoop();
  }

  void dispose() {
    pause();
    status.dispose();
  }

  // === 阶段 2a：目录爬取（不限速，并发）===

  Future<void> _processCatalogBatch() async {
    final tasks = await _repository.dequeueAllByStrategy(DeepParseStrategy.catalog);
    if (tasks.isEmpty) return;

    final total = tasks.length;
    var completed = 0;
    await _updateStatus();

    for (var i = 0; i < tasks.length; i += _catalogMaxConcurrent) {
      final chunk = tasks.skip(i).take(_catalogMaxConcurrent);
      await Future.wait(chunk.map((task) => _processCatalogTask(task).then((_) {
        completed++;
      })));
      await _updateStatus();
    }
  }

  Future<void> _processCatalogTask(ComicDeepParseTask task) async {
    try {
      if (task.catalogUrl == null || task.catalogUrl!.isEmpty) {
        await _repository.remove(task.comicId);
        return;
      }

      final html = await _catalogHtmlFetcher.fetchHtml(task.catalogUrl!);
      if (html == null || html.isEmpty) {
        await _repository.remove(task.comicId);
        return;
      }

      final parsed = _catalogThreadHtmlParser.parse(
        html: html,
        pageUrl: task.catalogUrl!,
      );

      if (parsed.entries.isNotEmpty) {
        await _comicRepository.mergeEpisodesFromLinks(
          comicId: task.comicId,
          episodeLinks: parsed.entries.map((e) => ComicEpisodeLink(
            url: e.url,
            rawText: e.subject.isEmpty ? '目录条目' : e.subject,
            episodeTitle: e.subject.isEmpty ? null : e.subject,
          )).toList(),
          fallbackSourceTid: task.sourceTid,
        );
      }

      // 目录获取成功后，将该漫画标记为 full（已完全解析）
      await _comicRepository.markProcessingLevel(
        comicId: task.comicId,
        processingLevel: 'full',
      );
      await _repository.remove(task.comicId);
    } catch (_) {
      // 目录爬取失败：删除任务，保留现有章节
      await _repository.remove(task.comicId);
    }
  }

  // === 阶段 2b：搜索队列（10.5s 间隔）===

  void _scheduleSearchLoop() {
    if (!_running) return;
    _timer?.cancel();
    _timer = Timer(searchInterval, _processSearchTick);
  }

  Future<void> _processSearchTick() async {
    if (!_running) return;

    await _updateStatus();

    // 取下一个搜索任务
    final task = await _repository.dequeueByStrategy(DeepParseStrategy.search);
    if (task == null) {
      await _updateStatus();
      return; // 搜索队列为空，停止循环
    }

    // 限流检查
    final limitResult = await _rateLimiter.check();
    if (limitResult is SearchRateLimitBlocked) {
      await Future.delayed(limitResult.remaining);
    }

    try {
      await _processSearchTask(task);
      await _rateLimiter.markTriggered();
    } catch (e) {
      await _repository.updateAttempt(
        task.comicId,
        success: false,
        error: '$e',
      );
    }

    await _updateStatus();
    _scheduleSearchLoop();
  }

  Future<void> _processSearchTask(ComicDeepParseTask task) async {
    final comic = await _comicRepository.getComicDetail(comicId: task.comicId);
    final searchTitle = comic?.customSearchTitle ?? task.title;

    final discoveryResult = await _discoveryService.discoverBySearch(
      tid: task.sourceTid,
      searchTitle: searchTitle,
    );

    await _comicRepository.mergeEpisodesFromLinks(
      comicId: task.comicId,
      episodeLinks: discoveryResult.episodeLinks,
      fallbackSourceTid: task.sourceTid,
    );

    // 搜索成功后标记为 full
    await _comicRepository.markProcessingLevel(
      comicId: task.comicId,
      processingLevel: 'full',
    );
    await _repository.remove(task.comicId);
  }

  // === 状态更新 ===

  Future<void> _updateStatus() async {
    final catalogCount = await _repository.countByStrategy(DeepParseStrategy.catalog);
    final searchCount = await _repository.countByStrategy(DeepParseStrategy.search);
    status.value = DeepParseQueueStatus(
      totalPending: catalogCount + searchCount,
      catalogPending: catalogCount,
      searchPending: searchCount,
      estimatedSecondsRemaining: catalogCount > 0
          ? (catalogCount * 3).ceil()  // 目录爬取约 3s/个（HTTP 请求）
          : searchCount > 0
              ? (searchCount * searchInterval.inSeconds).ceil()
              : null,
    );
  }
}

        sourceTid: detail.tid,
        strategy: DeepParseStrategy.catalog,
        catalogUrl: parsed.catalogUrl!,
        sourceTagName: sourceTagName ?? '',
        enqueuedAt: DateTime.now(),
        priority: DeepParsePriority.backlog,
      ),
    );
  } else if (isLongSerial) {
    // 長篇連載 + 无目录 → 加入**搜索**队列（受 10.5s 限速）
    await _deepParseQueueRepository.enqueue(
      ComicDeepParseTask(
        comicId: comicId,
        title: detail.subject,
        sourceTid: detail.tid,
        strategy: DeepParseStrategy.search,
        sourceTagName: sourceTagName ?? '',
        enqueuedAt: DateTime.now(),
        priority: DeepParsePriority.backlog,
      ),
    );
  }
  // 有 ≥ 3 个直接 episodelinks 或有目录 → processingLevel: 'full'，不需要队列

  return comicId;
}
```

**入队决策表**：

| 条件 | processingLevel | 入队策略 | 说明 |
|------|----------------|---------|------|
| 有 catalogUrl | light | catalog | 后台爬取目录页，完成后升级为 full |
| 長篇連載 + 无 catalog | light | search | 10.5s 搜索队列 |
| 有 >= 3 个直接链接 | full | 不入队 | 直接链接已足够 |
| 其他（普通帖） | full | 不入队 | 不需要补全 |

## 4. 数据流

```
FavoriteSyncService._progressiveIngest() 完成
  │
  ├─ lightUpsert(comic) → 有目录?
  │   YES → enqueue(strategy: catalog)      ← 目录爬取队列（无速率限制）
  │   長篇連載 + 无目录?
  │   YES → enqueue(strategy: search)       ← 搜索队列（10.5s 限速）
  │   有 ≥ 3 个 episodelinks?
  │   → processingLevel: full，不入队       ← 直接完成
  │
  ▼
ComicDeepParseQueue (SQLite persists)
  │
  ▼
ComicDeepParseScheduler.start()
  │
  ├─ 阶段 2a：_processCatalogBatch()
  │   从队列取出所有 strategy=catalog 的任务
  │   并发爬取目录页（HTTP GET，不限速）
  │   对每个任务：
  │     ├─ CatalogHtmlFetcher.fetchHtml(catalogUrl)
  │     ├─ CatalogThreadHtmlParser.parse(html) → entries[]
  │     ├─ ComicRepository.mergeEpisodesFromLinks(episodeLinks=entries)
  │     ├─ ComicRepository.markProcessingLevel('full')
  │     └─ queue.remove(comicId)
  │   目录爬取全部完成后 emit 进度
  │
  └─ 阶段 2b：_scheduleSearchLoop()
      每 10.5s:
        ├─ dequeueByStrategy(search) → task
        ├─ SearchRateLimiter.check() → wait if needed
        ├─ SearchService.search(title)
        ├─ ComicEpisodeDiscoveryService.discoverBySearch()
        ├─ ComicRepository.mergeEpisodesFromLinks()
        ├─ ComicRepository.markProcessingLevel('full')
        ├─ queue.remove(comicId)
        ├─ updateStatus() → notify UI
        └─ scheduleNext()
```

## 5. 合并机制对预计时间的影响

当队列中存在属于同一漫画的多个帖子时，合并机制会：
1. 检测到重复（阶段 5）
2. 合并重复漫画，只保留一个
3. 从队列中移除多余的待处理项

调度器每次 `_updateStatus()` 时从仓储重新 `count()`，所以预计时间会**自动动态调整**。
