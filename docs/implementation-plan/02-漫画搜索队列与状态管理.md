# 阶段 2：漫画搜索队列与状态管理

**预计时间：6–8 小时**

## 1. 问题分析

### 1.1 场景

```
用户收藏了 N 个漫画帖子，其中一部分是"長篇連載"标签。
对于这些漫画：
- 帖子本身只是一个章节的跳转链接（例如"第10话"）
- 没有"目录"页（catalogUrl 为 null）
- 需要通过 Discuz 搜索 API 用漫画标题搜索来发现完整章节列表
```

搜索 API 限制：`SearchRateLimiter` 规定每次搜索间隔 ≥ 10 秒。

### 1.2 当前缺陷

- `ComicEpisodeDiscoveryService` 在摄入时同步执行目录发现
- 如果 5 个漫画都需要搜索，按 10s 间隔 = 50s+
- 首次打开 App 的用户会看到部分漫画"没有完整章节"
- 没有"稍后处理"队列
- 没有向用户展示进度

### 1.3 需要实现的行为

1. 轻量摄入时，将"長篇連載 + 无目录 + 只有直接链接"的漫画加入队列
2. 队列按每 10.5s 处理一个漫画
3. 队列持久化（App 退出后恢复）
4. 显示队列状态：还有 N 部漫画未完全解析，预计 X 秒完成
5. 动态调整预计时间（合并机制会减少队列长度）

```dart
  const ComicDeepParseTask({
    required this.comicId,
    required this.title,
    required this.sourceTid,
    required this.sourceTagName,
    required this.enqueuedAt,
    required this.priority,
    this.attemptCount = 0,
    this.lastAttemptAt,
    this.lastError,
  });

  final String comicId;
  final String title;
  final String sourceTid;
  final String sourceTagName;
  final DateTime enqueuedAt;
  final DeepParsePriority priority;
  final int attemptCount;
  final DateTime? lastAttemptAt;
  final String? lastError;

  ComicDeepParseTask copyWith({...});

/// 队列整体状态，供 UI 展示
class DeepParseQueueStatus {
  const DeepParseQueueStatus({
    required this.totalPending,
    required this.currentlyProcessing,
    this.estimatedSecondsRemaining,
  });

  final int totalPending;
  final String? currentlyProcessing; // comicId 或 title
  final int? estimatedSecondsRemaining;

  bool get isActive => totalPending > 0 || currentlyProcessing != null;

  String formatEstimatedTime() {
    if (estimatedSecondsRemaining == null) return '计算中...';
    if (estimatedSecondsRemaining! <= 0) return '即将完成';
    final minutes = estimatedSecondsRemaining! ~/ 60;
    final seconds = estimatedSecondsRemaining! % 60;
    if (minutes > 0) return '约 $minutes 分 $seconds 秒';
    return '约 $seconds 秒';
  }
}
```

### 3.5 调度器

**新文件：`lib/features/comic/domain/services/comic_deep_parse_scheduler.dart`**

```dart
class ComicDeepParseScheduler {
  ComicDeepParseScheduler({
    required ComicDeepParseQueueRepository repository,
    required SearchRateLimiter rateLimiter,
    required ComicEpisodeDiscoveryService discoveryService,
    required ComicRepository comicRepository,
  });

  final ComicDeepParseQueueRepository _repository;
  final SearchRateLimiter _rateLimiter;
  final ComicEpisodeDiscoveryService _discoveryService;
  final ComicRepository _comicRepository;

  final ValueNotifier<DeepParseQueueStatus> status =
      ValueNotifier(const DeepParseQueueStatus(totalPending: 0));

  Timer? _timer;
  bool _running = false;

  /// 启动调度循环
  ///
  /// 每 10.5s 执行一次：
  /// 1. 从队列取下一个任务
  /// 2. 检查搜索限流
  /// 3. 用漫画标题搜索 → 发现章节
  /// 4. 将发现的章节合并到漫画
  /// 5. 从队列移除
  /// 6. 更新状态
  void start() {
    if (_running) return;
    _running = true;
    _scheduleNext();
  }

  void pause() {
    _running = false;
    _timer?.cancel();
    _timer = null;
  }

  void resume() {
    if (_running) return;
    _running = true;
    _scheduleNext();
  }

  void dispose() {
    pause();
    status.dispose();
  }

  Future<void> _scheduleNext() async {
    if (!_running) return;

    // 更新状态
    await _updateStatus();

    // 取下一个任务
    final task = await _repository.dequeue();
    if (task == null) {
      // 队列为空
      await _updateStatus();
      return;
    }

    // 限流检查
    final limitResult = await _rateLimiter.check();
    if (limitResult is SearchRateLimitBlocked) {
      // 需要等待剩余时间
      await Future.delayed(limitResult.remaining);
    }

    // 执行搜索
    try {
      await _processTask(task);
      await _rateLimiter.markTriggered();
    } catch (e) {
      // 记录失败，重试次数 +1
      await _repository.updateAttempt(
        task.comicId,
        success: false,
        error: '$e',
      );
    }

    // 下次执行
    await _updateStatus();
    _timer = Timer(searchInterval, _scheduleNext);
  }

  Future<void> _processTask(ComicDeepParseTask task) async {
    // 1. 用自定义搜索标题或原始标题进行搜索
    final comic = await _comicRepository.getComicDetail(comicId: task.comicId);
    final searchTitle = comic?.customSearchTitle ?? task.title;

    // 2. 通过 EpisodeDiscoveryService 的 "搜索优先" 策略发现章节
    // （需要在 ComicEpisodeDiscoveryService 中新增 search-based 策略）
    final discoveryResult = await _discoveryService.discoverBySearch(
      tid: task.sourceTid,
      searchTitle: searchTitle,
    );

    // 3. 合并章节到漫画
    await _comicRepository.mergeEpisodesFromLinks(
      comicId: task.comicId,
      episodeLinks: discoveryResult.episodeLinks,
      fallbackSourceTid: task.sourceTid,
    );

    // 4. 标记完成
    await _repository.remove(task.comicId);
  }

  Future<void> _updateStatus() async {
    final count = await _repository.count();
    status.value = DeepParseQueueStatus(
      totalPending: count,
      estimatedSecondsRemaining: count > 0
          ? (count * searchInterval.inSeconds).ceil()
          : null,
    );
  }

  /// 动态重新计算预计时间
  ///
  /// 当合并机制触发时（一个有多个帖子的漫画可能只产生一个任务），
  /// 队列会自动缩短，预计时间随之动态减少。
  Future<int> recalculateEstimatedSeconds() async {
    final count = await _repository.count();
    return (count * searchInterval.inSeconds).ceil();
  }
}
```

## 4. 数据流

```
FavoriteSyncService
  └─ lightUpsert(comic) → 是長篇連載 + 无目录?
      │                      YES → enqueue(task)
      │                      NO  → done
      ▼
ComicDeepParseQueue (SQLite persists)
  │
  ▼
ComicDeepParseScheduler.start()
  │  every 10.5s
  ├─ dequeue() → task
  ├─ SearchRateLimiter.check()
  ├─ SearchService.search(title)
  ├─ ComicEpisodeDiscoveryService.discoverBySearch()
  ├─ ComicRepository.mergeEpisodesFromLinks()
  ├─ queue.remove(comicId)
  ├─ updateStatus() → notify UI
  └─ scheduleNext()
```

## 5. 合并机制对预计时间的影响

当队列中存在属于同一漫画的多个帖子时，合并机制会：
1. 检测到重复（阶段 5）
2. 合并重复漫画，只保留一个
3. 从队列中移除多余的待处理项

调度器每次 `_updateStatus()` 时从仓储重新 `count()`，所以预计时间会**自动动态调整**。
