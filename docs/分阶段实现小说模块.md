# 分阶段实现小说模块

## 0. 文档目标

本文档用于指导在当前项目中落地“小说模块”，并确保方案：

1. 与现有漫画模块架构保持一致（低耦合、可维护、可测试）。
2. 支持新开 `小说 Tab`。
3. 覆盖 `fid=49`（文学区）与 `fid=55`（轻小说/译文区）。
4. 以“楼主 + pid + tid + page”为核心解析对象。
5. 兼顾两类作品展示：有封面轻小说 / 无封面原创小说。

---

## 1. 范围与原则

### 1.1 本期范围

1. 新增小说 Tab 页面与基础导航。
2. 小说入库、书架展示、详情页、阅读器。
3. 小说章节解析（优先链接法，失败后回退分页法）。
4. 小说更新（不依赖搜索，直接基于同帖多楼/多页解析）。

### 1.2 不在本期

1. 跨站源采集。
2. EPUB/TXT 外部导入。
3. AI 摘要/内容纠错。

### 1.3 实现原则

1. **先最小闭环**：先跑通“发现-入库-阅读-更新”。
2. **强复用**：优先复用漫画模块已有基础设施（DB、仓储、状态、页面骨架）。
3. **强解耦**：解析、存储、阅读器交互、UI 展示分层清晰。
4. **可观测**：保留解析日志与调试信号，便于后续修复样本。

---

## 2. 业务理解与关键约束

### 2.1 论坛区约束

1. 文学区：`fid=49`
2. 轻小说/译文区：`fid=55`

### 2.2 内容组织约束

1. 小说更新通常在同一 `tid` 内持续追加楼层。
2. 章节定位重点：`author(楼主)`、`pid`、`tid`、`page`。
3. 章节目录可能存在于楼主前几楼，形式包括：
- 连续跳转链接
- 文本为数字/章话节
- 非规则标题若连续可判定为跳转
4. 兜底用 `viewthread` 多 `page` 的 JSON 回退解析。

### 2.3 与漫画差异

1. 漫画常跨帖跳转，小说多在单帖内更新。
2. 小说更新优先同帖解析，不需要搜索兜底。
3. 小说阅读器核心是文本排版，而非图片翻页。

## 6. 核心解析策略（重点）

## 6.1 输入对象

每次解析应至少持有：

1. `tid`
2. `fid`
3. `subject`
4. `postlist`（含 `pid/author/authorid/message/dateline/number`）
5. 当前 `page`

## 6.2 策略一：目录链接优先（Primary）

从楼主前几楼（建议前 1~5 楼）提取章节跳转候选：

1. 锚点 URL 识别：
- `thread-xxx-1-1.html`
- `forum.php?mod=viewthread&tid=xxx`
- 异常 `;tid=xxx`

2. 文本特征识别：
- 纯数字：`1/01/001`
- 章节词：`第x章/第x话/第x节/番外/后记/序章`
- 连续链接簇（按 DOM 顺序连续出现）

3. 判定规则：
- 命中章节词 + 可提取 tid/pid 优先
- 连续链接簇整体升权
- 非规则文本但位于簇中可保留

4. 去重主键：
- 同帖章节以 `pid` 优先去重
- 若无 pid，退化到 `tid+title`

## 6.3 策略二：同帖分页回退（Fallback）

当策略一章节不足时：

1. 遍历 `viewthread` 分页（page=1..N）
2. 仅保留“楼主”楼层（authorId 与 1楼一致）
3. 识别章节切分信号：
- 标题样文本（第x章/话/节）
- 明显分隔符（例如“——”“= = =”）
- 长文本中开头短句+数字模式
4. 每个章节绑定：
- `sourcePid`
- `sourcePage`
- `sourceTid`

## 6.4 章节内容抽取

从 `message` 做文本化：

1. 清理无关标签（quote/attach icon/编辑痕迹）。
2. 保留换行与段落。
3. 处理 `&nbsp;`、多空格、HTML 实体。
4. 产出：`plainText + paragraphs[]`。

## 6.5 封面提取策略

`NovelCoverExtractor` 建议：

1. 在楼主前几楼找首张有效大图。
2. 优先含“封面/cover”上下文的图片。
3. 过滤表情/小图标。
4. 找不到则返回 `null`（由 UI 用简约卡片兜底）。

## 7. 更新策略（不走搜索）

## 7.1 更新入口

1. 小说详情页“刷新章节”按钮。
2. 可选：小说 Tab 下拉刷新批量更新。

## 7.2 更新流程

1. 读取本地最新章节锚点（pid/orderIndex）。
2. 拉取 `viewthread` 新页面（从已知末页向后探测）。
3. 对楼主新楼层做章节候选解析。
4. 增量写入：
- 新章节插入
- 已有章节更新标题/正文

## 7.3 幂等保证

1. `episode_id` 推荐：`novelId:pid`。
2. 若同 pid 再次解析，仅更新不重复插入。

## 8. UI 与交互设计

## 8.1 新增小说 Tab

在主壳（`main_shell_page`）新增第三个 Tab：

1. 论坛
2. 漫画
3. 小说

`NovelTabPage` 内建议包含：

1. 顶部筛选：`全部 / 文学区(49) / 轻小说(55)`
2. 内容区：网格书架
3. 刷新入口

## 8.2 书架卡片样式

### A. 有封面（轻小说常见）

1. 完整封面图
2. 底部渐变遮罩 + 标题（最多2行）
3. 可附作者/更新提示

### B. 无封面（原创常见）

1. 渐变或纯色背景卡
2. 居中大字标题（2-3行）
3. 左上可加 `原创` 标记

## 8.3 详情页（NovelDetailPage）

结构建议：

1. 顶部信息区（封面/标题/作者/fid/sourceTid）
2. 操作区（刷新章节、排序切换）
3. 章节列表（可升降序）

章节列表项建议展示：

1. `episodeTitle`
2. `PID:xxxx`（调试期可显示）
3. `Page:x`（调试期可显示）

## 8.4 阅读器（NovelReaderPage）

最低可用功能（Phase 1 必做）：

1. 纯文本分页滚动阅读
2. 字号调节
3. 行距调节
4. 段间距调节
5. 背景主题切换（浅色/护眼/深色）
6. 自动保存阅读进度（episode + offset）

建议参数默认值：

1. 字号 `18`
2. 行距 `1.8`
3. 段距 `10`
4. 页边距 `16`

增强功能（后续）：

1. 目录抽屉
2. 快速跳章
3. 长按复制
4. 夜间亮度遮罩

## 9. 分阶段计划（可执行）

## Phase 0：基础设施与可观测

目标：先把地基搭好。

任务：

1. 新建 `features/novel` 目录与空实现骨架。
2. DB 增量迁移（新增 novel 相关表或 content_type）。
3. 新增 `NovelSyncLogger` 与解析 debug 模型。

验收：

1. 可成功建表迁移。
2. 日志可打印解析关键信号。

## Phase 1：最小可用闭环

目标：可以“入库并阅读”。

任务：

1. 小说 Tab + 网格书架页。
2. 小说详情页 + 章节列表。
3. 小说阅读器（字号/行距/主题/进度）。
4. 基于已有 `tid` 手动刷新解析章节。

验收：

1. 从一个已知小说帖可看到章节并阅读。
2. 阅读设置可生效并持久化。

## Phase 2：章节解析增强（目录优先）

目标：提升自动章节识别成功率。

任务：

1. 落地 `NovelPostParsingEngine`。
2. 实现连续链接簇 + 章节词规则。
3. 前几楼目录识别与去重。

验收：

1. 对“有目录链接”的样本高命中。
2. 章节顺序正确。

## Phase 3：分页回退解析

目标：覆盖“无目录链接”帖子。

任务：

1. `viewthread page` 递进抓取。
2. 楼主楼层提取与章节切分启发式。
3. `pid/page/tid` 绑定入库。

验收：

1. 对无目录样本可解析出可读章节集。
2. 增量更新不重复。

## Phase 4：封面与体验优化

目标：提升小说书架体验。

任务：

1. `NovelCoverExtractor`。
2. 双卡片样式（有封面/无封面）。
3. 详情页排序与阅读器交互增强。

验收：

1. 轻小说封面命中率显著提升。
2. 原创卡片视觉不空洞。

## Phase 5：联动与后台刷新

目标：形成稳定长期使用体验。

任务：

1. 与收藏联动导入（fid=49/55）。
2. 定时或手动批量刷新。
3. 失败重试与报告。

验收：

1. 收藏同步后小说可自动进入小说书架。
2. 批量更新可控且不崩溃。

## 10. 关键实现细节建议

## 10.1 章节顺序定义

建议主排序键：

1. `orderIndex`（解析顺序）
2. 次排序 `pid` 数值
3. 再次 `page`

展示层可切换升降序，但存储始终保持统一正序。

## 10.2 解析阈值建议

1. `opHeadFloorScanLimit = 5`
2. `minDirectEpisodeCount = 3`
3. `maxViewthreadPagesPerRefresh = 30`
4. `maxConsecutiveNoNewEpisodes = 3`

## 10.3 文本清洗建议

1. 删除“本帖最后由...编辑”行（可选）。
2. 保留引用块但默认折叠（后续）。
3. 删除广告/统计脚本残留文本。

## 12. 风险与对策

风险 1：目录链接不规范

对策：

1. URL 多模式解析（thread/viewthread/;tid）。
2. 连续簇规则提升召回。

风险 2：分页过多导致请求负载高

对策：

1. 页面上限 + 连续无新增熔断。
2. 增量刷新从上次末页开始。

风险 3：正文清洗破坏格式

对策：

1. 保留 `rawHtml`。
2. 清洗算法可配置并加回归样本。

风险 4：UI 复杂度上升

对策：

1. 先做最小阅读器。
2. 样式面板分离成独立 widget/controller。
