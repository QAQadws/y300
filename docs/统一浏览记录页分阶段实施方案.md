# 统一浏览记录页分阶段实施方案

> 文档状态：Phase 2 已完成，Phase 3 待实施
> 编写日期：2026-07-16
> 适用范围：`history`、`startup`、`thread`、`forum` WebView、`comic`、`novel`、`library_shared`、本地持久化与应用导航
> 需求参考：`docs/记录页.md`、用户提供的历史页参考图
> 目标平台：Android / iOS；记录数据仅保存在本机

## 0. 文档定位

本方案要实现一个新的“记录”底部 Tab，统一展示三类用户访问：

1. 用户成功进入帖子详情，包括原生帖子详情和论坛 WebView 帖子详情。
2. 用户成功进入漫画详情页。
3. 用户成功进入小说详情页。

“记录”表达的是用户实际看到过的内容，不是网络请求日志、解析日志或收藏同步日志。实现必须把浏览行为与 HTTP、缓存、收藏同步、漫画解析、小说水合和后台刷新解耦。

整体交付路线固定为：

```text
先建立独立 history 领域和本地数据库
  -> 再完成记录页读模型、搜索、删除和底部导航
  -> 再接入漫画/小说详情可见事件
  -> 再接入原生帖子详情可见事件
  -> 再接入 WebView 主文档可见事件
  -> 最后完成重开路由、数据治理与全链路回归
```

本方案不监听全局网络请求，也不在 repository 成功返回时直接写记录。记录提交点位于“用户可见页面成功提交”的 presentation 边界。

## 1. 需求规范化

### 1.1 用户可见目标

- 底部导航新增“记录”和熟悉的历史图标，顺序固定为：
  `论坛 / 收藏 / 漫画 / 小说 / 记录 / 更多`。
- 记录页使用参考图的安静列表布局，不使用卡片套卡片：
  - 顶部标题“记录”。
  - 右侧搜索按钮和清空按钮。
  - 按本地自然日分组。
  - 左侧缩略图，中间标题与上下文，右侧单项删除按钮。
  - 点击整行重新打开对应帖子、漫画详情或小说详情。
- 同一个帖子或作品重复访问时移动到列表顶部，不连续制造重复行。
- 支持单项删除、清空全部、搜索、空状态、错误重试。
- 删除记录不删除收藏、书架作品、章节、阅读进度、下载或图片缓存。

### 1.2 “追加记录”的正式语义

用户口语中的“追加记录”规范为：

> 每次新的用户可见访问会话计入一次访问，但列表按目标身份聚合为一行。

因此：

- 同一目标只有一条 `HistoryEntry`。
- 新访问通过 UPSERT 更新 `lastVisitedAt`、展示快照和 `visitCount`。
- UI 按 `lastVisitedAt DESC` 排序。
- `firstVisitedAt` 保留第一次访问时间。
- 若未来需要完整的逐次访问时间线，再新增 `history_visit_events`；第一版不维护第二张事件表。

这种语义与参考图一致，也避免一个帖子刷新十次后出现十个相同条目。

### 1.3 明确不计入记录的行为

- 收藏同步的 `version=4` JSON 请求。
- 漫画目录解析、章节发现、搜索 fallback 和自动刷新队列。
- 小说首楼元数据同步、`version=1` 章节水合与增量更新。
- 图片预加载、封面预热、缓存命中、下载和后台任务。
- 帖子楼层定位 `thread.post.locate` 请求。
- 帖子详情加载失败、空白错误页、权限提示页或“主题不存在”页。
- WebView 图片、脚本、CSS 等子资源请求。
- 只创建页面路由但尚未成功展示内容的场景。

### 1.4 同一页面会话的计数规则

| 场景 | 新增一次访问计数 | 更新同一列表行 |
| --- | --- | --- |
| 原生帖子首次成功显示 | 是 | 是 |
| 原生帖子命中 snapshot/cache 后显示 | 是 | 是 |
| 原生帖子当前路由内刷新、翻页、倒序、只看楼主 | 否 | 否 |
| 退出后重新进入同一原生帖子 | 是 | 是 |
| WebView 首次成功显示帖子 A | 是 | 是 |
| WebView 帖子 A 内刷新、分页、切换排序 | 否 | 否 |
| WebView A -> B | 是，B 计一次 | 是 |
| WebView A -> B -> A | 是，返回 A 再计一次 | 是 |
| WebView 离开帖子到版块，再进入 A | 是 | 是 |
| 漫画详情首个有效 Header 显示 | 是 | 是 |
| 漫画详情当前路由内刷新、从阅读器返回后 reload | 否 | 否 |
| 小说详情首个有效 Header 显示 | 是 | 是 |
| 小说章节水合状态变化或详情刷新 | 否 | 否 |
| 从记录页打开目标并成功显示 | 是 | 是，返回记录页后移到顶部 |

## 2. 当前代码基线与影响面

### 2.1 主壳

`MainShellPage` 当前使用懒构建 `IndexedStack`，包含五项：论坛、收藏、漫画、小说、更多。新增记录页后：

- `_pageCount` 从 5 调整为 6。
- 记录页位于 index 4。
- 更多页从 index 4 移到 index 5。
- `_builtIndexes` 的懒构建语义继续保留。
- `TickerMode` 只启用当前 Tab。
- 书架多选时底部 `SelectionActionBar` 的替换逻辑不变。

Material 3 通常建议底部目的地不超过五个，但本需求明确要求六项。由于所有标签都是两个汉字，第一版保留六项 `NavigationDestination`，并把 320dp 宽度、大字体和横屏列为强制回归项；不能通过缩小字体或负字距硬塞。

### 2.2 统一作品详情

漫画和小说都通过 `UnifiedDetailPage` 展示，`UnifiedDetailController._load()` 成功后同时拥有：

- `LibraryDetailHeader`：作品 ID、展示标题、来源标题、封面 URL/本地路径/焦点、来源 TID 等。
- `List<LibraryChapterItem>`：章节标题和可选的当前阅读进度。

`UnifiedDetailPage` 是最合适的“首次内容已经提交”检测点，但 `library_shared` 不应依赖 `history`。目标实现是在共享页增加一个纯回调契约，由漫画/小说薄壳把快照转成历史访问草稿。

### 2.3 原生帖子详情

`ThreadDetailPageState` 已包含 TID、主题、版块名、当前页、canonical/desktop URL 和楼层列表。原生页面可能来自：

- 网络 HTML。
- parsed snapshot。
- 页面缓存。
- 小说楼层定位后的普通页面加载。

因此记录条件只能依赖最终可渲染状态，不能依赖是否发出 `thread.detail.html`。

### 2.4 论坛 WebView

`ForumWebViewPage` 已有：

- `_navigationGeneration` 防止迟到的异步结果污染新导航。
- `onPageStarted / onPageFinished / onProgress` 主文档回调。
- `ForumWebViewNavigator.classify()` 和 `extractTid()`。
- 高级 WebView 的 `onPageCommitVisible` 能力，但当前页面尚未接入 callback。

WebView 记录需要复用 generation，并建立“可见提交 + 元数据完成”的两阶段门禁。不能从 Dio/Yamibo 网关监听 WebView 请求。

### 2.5 本地数据库

当前 `comic_shelf.db` 实际承载漫画、小说、收藏、缓存和共享书架状态，但它仍由 `comic` 模块的 `ComicLocalDb` 所有。历史记录与这些表没有外键或事务需求。

本方案决定使用独立的 `history_records.db`：

- `history` 模块拥有 schema、迁移和生命周期。
- 不让新模块反向依赖 `comic/data/local`。
- 清空记录可以独立执行。
- 不影响现有 v32 主数据库和任何收藏/作品迁移。
- 代价只是增加一个懒加载 SQLite connection，当前数据规模和移动端平台可接受。

若未来项目抽取统一 `AppDatabase`，可以在独立迁移专项中合并；本期不借历史功能重构全部数据库。

## 3. 架构原则与模块边界

### 3.1 分层

新建：

```text
lib/features/history/
  domain/
    models/
    repositories/
    services/
  data/
    local/
    repositories/
    providers/
  presentation/
    controllers/
    models/
    widgets/
    history_page.dart
```

职责固定如下：

- `domain`：目标身份、访问草稿、记录实体、查询、repository contract、日期分组与会话去重策略。
- `data`：SQLite schema、DAO、row mapper、repository 实现、变更流。
- `presentation`：页面状态、搜索/分页、分组列表、删除/撤销、清空和错误反馈。
- 生产者模块：只在内容可见后构造 `HistoryVisitDraft` 并调用稳定 recorder port。
- `app/navigation`：把历史实体重新打开为具体页面，作为跨 feature composition root。

### 3.2 依赖方向

```text
thread/forum/comic/novel presentation
  -> history domain recorder contract + provider
  -> history data repository

history presentation
  -> history domain/query use cases
  -> 通过回调请求 app navigation 打开目标

app/navigation/history_entry_router.dart
  -> ThreadDetailPage / ForumWebViewPage / ComicDetailPage / NovelDetailPage
```

禁止：

- `history` repository 查询漫画/小说 repository 来临时拼列表。
- `library_shared` import `history`。
- `history` presentation 直接持有 Cookie、HTTP client 或 parser。
- `MainShellPage` 直接写 SQLite。
- 页面把数据库异常冒泡成详情页加载失败。

### 3.3 使用的设计模式

- Repository：隔离 SQLite 与领域查询。
- Application Service / Use Case：统一记录、删除、清空、恢复与查询。
- Port and Adapter：详情页面只调用 recorder port，数据实现由 Riverpod 组合。
- Snapshot Read Model：记录页使用写入时的展示快照，不跨模块 join。
- State Machine：WebView generation 和 route session 决定幂等提交。
- Strategy：不同目标类型通过 mapper 生成草稿，通过 opener strategy 重开。
- Policy Object：日期分组、保留上限、标题规范化和缩略图回退独立测试。

## 4. 领域模型

### 4.1 目标身份

```dart
enum HistoryTargetType {
  thread,
  comic,
  novel,
}

class HistoryTargetKey {
  final HistoryTargetType type;
  final String id;
}
```

身份规则：

- 帖子：`type=thread, id=<normalized tid>`。
- 漫画：`type=comic, id=<comic workId>`。
- 小说：`type=novel, id=<novel workId>`。
- 复合主键是 `(targetType, targetId)`。
- 同一小说/漫画来源帖与普通帖子记录可以同时存在，因为它们打开的是不同体验。

### 4.2 访问来源

```dart
enum HistoryVisitSurface {
  threadNative,
  threadWebView,
  comicDetail,
  novelDetail,
}
```

`lastSurface` 用于诊断和展示快照，不决定帖子重开模式。帖子重开始终尊重用户当前的论坛显示模式。

### 4.3 缩略图快照

```dart
class HistoryThumbnailSnapshot {
  final String? localPath;
  final String? remoteUrl;
  final double? focusX;
  final double? focusY;
}
```

规则：

- 漫画/小说复用 `LibraryDetailHeader` 当前有效封面优先级和焦点。
- 帖子可记录首楼作者头像 URL；取不到时使用类型图标。
- history 不复制封面文件，也不成为图片缓存 owner。
- 渲染时按“存在的本地文件 -> remote URL -> 类型图标”回退。
- 本地路径失效不能导致整行报错。

### 4.4 访问草稿

```dart
class HistoryVisitDraft {
  final HistoryTargetKey target;
  final HistoryVisitSurface surface;
  final String? title;
  final String? contextLabel;
  final HistoryThumbnailSnapshot? thumbnail;
  final String? sourceTid;
  final Uri? canonicalUri;
  final int? page;
  final String? forumName;
}
```

调用方不提供时间。`RecordHistoryVisitUseCase` 使用注入的 `Clock` 生成 UTC 时间，保证测试稳定。

### 4.5 持久化实体

```dart
class HistoryEntry {
  final HistoryTargetKey target;
  final String title;
  final String contextLabel;
  final HistoryThumbnailSnapshot? thumbnail;
  final String? sourceTid;
  final Uri? canonicalUri;
  final int? lastPage;
  final String? forumName;
  final HistoryVisitSurface lastSurface;
  final DateTime firstVisitedAt;
  final DateTime lastVisitedAt;
  final int visitCount;
}
```

`HistoryEntry` 是记录页自己的读模型快照，不是漫画、小说或帖子的权威数据。来源作品后续改名时，下一次成功访问会刷新快照；记录页不在每次打开时跨模块追最新标题。

### 4.6 标题与上下文规范

`HistoryVisitDraftNormalizer` 负责：

- trim 并折叠多余空白。
- 拒绝空 target ID。
- 帖子 TID 必须是正整数。
- 标题最多保留 200 grapheme cluster，不能按 UTF-16 生硬截断。
- 空标题回退：`帖子 <tid>`、`未命名漫画`、`未命名小说`。
- canonical URI 只保留 http/https；帖子 URL 规范化为必要参数，不保存 formhash、auth、highlight 等敏感或无关 query。
- `page <= 0` 规范化为 null。

上下文建议：

- 帖子：优先版块名；若打开页码大于 1，可显示 `第 N 页`。
- 漫画：优先当前阅读章节标题；没有进度时显示 `漫画详情`。
- 小说：优先上次阅读章节标题；没有进度时显示 `小说详情`。
- UI 统一组合为：`<contextLabel> · <HH:mm>`。

## 5. Repository 与应用服务契约

### 5.1 Repository

```dart
abstract interface class HistoryRepository {
  Future<void> recordVisit(HistoryEntry candidate);

  Future<HistoryQueryPage> query(HistoryQuery query);

  Future<void> delete(HistoryTargetKey target);

  Future<void> clear();

  Future<void> restore(HistoryEntry entry);

  Stream<HistoryChange> watchChanges();
}
```

### 5.2 查询模型

```dart
class HistoryQuery {
  final String searchText;
  final Set<HistoryTargetType> targetTypes;
  final HistoryCursor? cursor;
  final int limit;
}

class HistoryCursor {
  final DateTime lastVisitedAt;
  final HistoryTargetType targetType;
  final String targetId;
}
```

使用 keyset pagination，不使用大 offset：

```text
ORDER BY last_visited_at DESC, target_type ASC, target_id ASC
LIMIT 50
```

游标包含完整排序键，时间相同也不会丢项或重复。

### 5.3 Use cases

- `RecordHistoryVisitUseCase`
  - 规范化草稿。
  - 注入 UTC 时间。
  - 生成 candidate。
  - 原子 UPSERT。
  - 执行保留策略。
  - 发送 change event。
- `QueryHistoryUseCase`
  - 转义 `% / _ / \\` 后执行本地 LIKE。
  - 搜索标题、上下文、版块名和目标 ID。
- `DeleteHistoryEntryUseCase`
- `ClearHistoryUseCase`
- `RestoreHistoryEntryUseCase`
  - 支持单项删除后的 Snackbar 撤销。
  - 若撤销期间产生了更晚访问，不覆盖更新的数据。

### 5.4 写入失败语义

记录属于辅助功能：

- 写入失败不能阻断帖子或作品详情显示。
- 生产者以 best-effort 方式调用 recorder，并捕获错误。
- debug/诊断日志记录 target、surface 和错误类型，不记录标题全文、URL query 或正文。
- 记录页自身删除/清空失败必须显示 Snackbar，并回滚乐观 UI。

## 6. 本地数据库设计

### 6.1 数据库

```text
database: history_records.db
version: 1
owner: features/history/data/local/HistoryLocalDb
```

### 6.2 表结构

```sql
CREATE TABLE history_entries (
  target_type TEXT NOT NULL,
  target_id TEXT NOT NULL,
  title TEXT NOT NULL,
  context_label TEXT NOT NULL,
  thumbnail_local_path TEXT,
  thumbnail_remote_url TEXT,
  thumbnail_focus_x REAL,
  thumbnail_focus_y REAL,
  source_tid TEXT,
  canonical_url TEXT,
  last_page INTEGER,
  forum_name TEXT,
  last_surface TEXT NOT NULL,
  first_visited_at INTEGER NOT NULL,
  last_visited_at INTEGER NOT NULL,
  visit_count INTEGER NOT NULL DEFAULT 1,
  PRIMARY KEY (target_type, target_id)
);

CREATE INDEX idx_history_entries_recent
ON history_entries(last_visited_at DESC, target_type, target_id);
```

时间字段存 UTC epoch milliseconds。日期分组时才转换到设备当前时区。

### 6.3 UPSERT 合并规则

- `visit_count = visit_count + 1`。
- `first_visited_at = MIN(existing, incoming)`。
- `last_visited_at = MAX(existing, incoming)`。
- 只有 incoming 时间不早于 existing 时，才用 incoming 更新 title/context/route/thumbnail 快照。
- incoming 可选字段为空时保留已有有效值，避免一次贫化 payload 擦除封面和 canonical URL。
- `target_type / target_id` 永不更新。
- 整个 UPSERT 与保留策略在同一 transaction 中执行。

这能防止迟到的异步 WebView finish 把较新的快照覆盖回旧标题或旧页码。

### 6.4 保留策略

第一版最多保留 2000 个唯一目标：

- 每次成功写入后删除排序第 2001 位及之后的记录。
- 清理只影响 `history_entries`。
- 不删除封面缓存、作品、收藏或下载。
- 上限封装为 `HistoryRetentionPolicy`，测试中可注入较小值。

### 6.5 迁移策略

- v1 只创建表和索引。
- 后续版本采用逐版本增量迁移，不能通过重建数据库丢失用户历史。
- `onDowngrade` 不自动清空用户记录；开发期若确需重建，应由明确 debug 工具完成。
- 数据库存取全部通过 row mapper，presentation 不接触列名。

## 7. 访问提交状态机

### 7.1 通用 route session

每个原生页面路由拥有一个内存态 guard：

```dart
class RouteHistoryCommitGuard {
  HistoryTargetKey? committedTarget;

  bool shouldCommit(HistoryTargetKey target);
}
```

- 首次目标提交返回 true。
- 当前路由同目标后续 rebuild/reload 返回 false。
- Widget 更新为不同 workId/tid 时重置；正常路由通常不会发生该情况。
- guard 不持久化，不用随机 UUID，不进入数据库。

### 7.2 漫画/小说详情提交

为 `UnifiedDetailPage` 增加不依赖 history 的回调：

```dart
final FutureOr<void> Function(
  LibraryDetailHeader header,
  List<LibraryChapterItem> chapters,
)? onFirstContentPresented;
```

触发规则：

1. `UnifiedDetailController.initialize()` 成功取得 header。
2. 页面 `setState` 后等待首个 frame。
3. Widget 仍 mounted，workId 未变化。
4. route guard 尚未提交。
5. 调用回调；回调失败不改变详情状态。

漫画/小说薄壳分别使用 mapper 构造 `HistoryVisitDraft`。共享页只表达“内容已呈现”，不认识历史数据库。

小说章节水合可以仍在进行，只要本地 Header 已经可见就应记录；水合失败不撤销已经发生的详情访问。

### 7.3 原生帖子提交

提交条件：

- `isLoadingInitial == false`。
- `errorMessage` 为空。
- `posts.isNotEmpty`。
- 至少首个帖子卡片已进入可渲染树。
- TID 有效。

使用 `ThreadHistoryVisitMapper`：

- title：成功 state.subject，回退路由 subject，再回退 `帖子 <tid>`。
- context：forumName 或 `第 N 页`。
- thumbnail：首楼作者头像 URL（可选）。
- canonical：desktop/canonical URL 经 URL policy 清洗。
- page：首次成功显示的普通帖子页码。
- surface：`threadNative`。

snapshot/cache 命中与网络加载完全同等。楼层定位只负责找到真实页码，定位请求本身不提交记录。

### 7.4 WebView 帖子提交

新增 route-local `ForumWebViewHistoryCoordinator`：

```text
onPageStarted
  -> generation + 1
  -> 建立 pending navigation

onPageCommitVisible (高级引擎)
  -> 标记 generation 已可见

onPageFinished
  -> 读取最终 URL、TID、结构化帖子文档快照
  -> 标记 metadata ready

visible && metadata ready && generation still current
  -> 尝试提交
```

高级引擎接入现有但尚未使用的 `onPageCommitVisible` callback。Legacy WebView 没有该能力时，以 `onPageFinished + DOM 中存在有效帖子标题/正文容器` 作为可见证明。

WebView DOM 快照不应靠 `document.title.split(' - ')` 猜标题。新增/扩展结构化 bridge，一次读取：

- `.viewthread_title` 或移动模板等价标题节点。
- canonical URL。
- 可选首楼头像。
- 现有帖子菜单链接。
- 可证明这是有效帖子页面的 post wrapper 数量。

TID 提取必须复用 `ForumThreadUrlParser` 的 raw query 容错语义，或把等价能力下沉为共享 URL policy；禁止重新直接解码整段 query。带旧 GBK 百分号编码 `highlight=%D2...` 的 viewthread URL 必须仍能提取 TID，且历史 canonical URL 不保留 `highlight`。

去重规则：

- coordinator 保存 `lastCommittedTarget`。
- 连续提交同一 TID（分页、刷新、排序、只看楼主）跳过。
- 成功提交不同 TID 时更新 target。
- 非帖子主文档成功提交后清空 target；再次进入旧 TID 视为新访问。
- generation 不匹配的 finish/DOM 读取结果全部丢弃。
- 最终重定向 URL 为准，不使用请求前 URL。

## 8. 记录页 UI 规范

### 8.1 页面骨架

```text
Scaffold
  AppBar
    title: 记录 / 搜索输入框
    actions: 搜索、清空
  body
    loading / error / empty / grouped CustomScrollView
```

不增加营销式说明、装饰背景或嵌套卡片。

### 8.2 日期分组

`HistoryDateGroupingPolicy` 按设备本地自然日分组，而不是简单按 24 小时差：

- 当天：`今天`。
- 前一天：`1 天前`。
- 前 2 到 6 天：`N 天前`。
- 更早：`yyyy/M/d`。

跨午夜、夏令时和时区变化由注入的 clock/timezone 测试。组内按 `lastVisitedAt DESC`。

### 8.3 行布局

- 外层为无背景的 `InkWell` 列表行。
- 水平 padding 16，垂直 padding 10。
- 缩略图槽建议固定 `64 x 88`，圆角不超过 6。
- 标题最多 2 行，使用详情/书架同等级的紧凑标题字号。
- 副标题 1 行：`contextLabel · HH:mm`，颜色弱化。
- 右侧删除使用 `IconButton(Icons.delete_outline)`，48dp 点击区域和 tooltip“删除记录”。
- 行点击区域不包含删除按钮，避免删除点击同时触发导航。
- 图片加载失败只替换缩略图槽，不改变行高。
- 没有封面/头像时显示低对比度类型图标：帖子、漫画、小说分别使用熟悉图标；不显示损坏图片图标。

### 8.4 搜索

- 点击搜索图标后 AppBar 标题区域切换为 TextField。
- 自动聚焦并显示清除输入按钮。
- 输入 250ms debounce 后重新执行首屏查询。
- 搜索 title、contextLabel、forumName 和 targetId。
- 退出搜索恢复完整时间线和滚动状态。
- 搜索无结果使用独立 empty state，不显示“没有记录”的初始空状态文案。

### 8.5 删除与清空

单项删除：

- 立即从当前列表乐观移除。
- repository 成功后显示带“撤销”action 的 Snackbar。
- 撤销恢复原实体，不增加 visitCount。
- 删除失败恢复列表并显示错误 Snackbar。

清空全部：

- AppBar 使用 `delete_sweep_outlined` 或语义等价图标。
- 点击后弹确认对话框“清空全部记录”。
- 明确说明不会删除收藏、书架和下载。
- 确认后清空并展示空状态。
- 空列表时清空按钮禁用或隐藏。

### 8.6 加载与分页

- 初始加载使用页面中心进度状态。
- 每页 50 条。
- 接近列表末尾时加载下一页。
- 加载下一页失败在底部显示可重试行，不覆盖已加载内容。
- repository change stream 到达时刷新首屏；若当前处于搜索态，按当前查询刷新。
- 页面作为 `IndexedStack` 子项保留滚动和搜索状态；重新切回时不闪回顶部。

### 8.7 可访问性和响应式

- 图标按钮都有 tooltip 和 semantic label。
- 行 semantics 包含类型、标题、上下文和访问时间。
- 支持 320dp、360dp、平板宽度和横屏。
- 测试 text scale 1.0、1.3、2.0；标题和副标题允许合理换行，删除按钮不覆盖文字。
- 浅色/深色主题都复用 `ColorScheme`，不硬编码白色背景。
- 六项底部导航在最窄目标设备上不得溢出或截断；不按 viewport 动态缩小字体。

## 9. 重开导航设计

### 9.1 Composition root

新增 `lib/app/navigation/history_entry_router.dart`。history 页面只接收：

```dart
Future<HistoryOpenResult> Function(
  BuildContext context,
  HistoryEntry entry,
) onOpenEntry;
```

这样 `history/presentation` 不直接 import 三个详情页，具体路由由 app 层组合，避免 feature import cycle。

### 9.2 漫画与小说

- comic -> `ComicDetailPage(comicId: entry.target.id)`。
- novel -> `NovelDetailPage(novelId: entry.target.id)`。
- 打开前不额外刷新作品。
- 若本地作品已被删除：
  - 有 `sourceTid` 时返回可恢复失败，允许用户选择“打开原帖”。
  - 无 sourceTid 时显示“作品已从本地移除”，并提供删除该记录的操作。
- 历史表不通过外键跟随作品删除，保留用户浏览事实和来源回退能力。

### 9.3 帖子

帖子重开读取当前 `ForumShellMode`，不强制使用 `lastSurface`：

- native -> `ThreadDetailPage(tid, subject, initialPage)`。
- webView -> 使用规范化 viewthread URI 打开 scoped `ForumWebViewPage`。
- URI 只构造 `mod=viewthread / tid / page / mobile=2` 必要参数。
- `lastSurface` 仅用于诊断；用户切换论坛模式后，记录入口跟随当前设置。

### 9.4 导航失败

`HistoryOpenResult` 使用结构化结果：

```dart
sealed class HistoryOpenResult {}
class HistoryOpenSuccess extends HistoryOpenResult {}
class HistoryOpenUnavailable extends HistoryOpenResult {
  final String message;
  final String? fallbackTid;
}
class HistoryOpenFailure extends HistoryOpenResult {
  final Object error;
}
```

不能用 bool 混淆“用户取消、目标不存在、路由失败”。

## 10. Riverpod 组合与状态同步

建议 provider：

```text
historyDatabaseProvider
historyRepositoryProvider
historyClockProvider
historyRetentionPolicyProvider
recordHistoryVisitUseCaseProvider
historyControllerProvider
historyEntryRouterProvider (app composition)
```

`HistoryRepository.watchChanges()` 是进程内广播流：

- record/delete/restore/clear 成功后发布 revision event。
- HistoryController 监听并刷新当前查询。
- 记录页尚未构建时不会强制打开数据库；第一次记录或第一次进入 Tab 时懒打开。
- provider dispose 时关闭 stream controller 和 database connection。

不使用全局静态单例，不把 `BuildContext` 放进 provider，不从 data 层操作 UI。

## 11. 与其它模块的隔离保证

### 11.1 收藏同步

收藏同步继续走 JSON/API、分类、漫画/小说 ingest。它不创建用户可见 route，因此不会调用 recorder。

即使未来收藏同步改为 HTML，也不会污染记录，因为历史没有网络监听器。

### 11.2 漫画/小说刷新

更新章节、下拉刷新、首次小说水合和后台搜索队列只更新业务 repository。只有详情页首个可见 frame 可以提交访问。

### 11.3 阅读器

第一版不记录漫画阅读器、小说阅读器和帖子图片阅读器的单独访问。详情历史中可以快照“上次阅读章节”，但 reader progress 仍由原模块拥有。

未来若要记录“读到某章某页”，应增加新的 `readingSession` 事件和独立上下文，不复用本期详情进入事件。

### 11.4 删除与缓存

- 删除历史不调用 `WorkPurgeService`。
- 不改变 protected cover ownership。
- 不改变图片 cache retention。
- 缩略图缓存失效只触发 UI fallback。
- 数据与存储页未来可以统计 history DB 大小，但“清缓存”不能清历史；只有“清空记录”或“清除全部应用数据”才删除。

## 16. 第一版非目标与后续方向

第一版明确不实现：

- 云端同步或账号间同步历史。
- 完整逐次访问事件时间线。
- reader session、读到某页/滚动位置的独立历史。
- 浏览时长统计、排行榜、推荐算法或埋点上传。
- 按标签/版块的高级筛选。
- 历史记录导入导出。
- Web/Windows/macOS/Linux 专项适配。

可在稳定后扩展：

- `history_visit_events` 完整时间线。
- 类型筛选和日期范围筛选。
- 固定/收藏某条记录。
- 本地导出与隐私备份。
- 阅读器 session 与详情访问分层展示。

这些扩展必须建立在本期稳定的 `HistoryTargetKey + HistoryVisitDraft + Repository` 契约上，不能重新回到监听 HTTP 的实现。
