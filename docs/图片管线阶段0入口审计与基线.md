# 图片管线阶段 0 入口审计与基线

> 状态：阶段 0 基线  
> 范围：只记录现状与测试缺口，不引入 `ForumImageLoadSpec`、resolver、新 Widget 或新预热协调器。  
> 关联方案：`HTML-first正文与漫画阅读器图片管线优化方案.md`

## 1. 阶段目标

阶段 0 的目标是把当前图片入口和行为锁成后续改造的回归基线。此阶段不修复、不统一、不提前重构，只回答：

- 哪些入口在显示远程/本地图片。
- 当前用哪个 Widget 或服务显示。
- 当前 cache request 的 role、owner、retention 和 headers 从哪里来。
- 当前尺寸、fallback、预热、阅读器入口是什么。
- 哪些行为已有测试，哪些只做文档记录，留给后续阶段补强。

## 3. 已锁定测试

- HTML-first 正文图：
  - 普通图使用 `threadInline`。
  - 表情使用 `remoteSmiley` sticky。
  - 表情无尺寸不固定 24x24。
  - 表情 HTML 尺寸和缓存尺寸生效。
  - 普通图无尺寸使用 `0.7` fallback。
  - `data:image` 等非网络图回到 HTML renderer 默认路径。
- 缓存 Widget：
  - `CachedLibraryImage` 先查 `getCached`，命中时不启动 `ensureCached`。
  - 已显示远程图后，不在同帧切换本地文件。
  - `LibraryCachedImage` 使用 headers、规范化相对 URL、SVG/noavatar fallback、上报尺寸。
- 论坛 chrome：
  - 首页轮播图使用 `forumHeadImage`，retention 为 sticky。
- 头像：
  - 点评头像使用 `avatar` cache request。
  - 点评默认头像使用本地 `assets/noavatar.png`。
  - 楼层作者默认头像使用本地默认头像；普通作者头像当前仍是 `Image.network`。
- 书架/收藏封面：
  - `ShelfCoverImage` 委托 `AppImage`。
  - 无本地/远程时显示 placeholder。
  - custom cover 在 adapter 和 card 层保留 protected/local 优先语义。
- 阅读器：
  - `ComicReaderPreloadQueue` 覆盖优先级、去重、并发、`cancelExcept`、dispose。

## 4. 后续阶段关注点

- 阶段 1 再抽象 `ForumImageLoadSpec` 与 resolver，不在阶段 0 提前引入。
- 楼层作者头像当前仍未走 `avatar` cache request，后续头像收口阶段统一处理。
- 书架封面已有 `AppImage` 基础；后续阶段需要把近视口预取从 cancel-restart 收敛到窗口重排。
- 首页轮播图已有手写 `ensureCached + precacheImage`；后续阶段可迁移到统一 `ForumImagePrecacheService`。
- 版块图标和顶部图的展示入口仍需在后续阶段做更细测试与收口。
