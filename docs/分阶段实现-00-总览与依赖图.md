# 分阶段实现 00：总览与依赖图

本文档用于把本次需求拆成可以连续落地的阶段。当前项目已经有比较完整的模块边界：论坛、帖子详情、漫画、小说、统一书架/详情、更多页、收藏 API 数据层和 SQLite 本地库。后续实现不要推翻这些边界，应该优先沿着已有 adapter、repository、controller 体系扩展。

| --- | --- | --- |

| 标签源数据 | `assets/tag.json` | 当前是 `fid -> tags[typeid,name]` 的数组结构，适合启动时构建索引 |

## 推荐落地顺序

1. 阶段 01：标签与 typeid 基础设施
   - 先让 `ThreadDetailData`、论坛列表摘要、漫画/小说基础模型都能携带 `typeid/tagName`。
   - 建立 `TagLookup` 和统一的 `ThreadContentClassifier`。
   - 这是收藏同步、漫画/小说判定、详情页展示标签的共同前置。

2. 阶段 02：解析规则稳定化
   - 把漫画两处 raw HTML 扫描改为 DOM 提取。
   - 把小说解析改成规则列表式架构，便于后续添加封面、标题、正文、轻小说插图规则。
   - 这一阶段不需要大改 UI，但要提高后续收藏批量解析的稳定性。

3. 阶段 03：收藏同步与收藏 Tab
   - 基于 `myfavthread` 做全量/增量同步。
   - 进帖补全 `fid/typeid/tagName/contentKind`。
   - 把收藏里的漫画/小说同步进入漫画/小说模块。
   - 新增主 Tab“收藏”，复用 `UnifiedShelfPage`，默认列表显示。

4. 阶段 04：缓存机制重构
   - 图片缓存从“按 URL 缓存”改为“按逻辑图片身份缓存”。
   - 封面和作品元信息作为受保护缓存，不被清理图片缓存删除。
   - 阅读图片、小说插图等非封面图片进入可清理 LRU 图片缓存。

5. 阶段 05：存储与下载
   - 引入独立下载存储根目录。
   - 漫画以 `meta.json + cover.jpg + 多个 cbz` 存储。
   - 小说以 `meta.json + cover.jpg + chapters/images` 存储，先保证可读与可恢复，后续再考虑 epub 等导出格式。
   - 阅读优先级变为：下载存储 > 本地缓存 > 网络。

6. 阶段 06：更多页“数据与存储”
   - 删除旧“缓存目录”入口。
   - 新增“数据与存储”页面，包含图片缓存清理/上限和下载存储位置设置。
   - 所有缓存、存储目录写入 `.nomedia`。

7. 阶段 07：迁移、测试与验收
   - 补齐 SQLite 版本迁移、旧数据兼容、测试覆盖和手工验收路径。

## 核心设计决策

### 1. `assets/tag.json` 不必为了性能重构

当前 JSON 是数组结构：

```json
[
  {
    "fid": 30,
    "name": "...",
    "tags": [
      { "typeid": 65, "name": "公告" }
    ]
  }
]
```

数据量很小，启动时或者首次使用时构建如下索引就足够：

```dart
Map<String, ForumTag> byFidTypeid; // key = '$fid:$typeid'
Map<String, ForumBoardTagSet> byFid;
```

只有在后续要人工频繁维护、远程更新、或者服务端返回大量标签时，才需要改成更扁平的结构：

```json
{
  "byFidTypeid": {
    "30": {
      "65": "公告",
      "398": "韩国漫画"
    }
  }
}
```

现阶段推荐保留 `assets/tag.json`，在 Dart 侧构建索引，避免为了很小的数据引入额外维护成本。

### 2. 区分“自带标签”和“自定义标签”

后续详情页标签条需要展示：

1. 第一个标签：论坛自带标签，由 `fid + typeid` 定位。
2. 后续标签：用户在 App 内添加的标签，继续使用现有 `library_tags` / `library_work_tags`。

因此模型中不要把二者混成一个表。建议命名：

- `sourceTypeId`
- `sourceTagName`
- `customTags`

### 3. 漫画/小说判定必须统一成服务

同一套规则会被这些地方使用：

- 帖子详情页显示“加入漫画/小说”入口。
- 收藏同步进帖补全后判定内容类型。
- 漫画/小说模块接收收藏同步数据。
- 收藏 Tab 的“漫画/小说/默认”系统分类。

建议新增一个统一服务，例如：

```dart
enum ThreadContentKind { comic, novel, forum }

class ThreadContentClassifier {
  ThreadContentKind classify({
    required String fid,
    required String typeid,
    String? tagName,
  });
}
```

判定规则：

- 漫画：`fid == '30' && tag != '公告'`
- 小说：`fid == '49' || fid == '55'`，且 `tag != '公告'`
- 其它：论坛普通帖子

为了避免标签名称加载失败导致误判，`公告` 同时用名称和已知 typeid 兜底：

- `fid=30,typeid=65`
- `fid=49,typeid=121`
- `fid=55,typeid=147`

### 4. 收藏同步是后续书架数据的入口

用户明确希望漫画和小说模块的内容全部由新收藏模块表示。因此后续“加入书架”行为的主路径应是：

`myfavthread` 收藏列表 -> 本地 favorite cache -> 进帖补全 -> 按规则同步到 comic/novel 本地库 -> 漫画/小说书架显示。

帖子详情里原本的“漫画候选加入书架”可以在阶段 03 后逐步弱化，最终变成提示用户去论坛收藏，或者直接调用论坛收藏 API 后触发收藏同步。

### 5. 缓存和存储必须分离

缓存：

- 面向加速浏览。
- 可清理。
- 保存图片实体，而不是只保存图片 URL。
- 但作品元信息、封面、本地自定义封面、标签、简介、章节列表等是受保护缓存，不能被“清除图片缓存”删除。

存储：

- 面向用户主动下载。
- 不应被缓存清理删除。
- 用明确文件结构保存，可离线阅读、可备份、可被其它阅读器读取。

读取优先级：

1. 已下载存储。
2. 本地缓存。
3. 网络请求，并写入缓存。
