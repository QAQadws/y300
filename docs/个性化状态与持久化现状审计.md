# Y300 个性化状态与持久化现状审计

> 审计日期：2026-07-17
> 审计基线：`d5084f6c`
> 范围：应用设置、论坛与正文、漫画/图片阅读器、小说阅读器、公共书架、作品详情、编辑器，以及与个性化数据相邻的本地状态。

## 1. 结论摘要

当前个性化实现不是“完全没有持久化”，而是存在四种状态混在一起：

1. **设备级用户偏好**：主题、阅读器显示、默认打开方式等。它们规模固定、与具体作品无关，适合 `SharedPreferences`。
2. **业务个性化数据**：阅读进度、书签、自定义封面、分类、作品自定义元数据等。它们随作品增长，需要查询、关联和级联删除，适合 SQLite 与受保护文件缓存。
3. **会话/导航状态**：搜索词、弹窗开关、当前缩放、菜单是否展开等。通常只应留在内存。
4. **技术运行状态**：Cookie、搜索冷却时间、缓存维护时间戳、草稿快照等。它们不全是个性化设置，应使用各自的安全或结构化存储策略。

主要问题如下：

- 公共书架只持久化了“网格/列表、网格列数”，但**排序、筛选、上次分类均未持久化**。页面销毁后会恢复模块默认值。
- 书架显示设置、小说阅读显示设置、小说章节打开方式被放进 SQLite；这些都是固定规模的设备偏好，职责上更适合 `SharedPreferences`。
- 原生正文排版存在 `thread_text_*` 与 `forum_html_reader_*` 两套 SharedPreferences。生产正文使用后者，前者已基本成为孤立实现。
- `thread_detail_html_first_render_mode` 仍会读写，默认还是 `legacy`，但生产帖子详情已固定使用 HTML-first。这是**无效持久化状态**。
- 漫画网格列数同时存在旧 `settings.grid_column_count` 和新 `library_display_settings`。当新值恰好为 `3` 时还会回读旧值，无法区分“用户明确选择 3”和“新表没有有效配置”。
- 小说阅读器在 SQLite 中保存 13 个字段，但当前设置 UI 只开放其中 4 类；分页模式又被运行时强制为竖向，存在“已存但无效”和“已存但无法设置”的字段。
- `AppStorageKeys.imageCacheCustomDirectory` 没有消费者；图片缓存仍读取旧 `comic_cache_dir`，下载目录读取 `download_storage_dir`，命名和产品语义已经漂移。
- 草稿 JSON 与附件索引目前放在 SharedPreferences。草稿属于可增长、结构化数据，长期看应迁移到 SQLite；这与“设备偏好应移出 SQLite”是两个方向相反但同样必要的整理。
- 最近表情分组偏好只接入了旧/源码 `StickerPickerSheet`；新 Quill 内嵌表情面板固定从第 0 组打开，既不读取也不回写 `reply_sticker_last_group_id`。

## 2. 存储介质判定规则

| 状态性质 | 推荐介质 | 典型示例 |
| --- | --- | --- |
| 固定规模、设备级、只需要按 key 读取 | SharedPreferences | 主题、阅读模式、书架排序、默认章节打开方式 |
| 与账号强绑定且包含敏感凭据 | 平台安全存储 | 登录令牌、长期 Cookie（当前不在本轮改造范围） |
| 随作品/章节增长，需要条件查询或事务 | SQLite | 阅读进度、书签、分类、自定义元数据 |
| 大文件或二进制内容 | 文件系统 + SQLite 元数据 | 自定义封面、图片缓存、下载内容 |
| 临时页面交互 | 内存状态 | 搜索词、当前弹窗、展开状态、选择模式 |

判断重点不是“数据是否需要保留”，而是：

- 是否固定规模；
- 是否与具体业务实体关联；
- 是否需要查询、排序、事务或级联清理；
- 是否敏感；
- 是否会增长到不适合 key-value 存储。

### 2.1 已确认的目标默认值

以下值是后续个性化收口必须采用的**目标默认值**。迁移实现不得把它们与当前代码默认值混淆：

| 偏好 | 当前代码默认值 | 目标默认值 |
| --- | --- | --- |
| 原生 HTML 正文字号缩放 | `1.0` | `1.15` |
| 漫画与公共图片阅读模式 | `vertical` | `ltr` |
| 漫画与公共图片页间距 | `8` | `0` |
| 小说阅读器字号 | `18` | `18.5` |
| 小说阅读器行高/间隔 | `1.8` | `1.6` |
| 小说阅读器主题 | `light` | `sepia`（护眼） |

默认值变更只影响“从未保存过该偏好”的用户。已有合法用户值应继续优先，不得在升级时被新默认值覆盖。应用目前尚未发布时可以不迁移历史开发数据，但 repository 和 codec 仍应遵循这一优先级，避免以后发布后再次返工。

这组状态的领域边界和介质选择是当前最清晰的一组：共享不可变模型、repository、Riverpod controller 和 SharedPreferences 实现已经分离。后续只需把 key 纳入统一注册表，并补充保存失败回滚策略。

### 3.4 数据与存储

| 设置 | 当前 key | 默认值 | 评价 |
| --- | --- | --- | --- |
| 图片磁盘缓存上限 | `image_cache_max_bytes` | `512 MiB` | SharedPreferences 正确；归一化范围 `128..2048 MiB` |
| 自定义下载根目录 | `download_storage_dir` | `null`，使用平台默认目录 | SharedPreferences 正确 |
| 旧漫画/图片缓存根目录 | `comic_cache_dir` | `null`，使用临时目录 | 兼容遗留 key，无当前设置入口 |
| 新图片缓存目录 key | `image_cache_custom_dir` | 无 | 已声明但完全未使用 |

当前“数据与存储”页面设置的是**下载根目录**，并不会改动图片缓存根目录。图片缓存 resolver 仍读取旧 `comic_cache_dir`：

- 通用图片缓存使用 `<base>/y300_image_cache`；
- 旧漫画缓存使用 `<base>/y300_comic_cache`；
- 没有旧 key 时，两者都以系统临时目录为 base。

应明确产品语义：若只允许自定义下载位置，就删除未使用的 `image_cache_custom_dir`；若也允许自定义图片缓存位置，则增加独立设置，并迁移 `comic_cache_dir`，不要让“下载位置”隐式控制缓存。

### 3.5 编辑器便利状态

| 设置/状态 | 当前 key 或载体 | 默认值 | 评价 |
| --- | --- | --- | --- |
| 最近使用的表情分组 | `reply_sticker_last_group_id` | `null`，回退到首个分组 | 存储介质正确，但新 Quill 编辑器未接入 |
| 发帖/回复草稿 | `reply_draft.<identity>` JSON | 无草稿 | 不是偏好；SharedPreferences 不适合长期承载可增长草稿 |

草稿快照中还会保存正文、标题、附件、签名开关和发帖选项。这些值是“某一份草稿的数据”，不应拆成全局偏好覆盖草稿；但可额外建立“新草稿默认值”，例如默认使用签名、默认编辑器模式。

最近表情分组的现状已经确认：

- `StickerPickerSheet` 会通过 `stickerPickerLastGroupIdProvider` 读取上次分组，并在切换 Tab 时调用 `saveLastGroupId()`；
- 新 Quill 编辑器的内嵌 `_StickerPanel` 只创建 `DefaultTabController(length: groups.length)`，没有传 `initialIndex`，也没有监听 Tab 变化；
- 因此新编辑器每次都从第 0 组开始，用户在其中切换分组也不会更新偏好。

最佳修复方向不是在 Quill Widget 内直接访问 SharedPreferences，而是让共享表情面板接收 `initialGroupId` 与 `onGroupChanged`，由 composer provider/controller 负责加载和保存。源码与 Quill 两个入口必须复用同一偏好合同和同一组行为测试。

## 4. 已持久化在 SQLite 的个性化状态

### 4.1 公共书架显示方式

表：`library_display_settings`

| 模块 | 默认显示 | 默认列数 | 当前存储 |
| --- | --- | --- | --- |
| 漫画 | `grid` | `3` | SQLite，按 `module_key=comic` |
| 小说 | `list` | `3` | SQLite，按 `module_key=novel` |
| 收藏 | `list` | `3` | SQLite，按 `module_key=favorite` |

UI 允许网格列数 `1..10`。这是固定三行以内的设备显示偏好，不需要 SQL 查询、事务或外键，建议迁移到 SharedPreferences。

漫画还保留旧 `settings` 表中的 `grid_column_count=3`。`ComicShelfAdapter.loadDisplayPreference()` 在新表列数等于 `3` 时回读旧值，这会造成：

- 新表不存在和用户明确选择 3 无法区分；
- 旧值可能覆盖用户刚选择的 3；
- 两份数据长期不能自然收敛。

迁移后应只保留一个模块化书架偏好快照，不再用“值等于默认值”判断是否需要 fallback。

### 4.3 小说章节打开方式

`settings.novel_chapter_open_mode`：

- 默认：`reader`；
- 可选：`reader` / `sourcePost`；
- 设置入口：小说详情页章节打开模式；
- 当前实现：`SqfliteNovelInteractionPreferencesRepository`。

它是单个设备级枚举偏好，建议迁移到 SharedPreferences，并保留现有领域 repository 接口，避免 UI 直接依赖存储实现。

## 5. 当前未持久化、但逻辑上应持久化的状态

### 5.1 P0：公共书架查询偏好

`UnifiedShelfController` 每次创建都会重新生成以下状态：

| 状态 | 当前默认值 | 页面销毁后 | 建议 |
| --- | --- | --- | --- |
| 排序字段与方向 | 见下表 | 丢失 | 按模块持久化 |
| 筛选条件 | 全部 `ignore` | 丢失 | 按模块持久化，并保留明显的激活摘要 |
| 上次选择分类 | `default`，不可见时取首个分类 | 丢失 | 按模块保存 categoryId，加载后校验存在性 |
| 搜索模式与关键词 | 关闭、空字符串 | 丢失 | 保持临时，不持久化 |

当前模块默认排序：

| 模块 | 默认字段 | 默认方向 | 实际含义 |
| --- | --- | --- | --- |
| 漫画 | 收藏日期 | `asc`（上箭头） | 较早收藏在前 |
| 小说 | 收藏日期 | `asc`（上箭头） | 较早收藏在前 |
| 收藏 | 收藏日期 | `desc`（下箭头） | 最新收藏在前 |

建议使用一个模块级快照一次保存，避免筛选、排序和分类分别写多个互相不一致的 key：

```dart
class LibraryShelfViewPreferences {
  final LibraryModuleKey moduleKey;
  final LibraryShelfSortOption sortOption;
  final LibraryFilterSet filters;
  final LibraryDisplayMode displayMode;
  final int gridColumnCount;
  final String? lastCategoryId;
}
```

SharedPreferences 可按 `library.shelf.<module>.v1` 保存 JSON。加载时必须经过模块 capability 归一化，例如小说不得恢复旧的 unread 排序或 read/unread 筛选。

### 5.2 P1：作品详情章节排序

`UnifiedDetailState` 当前固定从以下值开始：

- 章节排序：`asc`；
- 章节筛选：全部 `ignore`；
- 漫画按来源 TID、小说按来源 PID 排序。

建议只持久化**模块级章节排序方向**。章节筛选（已下载、未读、有书签）更像当前任务上下文，持久化后容易造成“重新进入详情却看不到章节”的困惑，建议继续保持临时，除非未来 UI 提供明确的“记住筛选”选项。

### 5.3 P1：编辑器默认行为

当前发帖和回复页面每次都以 Quill 可视编辑表面打开；页面内切换到源码只存在于 Widget 私有状态。与此同时，旧 `ComposerEditorMode` 仍定义为 `source/preview` 并进入草稿状态，但它已经不能准确表达当前 `quill/source` 两种编辑表面。

建议：

- 新建 `ComposerSurfacePreference { quill, source }`；
- 作为全局或按“发帖/回复”区分的 SharedPreferences 偏好；
- 默认保持当前产品行为 `quill`；
- 草稿保存内容与附件，不再用旧 `source/preview` 字段表达 UI 表面；
- “使用个人签名”继续写入具体草稿，同时增加一个“新草稿默认使用签名”的设备偏好，默认 `true`。

发帖中的 `allowNoticeAuthor=false`、`bbCodeOff=false`、`smileyOff=false`、`parseUrlOff=false`、标签空、普通帖等应继续视为草稿级业务参数，不应无条件变成全局偏好。

### 5.4 可选：主导航恢复

主壳默认 Tab 为索引 `0`（论坛），当前不持久化。它属于导航恢复而非设置：

- 若产品希望每次冷启动都回到论坛，保持现状；
- 若希望恢复上次位置，可只保存 `LibraryModuleKey/route id`，不要保存易受导航项增删影响的裸索引。

本项优先级低于书架排序，不建议与首轮偏好迁移混做。

## 6. 已正确放在 SQLite/文件中的业务个性化数据

以下状态虽然由用户产生，但**不应迁移到 SharedPreferences**：

| 数据 | 默认状态 | 当前介质 | 原因 |
| --- | --- | --- | --- |
| 漫画/小说阅读进度 | 无记录；首次读取从 0 开始 | SQLite | 按作品/章节增长并需排序、恢复 |
| 章节书签与小说位置书签 | 默认无书签 | SQLite | 关联作品和章节，需要查询 |
| 漫画已读/下载状态 | 默认 `false` | SQLite | 章节级业务状态；小说已不使用未读语义 |
| 自定义标题、作者、翻译者、搜索标题 | 默认 `null` | SQLite | 作品级元数据 |
| 自定义简介 | 默认无用户值，解析来源可补齐 | SQLite | 作品级数据，刷新时需保护用户值 |
| 自定义封面路径、来源、焦点 | 默认 `null`，视觉回退居中 | SQLite + protected 文件 | 文件与作品生命周期绑定 |
| 小说取消封面 | `cover_hidden=0` | SQLite | 作品级显式覆盖 |
| 自定义目录 URL | 默认 `null`，回退来源目录 | SQLite | 作品级刷新策略配置 |
| 漫画/小说书架分类、成员关系、顺序 | 默认分类 + 作品关系 | SQLite | 可增长并需要事务 |
| 浏览记录 | 默认空 | 独立 history SQLite | 分页、去重、保留策略和删除都需要查询 |
| 收藏同步快照与无效分类 | 默认由同步创建 | SQLite | 服务端镜像/业务数据，不是偏好 |
| 图片缓存与封面缓存元数据 | 默认无缓存 | SQLite + 文件 | 需要容量核算、淘汰和 owner 关联 |

## 7. 不属于个性化设置，但应单独治理的状态

| 状态 | 当前介质 | 建议 |
| --- | --- | --- |
| 网络 Cookie JSON | SharedPreferences `network.cookies.v1` | 不纳入普通偏好仓储；后续评估平台安全存储与账号隔离 |
| 搜索冷却时间 | SharedPreferences `search.last_search_at_ms` | 属于运行治理状态，可保留，但不应出现在“恢复默认设置”中 |
| 发帖/回复草稿 JSON | SharedPreferences `reply_draft.*` | 迁移到 SQLite 草稿表；附件仍走文件系统 |
| 页面搜索词、加载状态、错误提示 | 内存 | 保持临时 |
| 阅读器菜单可见、当前缩放、双指手势状态 | 内存 | 保持临时 |
| 简介展开状态 | 内存，默认收起 | 保持临时 |
| 详情页当前滚动位置 | Flutter 页面栈 | 不作为全局偏好；阅读器进度由专用表负责 |

## 8. 目标架构建议

不要建立一个知道所有模块字段的巨大 `SettingsManager`。建议保留模块边界，在 data 层共享一个小型 key-value 基础设施：

```text
SharedPreferencesAsync / PreferencesStore
  ├─ AppAppearancePreferencesRepository
  ├─ ForumPreferencesRepository
  ├─ ForumReaderPreferencesRepository
  ├─ ImageReaderPreferencesRepository
  ├─ NovelReaderPreferencesRepository
  ├─ LibraryViewPreferencesRepository
  ├─ ComposerPreferencesRepository
  └─ DiagnosticPreferencesRepository
```

原则：

1. Domain/presentation 只依赖具体小型 repository 接口，不依赖 `SharedPreferences`。
2. key 统一放入注册表并使用版本化命名，如 `reader.image.v1`、`library.shelf.comic.v1`。
3. 多字段偏好优先保存一个 JSON 快照，保证一次读取获得一致配置。
4. enum 保存稳定字符串，不保存 ordinal；未知值必须回退默认并通过 capability 归一化。
5. repository 接受可注入的 preference client，避免每个方法重复 `SharedPreferences.getInstance()`，也方便测试。
6. 使用当前依赖 `shared_preferences 2.5.5` 时可评估 `SharedPreferencesAsync`，避免 singleton cache 在多 isolate/原生侧写入时产生陈旧读；本项目即使暂时单 isolate，也能获得更清晰的依赖注入边界。
7. “恢复默认”按领域执行，不应顺带删除账号、草稿、书签、历史或作品自定义数据。
8. 保存失败时统一采用 optimistic update + rollback + transient feedback，避免各 controller 行为不一致。

## 9. 建议的迁移顺序

### Phase 0：建立基线

- 为本文所有有效偏好补默认值与 codec 测试。
- 将目标默认值锁定为：原生 HTML 字号 `1.15`；图片阅读 LTR、页间距 `0`；小说字号 `18.5`、行高 `1.6`、护眼主题。
- 固化当前 SharedPreferences key、SQLite fallback 和模块默认排序。
- 明确“恢复默认设置”只覆盖哪些偏好域。

### Phase 1：统一偏好基础设施

- 建立可注入 `PreferencesStore` 与集中 key 注册表。
- 保持现有各领域 repository 接口，不让页面直接操作 key。
- 为 JSON 快照增加 schema version、容错和归一化。
- 将共享图片阅读偏好的缺省解析改为 `readerMode=ltr`、`pageSpacing=0`，并验证漫画和公共图片阅读器使用同一默认快照。

### Phase 2：收口公共书架

- 新增 `LibraryViewPreferencesRepository`。
- 同时持久化显示方式、列数、排序、筛选和上次分类。
- 从 `library_display_settings` 与旧 `settings.grid_column_count` 一次性迁移。
- 读取优先级：新 SharedPreferences -> 新 SQLite 行 -> 旧 comic setting -> 模块默认。
- 成功写入新值后记录迁移版本；稳定一个版本后删除旧 fallback，不能永久双读。

### Phase 3：迁移小说设备偏好

- 将 `NovelReaderPreferences` 从 `NovelRepository` 拆出。
- 将小说阅读显示和章节打开方式迁移到 SharedPreferences。
- 新偏好不存在时使用字号 `18.5`、行高 `1.6`、`sepia` 主题；存在合法旧值时不得覆盖。
- 明确保留字段：当前 UI 支持且真实生效的字段。
- 对分页、章节标题等已失效字段停止持久化；未来功能恢复时以新 schema 引入，不复活旧含义。

### Phase 4：清理正文偏好

- 以 `ForumHtmlReaderPreferences` 为唯一正文偏好。
- 将生产正文无持久化值时的字号缩放改为 `1.15`，设置抽屉的“恢复默认”也必须回到 `1.15`。
- 仅在新 key 缺失时读取一次旧 `thread_text_*`。
- 删除孤立 `ThreadTextPreferences`、旧设置 sheet 和无效 render-mode repository。
- 决定段间距、简繁转换是否正式暴露；不暴露的字段要么成为明确内部默认，要么从可持久化模型移除。

### Phase 5：编辑器与草稿分层

- 新增 Quill/源码默认表面偏好和新草稿签名默认值。
- 保持每份草稿自己的业务开关。
- 让 Quill 与源码表情面板共同读取、更新最近表情分组；以稳定 groupId 恢复，分组不存在时回退首组。
- 将可增长草稿快照迁移到 SQLite，SharedPreferences 只保留固定规模编辑器偏好和最近表情分组。

### Phase 6：清理技术 key

- 删除未使用的 `image_cache_custom_dir` 或补齐独立产品入口。
- 明确 `comic_cache_dir` 的一次性迁移与退场时间。
- Release 强制忽略 Debug 诊断偏好。
- 将 Cookie、安全凭据和搜索限流状态从普通个性化重置流程中隔离。

## 10. Review 检查清单

- 冷启动后漫画、小说、收藏各自恢复上次显示、排序、筛选与有效分类。
- 漫画/小说升序收藏日期与收藏页降序默认不会在迁移中被统一覆盖。
- 小说不恢复已经移除的未读筛选；模块 capability 能清洗旧值。
- 用户明确选择网格 3 列后不会被旧 comic setting 覆盖。
- 小说显示偏好迁移后不再打开业务 SQLite 才能读取设备设置。
- 原生正文只有一套字号/行高 key，旧值只迁移一次。
- 无已保存值时原生 HTML 正文使用 115% 字号，图片阅读器使用 LTR 且页间距为 0。
- 无已保存值时小说阅读器使用 18.5 字号、1.6 行高和护眼主题。
- Quill 与源码编辑器都能恢复并更新同一个最近表情分组。
- Release 不会因为 Debug 安装留下的 key 自动开启诊断日志。
- “恢复默认设置”不会删除阅读进度、书签、历史、草稿、分类、自定义封面或作品元数据。
- 清除作品/取消收藏仍能按现有业务规则清理关联 SQLite 数据和文件，不受偏好迁移影响。
- 小说解析网络继续固定使用 `version=1`；本次个性化收口不得触碰小说请求与解析链路。
