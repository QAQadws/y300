# Y300 漫画模块分阶段实现方案（基于现有架构）

> 适用代码基线：`lib/` 当前 Riverpod + Repository + Model 架构
> 当前状态：帖子详情 `ThreadDetailPage` 使用 `Html(data: post.message)` 直接渲染，尚未做漫画语义解析与书架域建模。

## 1. 目标与边界

### 1.1 业务目标
- 在保留现有“首页/论坛/帖子”能力不受影响的前提下，新增独立“漫画”Tab。
- 自动识别论坛帖子中的“漫画候选内容”（重点 `fid=30`，但规则可扩展）。
- 在帖子详情页提供“加入书架”入口。
- 漫画模块支持：
  - 书架网格展示
  - 分类（默认 + 自定义）
  - 漫画详情（封面、标题、作者、话列表倒序）
  - 章节阅读（长图纵向阅读）
- 增加本地缓存与索引，降低对论坛服务器压力。

### 1.2 本期不做（后续阶段）
- 云同步（多设备同步）
- 复杂推荐算法
- 离线全文检索
- 多源站点聚合

## 2. 现状分析（与你当前代码对齐）

### 2.1 可复用能力
- 网络层：`core/network/api_client.dart` 已完成 Discuz API 请求与解析模板。
- 帖子详情：`features/thread/data/thread_repository.dart` + `thread_detail_models.dart` 已可拿到 `fid/tid/postlist/message`。
- 状态管理：`flutter_riverpod` 已建立 Controller/State 模式。
- HTML 渲染：已引入 `flutter_html`。

### 2.2 当前痛点

- 没有“漫画领域模型”（Comic / Episode / ShelfCategory / ShelfItem）。
- 没有本地持久化层来支撑书架和缓存索引。

### 3.2 数据流
1. 进入帖子详情 -> 拿到首楼 `message` 与 `subject/fid/tid`。
2. `ComicDetector` 判断是否“漫画候选”。
3. 候选则 `ComicParserService` 提取：
   - 图片列表（当前话）
   - 章节链接列表（如 01、2.1、2.2）
   - 封面候选图（默认第一张）
   - 作者/翻译组线索（可选）
4. 用户点击“加入书架” -> 持久化 `Comic + Episodes + ShelfMapping`。
5. 书架页读取本地库，展示网格。
6. 点开漫画后读取章节；点开章节加载图片并缓存。

## 4. 漫画识别与解析策略

### 4.1 识别策略（多信号评分，避免误判）

建议建立 `ComicDetectScore`，满足阈值即判定漫画：

- 强信号：
  - `fid == "30"`：+40
  - 首楼 message 内 `<img` 数量 >= 2：+35
  - `subject` 包含关键词（例：`第xx话`、`汉化`、`[组]`）：+20
- 弱信号：
  - message 内存在同主题章节链接（`thread-xxxxx-1-1.html` 多个）：+15
  - message 文本含“目录/图源/嵌字/校对”等：+10

阈值建议：`>= 60` 判定漫画。

> 注意：不要只靠 `fid=30`，否则普通图文帖会混入。

### 4.2 HTML 解析策略

不要从 UI 的 `Html()` 组件反向拿数据，应新增解析器直接处理原始 `message` 字符串：

- 输入：`message`（服务端原始 HTML）
- 输出：`ParsedComicPost`
  - `List<String> imageUrls`
  - `List<ComicEpisodeLink> episodeLinks`
  - `String? catalogUrl`
  - `String? inferredAuthor`
  - `String plainTextSummary`

实现建议：
- 用 `html` 包解析 DOM。
- 提取所有 `img[src]`，去重、过滤表情/小图标。
- 提取 `a[href]`，过滤非 thread 链接。
- 对链接文字做章节编号正则提取（`^\d+(\.\d+)?$`、`第.+话`）。

## 6. 缓存策略设计

### 6.1 缓存目标
- 减少重复请求首楼和章节图片。
- 阅读页滚动稳定，弱网可继续看。

### 6.2 缓存分层
- 元数据缓存（DB）：漫画、章节、图片索引。
- 图片文件缓存（磁盘）：依赖图片缓存库 + 可选手动预下载。

### 6.3 缓存键
- 图片：以 `imageUrl` 的 hash 作为 key。
- 章节：`episodeId`。
- 漫画：`comicId`。

### 6.4 失效策略
- 元数据：按“主动刷新”更新，不做强时效过期。
- 图片：LRU + 最大容量限制（如 2GB，可配置）。

## 10. 关键实现细节建议

### 10.1 章节链接规范化
对 `a[href]` 提取出的 URL 做标准化：
- `https://bbs.yamibo.com/thread-xxx-1-1.html`
- 去掉跟踪参数
- 解析得到 `tid`

### 10.2 标题清洗
`subject` 可能包含前缀如 `【萌木汉化组】...`，建议保存两份：
- `rawTitle`：原始
- `displayTitle`：清洗后（可配置规则）

### 10.3 防重复添加
`comicId` 唯一约束；重复点击“加入书架”时幂等处理。

### 10.4 容错
解析失败时：
- 不影响帖子原文渲染
- 只隐藏漫画入口并记录日志

## 11. 风险与规避

- 风险：仅靠 `fid=30` 误判较高
  - 规避：评分模型 + 可手动纠正（“仍然加入书架”）
- 风险：大图过多导致内存抖动
  - 规避：分辨率限制、分页加载、缓存上限
- 风险：帖子 HTML 格式不统一
  - 规避：Parser 做多规则兜底，保留 raw 字段方便调试
