# 分阶段实现 05：下载存储结构

本阶段目标是实现“存储”和“缓存”的分离。存储代表用户主动下载、可长期保留、可迁移备份的数据；缓存代表 App 为了加速浏览自动保存、可被清理的数据。

## 目标

1. 新增独立的下载存储根目录。
2. 存储根目录至少包含：
   - `comics/`
   - `novels/`
   - `favorites.json`
   - `.nomedia`
3. 漫画下载为：
   - `meta.json`
   - `cover.jpg`
   - 多个 `.cbz`
4. CBZ 解压后图片命名为：
   - `001.jpg`
   - `002.jpg`
   - ...
5. 小说下载为结构化本地文件，支持封面、正文、插图。
6. 阅读优先级：
   - 下载存储
   - 图片/正文缓存
   - 网络

## 默认存储位置

用户希望 Android 默认：

```text
/storage/emulated/0/Android/media/<包名>/
```

建议实现为平台分支：

```text
Android: /storage/emulated/0/Android/media/<packageName>/Y300
iOS: getApplicationDocumentsDirectory()/Y300
desktop: getApplicationDocumentsDirectory()/Y300
```

注意：

- Android 上获取 `<packageName>` 可能需要新增 `package_info_plus` 依赖。
- 如果不能稳定写入 Android media 目录，则降级到 `getExternalStorageDirectory()` 或应用文档目录，并在 UI 中显示实际路径。
- iOS 没有 Android media 目录概念，使用 App Documents 或 Application Support。

无论平台如何，根目录创建后都写入：

```text
.nomedia
```

Android 相册不会扫描该目录。

## 目录结构

### 根目录

```text
<storageRoot>/
  .nomedia
  favorites.json
  comics/
    .nomedia
  novels/
    .nomedia
```

`favorites.json` 保存收藏模块已经解析出的全部 tid 和对应 fid/tag/typeid，减少重复进帖。

### 漫画目录

```text
<storageRoot>/comics/<safeComicName>/
  .nomedia
  meta.json
  cover.jpg
  001-第一话.cbz
  002-第二话.cbz
  003-特典.cbz
```

`safeComicName` 是清洗后的作品名：

- 去掉 Windows/Android 不安全字符：`\/:*?"<>|`
- 去掉尾部空格和点。
- 太长时截断，并追加短 hash，避免重名。

CBZ 文件名同样需要清洗。

### 漫画 CBZ 内容

每个 `.cbz` 是 zip 文件，内部：

```text
001.jpg
002.jpg
003.jpg
...
```

图片扩展名按实际 mime 选择：

- `image/jpeg` => `.jpg`
- `image/png` => `.png`
- `image/webp` => `.webp`

如果无法识别，默认 `.jpg`。

## 漫画 meta.json

建议 schema：

```json
{
  "schemaVersion": 1,
  "contentType": "comic",
  "workId": "yamibo:536398",
  "sourceTid": "536398",
  "sourceFid": "30",
  "sourceTypeId": "398",
  "sourceTagName": "韩国漫画",
  "title": "作品名",
  "author": "作者",
  "translationGroup": "汉化组",
  "intro": "简介",
  "coverFile": "cover.jpg",
  "customCoverFile": null,
  "favorite": {
    "favid": "2580579",
    "dateline": 1778062815
  },
  "tags": {
    "source": {
      "typeid": "398",
      "name": "韩国漫画"
    },
    "custom": [
      { "tagId": "tag_1", "name": "待读" }
    ]
  },
  "chapters": [
    {
      "episodeId": "yamibo:536398:536398",
      "sourceTid": "536398",
      "title": "第一话",
      "orderIndex": 0,
      "cbzFile": "001-第一话.cbz",
      "imageCount": 24,
      "imageFiles": [
        "001.jpg",
        "002.jpg"
      ]
    }
  ],
  "updatedAt": "2026-05-08T00:00:00.000Z"
}
```

关键要求：

- `chapters` 数组就是排序来源。
- 不要依赖文件系统排序。
- `cbzFile` 必须和章节一一对应。
- `imageFiles` 可选，但有助于校验和恢复。

## 小说目录

小说情况复杂：可能无封面、有封面、有插图、章节在同一个 tid 的不同楼层。建议先使用 App 自己容易恢复的结构：

```text
<storageRoot>/novels/<safeNovelName>/
  .nomedia
  meta.json
  cover.jpg
  chapters/
    001-序章.json
    002-第一章.json
  images/
    001/
      001.jpg
      002.jpg
    002/
      001.jpg
```

章节 JSON 保存：

```json
{
  "episodeId": "novel:49:551089:123456",
  "sourceTid": "551089",
  "sourcePid": "123456",
  "sourcePage": 1,
  "title": "第一章",
  "orderIndex": 1,
  "rawHtml": "...",
  "plainText": "...",
  "paragraphs": [
    "第一段",
    "第二段"
  ],
  "images": [
    {
      "index": 0,
      "file": "../images/002/001.jpg",
      "sourceUrl": "https://..."
    }
  ]
}
```

后续如果要导出 epub，可以基于这个结构生成，而不是一开始就把内部存储绑定到 epub。

## favorites.json

存储根目录下：

```text
<storageRoot>/favorites.json
```

建议 schema：

```json
{
  "schemaVersion": 1,
  "remoteCount": 147,
  "syncedAt": "2026-05-08T00:00:00.000Z",
  "threads": [
    {
      "tid": "536398",
      "favid": "2580579",
      "title": "标题",
      "author": "作者",
      "fid": "30",
      "typeid": "398",
      "tagName": "韩国漫画",
      "contentKind": "comic",
      "workId": "yamibo:536398",
      "removed": false,
      "dateline": 1778062815
    }
  ]
}
```

用途：

- 给用户存储目录一个可读的收藏索引。
- App 重装或迁移存储目录时，可以用它恢复部分收藏元信息。
- 减少重复进帖补全 `fid/tag`。

SQLite 仍是 App 内主索引；`favorites.json` 是存储目录中的同步快照。

## 下载服务设计

新增：

```text
lib/features/storage/data/storage_location_repository.dart
lib/features/storage/domain/download_storage_service.dart
lib/features/comic/data/comic_download_service.dart
lib/features/novel/data/novel_download_service.dart
```

### DownloadStorageService

职责：

- 解析当前存储根目录。
- 创建 `.nomedia`。
- 生成安全文件名。
- 原子写入 `meta.json`。
- 提供读取优先级检查。

### ComicDownloadService

下载单章流程：

1. 读取 `ComicEpisodeItem`。
2. 确保图片列表存在。
3. 对每张图片：
   - 优先使用下载存储已有文件。
   - 其次使用缓存本地文件。
   - 否则从网络下载并写入缓存。
4. 复制或写入临时目录：
   - `001.jpg`
   - `002.jpg`
5. 用 `archive` 包生成 `.cbz`。
6. 更新 `meta.json`。
7. 标记 `library_episode_state.isDownloaded=true`。

下载全部章节：

- 顺序下载，避免大量并发压垮网络和内存。
- 支持取消或失败重试。
- 单章失败不应破坏已下载章节。

### NovelDownloadService

下载小说流程：

1. 读取 `NovelItem` 和章节列表。
2. 对每章读取 `NovelChapterContent`。
3. 缓存/复制章节插图。
4. 写入 `chapters/*.json`。
5. 写入 `meta.json`。
6. 标记章节 downloaded。

## 读取优先级实现

### 漫画阅读器

当前 `ComicReaderController._ensureEpisodeImages` 只查 DB 和网络。

后续顺序：

1. `ComicDownloadService.findDownloadedEpisode(comicId, episodeId)`
   - 如果有 cbz，使用 cbz 内图片或解压到临时阅读目录。
2. `ImageCacheService.getCached(cacheKey)`
   - 如果本地图片存在，使用本地。
3. 网络拉取图片 URL 并缓存。

### 小说阅读器

当前 `LocalNovelRepository.getChapterContent` 查 DB。

后续顺序：

1. 下载存储章节 JSON。
2. SQLite 缓存正文。
3. 网络刷新帖子并写入缓存。

## 存储目录变更

当用户选择自定义存储目录：

1. 只改变后续下载位置。
2. 不自动移动旧目录，避免耗时和失败。
3. 可以后续增加“迁移已有下载”功能。
4. UI 提示当前路径。

恢复默认：

1. 设置路径回默认。
2. 创建默认目录和 `.nomedia`。
3. 不删除自定义目录旧文件。

## 测试建议

1. 漫画下载生成 `meta.json/cover.jpg/*.cbz`。
2. CBZ 解压后文件名为 `001.jpg`、`002.jpg`。
3. `meta.json.chapters` 顺序和详情页章节顺序一致。
4. 阅读已下载漫画时不请求网络。
5. 小说下载生成 `meta.json/chapters/*.json`。
6. 存储目录包含 `.nomedia`。
7. 清理图片缓存不会删除存储目录内容。
8. 自定义存储目录和恢复默认都只影响后续下载，不破坏旧文件。

## 完成标准

- 漫画可离线从 CBZ 阅读。
- 小说可离线从本地章节 JSON 阅读。
- 存储目录结构清晰，可被用户备份。
- 缓存清理和下载存储完全分离。
