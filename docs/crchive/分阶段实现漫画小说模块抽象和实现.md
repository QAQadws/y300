# 分阶段实现漫画小说模块抽象和实现

## 0. 文档目标与边界

本文档基于当前 `lib` 目录现状，给出一套可落地的“书架页 + detail 页通用抽象”实施方案，目标是同时支撑漫画和小说模块，并满足你提出的全部交互细节。

本方案默认：

1. 保持现有 `Riverpod + SQLite + Repository` 架构。
2. 优先增量重构，不做一次性推倒重写。
3. 先统一交互与数据模型，再逐步替换页面实现。
4. 所有新增文档/代码统一使用 UTF-8。

## 2. 目标抽象设计

## 2.1 书架抽象层

新增统一书架域（建议目录）：

`lib/features/library_shelf/`

建议拆分：

1. `domain/models/`：通用模型（分类、作品、筛选、排序、显示配置）。
2. `domain/contracts/`：模块适配接口（漫画/小说适配器）。
3. `presentation/pages/unified_shelf_page.dart`：统一书架页骨架。
4. `presentation/widgets/`：统一 `AppBar` 搜索模式、筛选面板、网格卡片、列表卡片。
5. `presentation/controllers/unified_shelf_controller.dart`：统一状态机。

### 2.1.1 模块适配接口（核心）

新增 `ShelfModuleAdapter`：

1. `moduleKey`：`comic` 或 `novel`
2. `moduleTitle`：`漫画` 或 `小说`
3. `defaultDisplayMode`：漫画=网格，小说=列表
4. `loadCategories()`
5. `loadItemsByCategory()`
6. `searchItems(keyword)`（作品名/作者/汉化组）
7. `refreshShelf()`
8. `openDetail(workId)`
9. `category CRUD` 与 `moveItem` 能力

这样统一页只管流程，漫画/小说只提供数据差异。

### 2.1.2 统一 AppBar 行为

满足你的交互：

1. 非搜索态：左侧文字标题（漫画/小说）；右侧 `search / filter_list / more_vert`。
2. 点击搜索后：
- `search` 图标消失。
- 左侧变返回箭头。
- 箭头与 `filter_list` 间变为输入框，placeholder 为 `搜索···`。
3. 搜索实时作用于 `GridView/ListView`。
4. 分类右侧显示当前搜索命中数。

### 2.1.3 分类导航与默认分类规则

通用规则实现（需在仓储层落实）：

1. 未分类作品全部归入 `default`。
2. 若 `default` 无作品且其他分类有作品，则 `default` 在 UI 隐藏。
3. 当有新作品未指定分类加入时，自动创建/恢复 `default`，并插入最左侧。
4. 分类 Tab 保持水平滑动（`TabBar + TabBarView` 或现有 `FixedSlotPagerHeader + PageView`）。

### 2.1.4 列表/网格两种展示

1. 网格：沿用漫画卡片风格，图片底部文字浮层，左上角未读数量圆角背景。
2. 列表：左侧圆角图，中间标题，右侧未读数量圆角背景。
3. 页面支持下拉刷新（`RefreshIndicator`）。

### 2.1.5 筛选面板（`filter_list`）

底部弹窗（带横向分类页签）：

1. `筛选`：三态复选（不筛选/包含/排除）
- 已下载
- 未读
- 阅读过
- 已添加标签
2. `排序`：升降箭头 + 选项
- 名称
- 章节数
- 最近阅读
- 检查更新时间
- 未读章节数
- 作品更新时间
- 章节获取时间
- 收藏日期
3. `显示`
- 显示方式：网格/列表
- 网格模式显示每行个数滑条（1~3）

### 2.1.6 更多菜单（`more_vert`）

1. 新建分类
2. 重命名当前分类
3. 删除当前分类
4. 分隔线
5. 更新书架
6. 随机打开作品

## 2.2 详情抽象层

新增统一详情域（建议目录）：

`lib/features/library_detail/`

建议拆分：

1. `presentation/pages/unified_detail_page.dart`
2. `presentation/widgets/detail_header.dart`
3. `presentation/widgets/detail_chapter_list.dart`
4. `presentation/controllers/unified_detail_controller.dart`
5. `domain/contracts/detail_module_adapter.dart`

### 2.2.1 通用头部与滚动行为

1. `AppBar` 初始透明，左返回，右侧 `file_download / filter_list / more_vert`。
2. 若存在封面图：顶部到封面结束区域使用封面中部裁切的横向模糊背景。
3. 背景叠加自上而下渐隐到页面底色。
4. 滚动时整个 body 上移；标题区离开后 `AppBar` 变实体。
5. 实体 `AppBar` 中间显示作品名，超长 `···`。

### 2.2.2 头部信息区

1. 左上作品图（漫画默认首话首图；小说可为空兜底）。
2. 右侧作品名。
3. 漫画：`group_outlined + 汉化组`。
4. 小说：`person_outlined + 作者`。
5. 横向按钮：
- 在书架中/添加到书架（`favorite_border` / `favorite`，长按可选分类）
- 更新
- 原帖（跳转 thread）

### 2.2.3 简介与标签

1. 简介支持 `Truncated Text with Expand/Collapse`，并移除无效跳转片段。
2. 标签预留接口，横向中空方框样式。

### 2.2.4 章节列表

1. 左侧标题（漫画/小说分别由解析结果提供，不强制统一文案格式）。
2. 次行淡字：发布日期 + tid。
3. 右侧同位状态图标：下载 `arrow_circle_down` / 已下载 `check_circle_outline`。
4. 阅读完成后列表项整体稍微变淡。
5. 长按章节弹出底部按钮：
- `bookmark_add_outlined`：该章节加书签（标题右侧显示 `bookmark`）
- `remove_done`：取消全部阅读完成
- `delete_outline`：删除该章节下载数据

### 2.2.5 详情页菜单与筛选

1. 下载菜单（`file_download`）：`未读`、`全部`。
2. 章节筛选（`filter_list`）：
- 筛选：已下载、未读、已添加书签
- 排序：按章节编号、按日期、按名称、按 tid
3. 更多菜单（`more_vert`）：
- 刷新
- 修改分类
- 编辑简介
- 添加标签
- 移除标签

### 2.2.6 右下角浮动按钮

1. 文案 `开始` 或 `继续`。
2. 点击进入对应章节阅读器。

## 3. 数据与存储改造设计（支撑上述交互的关键）

当前数据库 `lib/features/comic/data/local/comic_local_db.dart` 已包含漫画与小说基础表，但缺少统一状态表。建议新增以下表（使用 `content_type` 区分漫画/小说）：

## 3.1 新增表

1. `library_work_state`
- `content_type` (`comic`/`novel`)
- `work_id`
- `last_read_episode_id`
- `last_read_at`
- `check_updated_at`
- `fetched_updated_at`
- `intro_text`
- `created_at`
- `updated_at`
- 主键：`(content_type, work_id)`

2. `library_episode_state`
- `content_type`
- `episode_id`
- `work_id`
- `is_read` (0/1)
- `is_downloaded` (0/1)
- `is_bookmarked` (0/1)
- `read_at`
- `downloaded_at`
- 主键：`(content_type, episode_id)`

3. `library_tags`
- `tag_id`
- `name`
- `created_at`

4. `library_work_tags`
- `content_type`
- `work_id`
- `tag_id`
- 唯一键：`(content_type, work_id, tag_id)`

5. `library_display_settings`
- `module_key` (`comic`/`novel`)
- `display_mode` (`grid`/`list`)
- `grid_columns` (1~3)
- `updated_at`

## 3.2 迁移策略

1. 不迁移/替换原漫画与小说主表，先增量加状态表。
2. 首次迁移后做一次回填：
- `is_read` 默认 0
- `is_downloaded` 依据现有缓存状态推断（漫画可从 `episode_images.cache_status` 聚合）
3. 所有新增 SQL 放入 `ComicLocalDb.onUpgrade` 新版本分支。

## 3.3 查询接口扩展

在 `ComicRepository`、`NovelRepository` 或新 `LibraryRepository` 增加：

1. 统计未读章节数
2. 统计分类命中数（搜索态）
3. 三态筛选查询
4. 多字段排序
5. 章节状态写入（读完/下载/书签）
6. 标签增删与按标签筛选

## 7. 关键工程决策与注意事项

## 7.1 为什么不直接重写漫画/小说仓储

1. 当前漫画与小说存储结构不同，强行一次性统一风险高。
2. 先在上层做 adapter + 通用状态表，能最快达成业务目标。
3. 后续再考虑把漫画迁移到 `works/work_episodes` 统一表。

## 7.2 默认分类规则落地建议

1. DB 层允许 `default` 不存在。
2. 新增未分类入架时自动 `ensureDefaultCategory()`。
3. 每次刷新分类时执行 `hideDefaultIfEmptyAndOthersNonEmpty()`。

## 7.3 搜索字段建议

书架搜索关键字统一命中：

1. 作品名称
2. 作者
3. 汉化组

实现方式建议：

1. SQL 层 `LIKE` + 小写标准化。
2. 关键词分词后 `AND` 匹配。

## 7.4 下载状态定义建议

1. 漫画：章节所有图片均 `cache_status=done` 视为已下载。
2. 小说：章节正文已落地到本地内容表视为已下载。

## 7.5 已读状态定义建议

1. 阅读器退出或切章时写入 `is_read=1`（可配置阈值，如阅读超过 80%）。
2. 手动“取消已读”只改状态，不删阅读进度。

## 9. 风险与缓解

1. 风险：DB 迁移影响旧用户数据。
- 缓解：迁移前后做校验脚本；灰度开关控制新状态逻辑。

2. 风险：统一 UI 后出现模块行为回归。
- 缓解：adapter 合同测试 + 双模块快照对比。

3. 风险：筛选排序 SQL 复杂导致性能下降。
- 缓解：补充索引、分页加载、必要时内存二次过滤。

4. 风险：封面模糊头图在低端机掉帧。
- 缓解：缓存处理后的背景图，滚动区减少重绘。

---

## 10. 推荐实施顺序（最稳妥）

1. 先做 Phase 0~2（接口、DB、控制器），保证状态机正确。
2. 再做 Phase 3（书架 UI），先漫画接入，稳定后接小说。
3. 再做 Phase 4~5（详情页与章节交互），先通用骨架再补菜单。
4. 最后做 Phase 6~7（联动、回归、性能）。

这样可以持续交付，不会出现“大改完才发现不可用”的风险。
