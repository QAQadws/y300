# 分阶段实现 04：缓存机制重构

本阶段目标是修正“图片 URL 会变化，所以不能只缓存 URL”的问题。新的缓存机制应该缓存图片实体，并用逻辑身份作为缓存 key；同时保护漫画/小说在书架和详情页需要长期显示的元信息和封面。

## 当前问题

当前漫画阅读器：

- `NetworkComicReaderService.cacheImage(imageUrl: imageUrl)` 调用 `downloadFile(imageUrl, key: imageUrl)`。
- `episode_images.image_url` 保存远程 URL。
- 书架和详情页使用 `Image.network` 显示封面。

问题：

- 同一张图片的远程 URL 一段时间后可能变化。
- 以 URL 为缓存 key 会导致旧缓存无法命中。
- 书架/详情页封面如果只保存 URL，URL 失效后封面丢失。
- 清理缓存时没有区分“可清理阅读图片”和“必须保留的作品封面/元信息”。

## 目标

1. 图片缓存 key 改为逻辑身份，而不是远程 URL。
2. 缓存图片实体到本地文件。
3. 漫画封面默认取第一话第一张图片，并本地缓存。
4. 小说如果解析到封面，也本地缓存。
5. 自定义封面支持本地图片，设置后复制到 App 管理目录并受保护。
6. 书架和详情页显示本地封面，URL 只作为重新获取图片的临时来源。
7. 清除图片缓存只清理非封面、非自定义、非下载存储图片。
8. 缓存和下载存储分离。

## 图片身份设计

建议用稳定 key：

```text
cover/comic/<comicId>
cover/novel/<novelId>
comic/<comicId>/<episodeId>/<imageIndex>
novel/<novelId>/<episodeId>/<imageIndex>
```

示例：

```text
cover/comic/yamibo:536398
comic/yamibo:536398/yamibo:536398:551001/000
```

远程 URL 只作为 `last_source_url` 保存，用于缓存未命中时重新下载。

## 数据库建议

### 1. 扩展 episode_images

当前 `episode_images`：

- `episode_id`
- `image_url`
- `image_index`
- `cache_local_path`
- `cache_status`

建议新增：

```sql
ALTER TABLE episode_images ADD COLUMN stable_cache_key TEXT;
ALTER TABLE episode_images ADD COLUMN last_source_url TEXT;
ALTER TABLE episode_images ADD COLUMN local_path TEXT;
ALTER TABLE episode_images ADD COLUMN bytes INTEGER;
ALTER TABLE episode_images ADD COLUMN mime_type TEXT;
ALTER TABLE episode_images ADD COLUMN last_accessed_at INTEGER;
ALTER TABLE episode_images ADD COLUMN protected INTEGER NOT NULL DEFAULT 0;
```

兼容策略：

- 旧 `image_url` 保留，作为 `last_source_url` 使用。
- 旧 `cache_local_path` 可以迁移到 `local_path`，也可以保留一段时间兼容。

### 2. 新增统一图片缓存表

如果不想把小说插图硬塞进 `episode_images`，建议新增：

```sql
CREATE TABLE IF NOT EXISTS cached_images (
  cache_key TEXT PRIMARY KEY,
  owner_type TEXT NOT NULL,
  owner_id TEXT NOT NULL,
  episode_id TEXT,
  image_index INTEGER,
  role TEXT NOT NULL,
  last_source_url TEXT,
  local_path TEXT,
  bytes INTEGER NOT NULL DEFAULT 0,
  mime_type TEXT,
  protected INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  last_accessed_at INTEGER
)
```

`role`：

- `cover`
- `comic_page`
- `novel_inline`

`protected`：

- 封面：`1`
- 自定义封面：`1`
- 阅读缓存图片：`0`
- 已下载存储图片不应该在此表里作为可清理缓存管理。

推荐新增表，因为后续小说插图、普通帖子图片都可以复用。

### 3. 扩展漫画/小说主记录

`comics` 表建议新增：

```sql
ALTER TABLE comics ADD COLUMN cover_local_path TEXT;
ALTER TABLE comics ADD COLUMN custom_cover_local_path TEXT;
```

`works` 表建议新增：

```sql
ALTER TABLE works ADD COLUMN cover_local_path TEXT;
ALTER TABLE works ADD COLUMN custom_cover_local_path TEXT;
```

领域模型同步增加：

- `coverImageUrl`：最后一次来源 URL，可为空。
- `coverLocalPath`：本地封面路径。
- `customCoverLocalPath`：用户自定义封面路径。

显示优先级：

1. `customCoverLocalPath`
2. `coverLocalPath`
3. `coverImageUrl`
4. 占位图

## 缓存服务设计

新增：

```text
lib/features/cache/data/image_cache_repository.dart
lib/features/cache/domain/image_cache_service.dart
lib/features/cache/data/image_cache_providers.dart
lib/features/cache/presentation/widgets/library_cached_image.dart
```

### ImageCacheService

建议接口：

```dart
class ImageCacheRequest {
  const ImageCacheRequest({
    required this.cacheKey,
    required this.sourceUrl,
    required this.ownerType,
    required this.ownerId,
    required this.role,
    this.episodeId,
    this.imageIndex,
    this.protected = false,
  });
}

abstract class ImageCacheService {
  Future<CachedImageResult> ensureCached(ImageCacheRequest request);

  Future<CachedImageResult?> getCached(String cacheKey);

  Future<int> calculateUsageBytes({bool includeProtected = false});

  Future<void> pruneToLimit({required int maxBytes});

  Future<void> clearUnprotected();
}
```

### 使用 flutter_cache_manager 的方式

可以继续使用 `flutter_cache_manager`，但要传稳定 key：

```dart
final fileInfo = await cacheManager.downloadFile(
  sourceUrl,
  key: stableCacheKey,
);
```

注意：

- `key` 不再等于 URL。
- 数据库里记录 `stableCacheKey -> file.path`。
- 如果远程 URL 变了但逻辑图片没变，仍命中相同 key。
- 如果图片内容确实变化，需要提供“强制刷新”能力，先 remove old key 再下载。

### 不直接依赖 CachedNetworkImage 的 URL key

阅读器当前用 `CachedNetworkImage(imageUrl: imageUrl)`。后续建议改成统一组件：

```dart
class LibraryCachedImage extends StatelessWidget {
  const LibraryCachedImage({
    required this.cacheKey,
    required this.sourceUrl,
    this.localPath,
    required this.fit,
  });
}
```

渲染策略：

1. 如果 `localPath` 存在且文件存在，使用 `Image.file`。
2. 否则使用网络加载并触发 `ImageCacheService.ensureCached`。
3. 加载失败显示重试。

书架、详情页、阅读器统一使用这个组件或同一套 `ImageProvider` 解析逻辑。

## 漫画封面逻辑

用户要求：漫画封面选择逻辑为漫画第一话第一张图片，支持自定义。

实现路径：

1. 在漫画入库或刷新章节后，获取章节列表升序。
2. 找到第一话：
   - 优先 `orderIndex` 最小的有效章节。
   - 如果存在首楼章节 `orderIndex=-1`，需要明确它是否算第一话。建议：如果它就是当前 tid 的首楼图片，并且没有更明确章节，才用它。
3. 确保第一话图片列表存在：
   - 本地有 `episode_images`，直接取 `imageIndex=0`。
   - 没有则用 `ComicReaderService.fetchEpisodeImagesByTid` 拉取并保存。
4. 用稳定 key `cover/comic/<comicId>` 缓存这张图。
5. 保存到 `comics.cover_local_path`。

自定义封面：

1. 用户选择本地图片。
2. App 复制图片到受保护缓存目录，例如：
   - `<app-cache-root>/protected/covers/comic/<comicId>.jpg`
3. 保存 `custom_cover_local_path`。
4. 书架/详情页优先显示自定义封面。

不要只保存用户选中的原始路径，因为用户可能移动或删除原文件。

## 小说封面逻辑

小说可能没有封面，也可能首楼或章节中有封面图。

实现路径：

1. 阶段 02 的 `NovelRefreshPlan.coverImageUrl` 提供候选。
2. 如果有候选，用稳定 key `cover/novel/<novelId>` 缓存。
3. 保存到 `works.cover_local_path`。
4. 没有封面时继续显示现有“小说无封面”占位。

小说自定义封面同漫画。

## 作品元信息缓存

用户明确要求漫画/小说在书架和 detail 页能看到的信息必须缓存且不能被清理：

漫画：

- 第一话第一张图片作为封面
- 作品名称
- 所在 fid
- 最新 tid
- 每话 tid
- 作者
- 简介
- 自带标签
- 自定义标签
- 话数
- 每话张数
- 自定义封面
- 自定义信息
- 标记

小说：

- 名称
- fid
- tid
- 作者
- 简介
- 自带标签
- 自定义标签
- 章节数
- 封面
- 阅读状态/标记

这些信息应该放在 SQLite 主表和统一状态表中，不应该放在可清理图片缓存目录里。

推荐：

- 主数据：`comics`、`episodes`、`episode_images`、`works`、`work_episodes`。
- 用户状态：`library_work_state`、`library_episode_state`、`library_tags`、`library_work_tags`。
- 图片实体：`cached_images` + 本地文件。

清除图片缓存只删除：

- `cached_images.protected=0`
- 对应本地文件

不删除：

- SQLite 元信息
- `protected=1` 的封面
- 自定义封面
- 下载存储中的文件

## 缓存目录与大小

默认图片缓存上限建议：`512 MB`。

理由：

- 漫画图片体积较大，128 MB 很容易频繁淘汰，体验差且增加服务器压力。
- 512 MB 对多数移动设备可接受。
- 允许用户调整，比如 `128 MB - 2048 MB`。

清理策略：

1. 计算 `protected=0` 的图片总大小。
2. 如果超过上限，按 `last_accessed_at ASC` 删除最久未访问的图片。
3. 每次阅读本地图片时更新 `last_accessed_at`。
4. 手动“清除图片缓存”删除所有 `protected=0` 图片。

## 对现有代码的具体影响

### ComicReaderService

当前：

```dart
Future<ComicImageCacheResult> cacheImage({required String imageUrl});
```

建议改为：

```dart
Future<ComicImageCacheResult> cacheImage({
  required String imageUrl,
  required String cacheKey,
  required ImageCacheRole role,
  bool protected = false,
});
```

调用方根据 episode/imageIndex 生成 key。

### ComicReaderController

当前 `ComicReaderImageState` 只有 `imageUrl/cacheLocalPath`。

建议增加：

```dart
final String cacheKey;
final String? localPath;
```

加载图片优先使用 `localPath`。

### UnifiedShelfPage / UnifiedDetailPage

当前多处 `Image.network`：

- `unified_shelf_page.dart`
- `unified_detail_page.dart`

应替换为统一封面组件：

```dart
LibraryCoverImage(
  localPath: item.coverLocalPath,
  imageUrl: item.coverImageUrl,
  moduleKey: state.moduleKey,
)
```

`LibraryWorkItem` 和 `LibraryDetailHeader` 增加 `coverLocalPath`。

## 测试建议

1. 同一个 `cacheKey`，远程 URL 改变后仍能命中本地图片。
2. 书架封面本地文件存在时不发起网络图片加载。
3. 清除图片缓存不会删除封面和自定义封面。
4. LRU 清理只删除 `protected=0` 的图片。
5. 漫画第一话第一张图能成为封面。
6. 小说解析到封面时会缓存到本地。
7. 用户自定义封面复制到 App 管理目录后，即使原图删除仍能显示。

## 完成标准

- 远程图片 URL 变化不会导致已缓存图片失效。
- 漫画/小说书架和详情页关键元信息离线可显示。
- 清理图片缓存不会破坏漫画/小说条目、封面、自定义标签和简介。
- 阅读图片缓存有可配置上限和 LRU 策略。
