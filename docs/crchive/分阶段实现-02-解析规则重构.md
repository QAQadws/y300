# 分阶段实现 02：解析规则重构

本阶段目标是提高解析稳定性：漫画两处 raw HTML 扫描改为统一 DOM 提取；小说解析改成可扩展规则架构，方便后续添加封面、简介、轻小说插图、章节标题等规则。

## 目标

1. `comic_episode_discovery_service.dart` 中 `_collectRecursiveTidCandidates` 不再直接扫 raw HTML。
2. `comic_consecutive_op_post_parser.dart` 中 `_extractImages` 不再用正则扫 `<img>`。
3. 抽出统一 DOM 提取工具，供漫画解析、小说解析、后续收藏批量解析复用。
4. 小说解析从硬编码流程改成“规则列表 + 计划输出”的结构。

## 当前问题点

### 1. 漫画递归发现 raw HTML 扫描

文件：`lib/features/comic/domain/services/comic_episode_discovery_service.dart`

当前 `_collectRecursiveTidCandidates` 在约 363 行附近：

```dart
for (final post in posts) {
  final html = post.message;
  for (final match in _threadPathPattern.allMatches(html)) { ... }
  for (final match in _viewThreadPattern.allMatches(html)) { ... }
  for (final match in _damagedTidPattern.allMatches(html)) { ... }
}
```

问题：

- 会扫到非链接文本、脚本、引用、隐藏内容。
- HTML 实体、相对链接、Discuz 损坏链接等规范化逻辑散落。
- 与 `ComicPostParsingEngine` 内部 anchor 提取重复。

### 2. 连续楼主楼层图片提取 raw HTML 扫描

文件：`lib/features/comic/domain/services/comic_consecutive_op_post_parser.dart`

当前 `_extractImages` 在约 97 行附近：

```dart
final matches = RegExp('<img[^>]*\\ssrc=["\\\']([^"\\\']+)["\\\']').allMatches(html);
```

问题：

- 只识别 `src`，不能兼容 `data-src`、`file` 等常见懒加载字段。
- 可能误收表情、头像、论坛 UI 图片。
- 与 `HtmlComicParserService` 中 `html_parser.parseFragment(message).querySelectorAll('img')` 重复。

## 推荐新增 DOM 工具

推荐目录：

```text
lib/features/thread/domain/services/forum_thread_url_parser.dart
```

也可以放到 `lib/features/library_shared/domain/services`，但由于输入是论坛帖子 HTML，放在 thread domain 更自然。

### ForumThreadUrlParser

把当前分散在多个文件的 URL 规范化和 tid 提取集中起来：

```dart
class ForumThreadUrlParser {
  const ForumThreadUrlParser({this.siteOrigin = 'https://bbs.yamibo.com/'});

  final String siteOrigin;

  String? normalizeHref(String href) { ... }

  String? extractTid(String normalizedUrl) { ... }

  bool isThreadUrl(String normalizedUrl) => extractTid(normalizedUrl) != null;
}
```

可以迁移这些现有正则：

- `thread-(\d+)-\d+-\d+\.html`
- `forum.php?...mod=viewthread...tid=(\d+)`
- 损坏链接 `;tid=xxx` 或 `tid=xxx`

保留正则提取 URL 中的 tid 是可以的，关键是不要对整段 raw HTML 做 allMatches。

## 漫画解析改动

### 1. `ComicConsecutiveOpPostParser`

构造函数增加依赖：

```dart
ComicConsecutiveOpPostParser({
  required ComicPostParsingEngine engine,
  ForumPostDomExtractor? domExtractor,
}) : _domExtractor = domExtractor ?? ForumPostDomExtractor();
```

替换 `_extractImages`：

```dart
final images = _domExtractor.extractImageSources(context.messageHtml);
```

然后删除私有 `_extractImages`，或者保留成薄包装：

```dart
List<String> _extractImages(String html) {
  return _domExtractor.extractImageSources(html);
}
```

### 2. `ComicEpisodeDiscoveryService`

构造函数增加：

```dart
ForumPostDomExtractor? domExtractor,
```

`_collectRecursiveTidCandidates` 中：

```dart
for (final post in posts) {
  for (final candidateTid in _domExtractor.extractThreadTids(post.message)) {
    if (candidateTid != tid) {
      candidates.add(candidateTid);
    }
  }
}
```

这样只从 DOM anchor 中收集 tid，不再从整段 HTML 扫描。

### 3. `ComicPostParsingEngine`

当前 `_extractAnchors` 是私有且包含 URL 规范化。建议逐步改成：

- `ForumPostDomExtractor.extractAnchors` 负责 DOM 和 URL 基础规范化。
- `ComicPostParsingEngine` 负责语义规则：目录、章节、连续组、拒绝。

不要一次性大重构所有规则。第一步可以只让 `ComicPostParsingEngine` 内部调用新 extractor，保持外部返回不变。

## 小说解析规则化

当前文件：`lib/features/novel/domain/services/novel_episode_discovery_service.dart`

现状：

- 仅解析楼主楼层。
- 每个楼主楼层都是章节。
- 标题通过一个正则匹配，否则回退“第N节（PID）”。

这是可用的最小实现，但后续要支持更多规则会越来越难维护。建议改成以下结构。

### 1. 扩展输出模型

文件：`lib/features/novel/domain/models/novel_thread_models.dart`

`NovelRefreshPlan` 建议增加：

```dart
final String? intro;
final String? coverImageUrl;
final List<String> inlineImageUrls;
final NovelParsingDebugInfo? debugInfo;
```

`NovelEpisodeDraft` 建议增加：

```dart
final List<String> imageUrls;
```

轻小说可能在章节正文里有插图，这些图片后续需要进入图片实体缓存和下载存储。

### 2. 定义规则接口

推荐新增：

```text
lib/features/novel/domain/services/novel_parsing_rule.dart
```

接口：

```dart
abstract class NovelParsingRule {
  NovelRuleResult apply(NovelParsingContext context);
}

class NovelParsingContext {
  const NovelParsingContext({
    required this.novelId,
    required this.page,
    required this.post,
    required this.opAuthorId,
    required this.domExtractor,
    required this.currentOrderIndex,
  });

  final String novelId;
  final ThreadDetailData page;
  final ThreadPost post;
  final String opAuthorId;
  final ForumPostDomExtractor domExtractor;
  final int currentOrderIndex;
}
```

`NovelRuleResult` 可以包含：

- 是否接受该 post 为章节。
- 标题候选。
- 正文段落。
- 图片 URL。
- 简介候选。
- 封面候选。
- debug signals。

### 3. 初始规则列表

推荐默认规则：

1. `OpAuthorOnlyRule`
   - 非楼主楼层默认不进入章节。
   - 后续如果要支持多作者协作，可增加配置。

2. `MeaningfulTextRule`
   - 过滤空楼层、纯图片楼层、太短的回复。
   - 阈值可配置，例如正文文本长度 >= 20 或图片数量 > 0。

3. `ChapterTitleRegexRule`
   - 从纯文本中匹配：
     - `第...章`
     - `第...节`
     - `第...话`
     - `第...回`
     - `卷...`
     - `番外`
     - `特典`

4. `HeadingTitleRule`
   - 从 DOM 中识别明显标题：
     - `h1/h2/h3`
     - `strong/b/font[size]`
     - 首段短文本且命中章节关键词

5. `CoverImageRule`
   - 第一个楼主楼层中的第一张有效图片可作为小说封面候选。
   - 注意不要把表情、头像作为封面。

6. `IntroBeforeFirstChapterRule`
   - 首楼中位于第一处章节标题前的文本可作为简介候选。
   - 如果已经有用户自定义简介，刷新时不要覆盖自定义简介。

7. `FallbackTitleRule`
   - 仍保留当前回退：
     - 首楼：`序章`
     - 其它：`第N节（PID:xxx）`

### 4. Orchestrator

`NovelEpisodeDiscoveryService` 不再直接写所有判断，而是：

1. 遍历页和帖子。
2. 构建 `NovelParsingContext`。
3. 依次应用规则。
4. 合并规则结果。
5. 生成 `NovelRefreshPlan`。

伪代码：

```dart
class NovelEpisodeDiscoveryService {
  NovelEpisodeDiscoveryService({
    List<NovelParsingRule>? rules,
    ForumPostDomExtractor? domExtractor,
  }) : _rules = rules ?? NovelParsingRules.defaults,
       _domExtractor = domExtractor ?? ForumPostDomExtractor();

  NovelRefreshPlan buildPlan({ ... }) {
    final planBuilder = NovelRefreshPlanBuilder(...);

    for (...) {
      final context = NovelParsingContext(...);
      final result = _rules.fold(NovelRuleResult.empty, merge);
      if (result.acceptAsEpisode) {
        planBuilder.addEpisode(result.toDraft(...));
      }
      planBuilder.acceptMeta(result);
    }

    return planBuilder.build();
  }
}
```

## 与缓存/收藏的关系

本阶段虽然不直接实现收藏和图片缓存，但要为后续做好字段准备：

- 漫画 DOM 图片提取结果会进入 `episode_images`。
- 小说 `coverImageUrl` 和 `imageUrls` 会进入图片缓存。
- 收藏同步批量进帖时会大量调用漫画/小说解析，解析越稳定，服务器请求越少。

## 测试建议

### 漫画 DOM 提取测试

新增测试：

- `<img src="...">` 能提取。
- `<img data-src="...">` 能提取。
- 表情和头像被过滤。
- `<a href="thread-123-1-1.html">上一话</a>` 能提取 tid `123`。
- 损坏链接 `<a href=";tid=123">上一话</a>` 能规范化并提取。
- 普通文本里的 `thread-123-1-1.html` 不应被当成递归候选，除非它真的在 anchor 中。

### 小说规则测试

新增测试：

- 非楼主楼层默认不生成章节。
- 首楼有正文时标题为 `序章`。
- 文本中 `第十二章` 能被识别。
- `番外`、`特典` 能被识别。
- 首楼第一张有效图片成为 `coverImageUrl`。
- 简介不会把整章正文都吃进去。

- 现有漫画章节发现测试仍通过。

- `NovelRefreshPlan` 已能携带封面/插图/简介候选，供后续缓存阶段使用。
