# 分阶段迁移实现漫画阅读

## 1. 目标与范围

本文档用于把 `.information/mangayomi_lib` 中成熟漫画阅读器能力，分阶段迁移到当前项目 `y300`，并同步引入新的底部 Tab：`更多`。

本次迁移目标包括：
- 阅读页点击中部后，上下菜单动效出现/隐藏。
- 下部菜单支持阅读方式切换：
  - 垂直连续
  - 从左到右分页
  - 从右到左分页
- 下部菜单上方支持可拖动阅读进度条：
  - 左内侧显示当前页
  - 右内侧显示总页数
  - 左外侧按钮：上一话
  - 右外侧按钮：下一话
- 上部菜单显示返回按钮 + 当前话信息。
- 任意阅读模式支持：
  - 双指缩放
  - 双击快速缩放到点击区域
- 新增 `更多` Tab，承载迁移期设置入口：
  - 登录入口迁移到“更多”
  - 缓存目录配置（含默认值）
  - 预留后续扩展入口

不在本轮强制范围（可后续迭代）：
- 双页模式（one/double page）
- 自动滚动、边缘裁切、色彩滤镜
- 复杂预加载策略（跨章节双向智能预载）

## 3. 总体迁移策略

采用“**先解耦、再增强、最后替换默认交互**”策略：
- 先把阅读器状态和 UI 结构拆分成可演进模块。
- 再逐步引入手势、模式切换、菜单动画、进度拖动。
- 最后接入 `更多` Tab 统一承载配置，迁移登录入口。

每阶段必须满足：
- 可独立提交与回归验证。
- 旧能力不中断（可保留兼容入口）。
- 数据结构向前兼容（不破坏已存阅读进度）。

## 阶段 5：缩放能力（双指 + 双击定位缩放）（2~3 天）

目标：
- 任意阅读方式都支持双指缩放与双击缩放目标区域。

实施项：
1. 图片组件升级
- 当前 `CachedNetworkImage` 外层升级为支持手势矩阵变换的组件。
- 建议方案：
  - `InteractiveViewer`（标准库，成本低）
  - 或 `photo_view`（更接近 mangayomi）

2. 双击缩放点对齐
- 使用 `onDoubleTapDown` 获取点击坐标。

3. 与分页滑动冲突处理
- 缩放比例 > 1 时，优先图片平移；
- 缩放恢复为 1 时，恢复页面翻页手势。

4. 垂直模式滚动冲突处理
- 局部缩放图内拖拽与父级 List 滚动需要手势竞争策略（可用 `GestureDetector` + `NotificationListener` 控制）。

验收标准：

## 6. 关键风险与规避

风险 1：缩放与翻页手势冲突导致误触
- 规避：先在分页模式落地缩放，再扩展垂直模式；引入缩放阈值门控。

风险 2：模式切换后页位错乱
- 规避：统一使用“逻辑图片 index”作为单一真值。

风险 3：缓存目录权限和平台差异
- 规避：目录选择后做可写性探测；失败回退默认目录并提示。

风险 4：一次改动过大难以回滚
- 规避：阶段化提交，每阶段都可独立回退。

## 阶段0补充约束（2026-05-01修订）

### A. AsyncNotifier 生命周期安全约束（必须遵守）

背景：`ComicReaderController` 使用 `AsyncNotifierProvider.autoDispose`。在页面退出、参数切换、provider重建时，旧实例会被销毁。若异步任务在销毁后继续访问 `ref.read(...)` 或写状态，会触发 `UnmountedRefException`。

工程化约束：
1. 依赖在 `build()` 中一次性读取并缓存到字段（如 `_repository`、`_readerService`）。
2. 每个 `await` 后在继续写状态或继续业务前检查 `ref.mounted`。
3. 不在 dispose/onDispose 链路中访问 `ref.read`。
4. 控制器方法应在 provider 销毁后安全提前返回（silent return）。

验收点：
- 快速打开/关闭阅读页、快速切章节，不再出现 `UnmountedRefException`。

### B. 阅读器菜单交互基线（前置到阶段0）

为避免交互回退，提前固化以下行为：
1. 菜单默认隐藏。
2. 仅点击屏幕中部区域（包括中上/中下）触发菜单显示/隐藏。
3. 菜单显示采用顶部/底部动效滑入。
4. `上一话/下一话` 按钮属于底部菜单的一部分，默认隐藏，菜单显示时出现。

实现备注：
- 左右区域先不处理翻页点击，留给后续阶段的手势分区（避免阶段0过耦合）。
